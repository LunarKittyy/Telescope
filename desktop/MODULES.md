# Telescope Desktop - Module Reference

The detailed reference for every desktop module. For an introduction, start with [the architecture overview](../docs/architecture.md). Where this and the code disagree, the code wins.

---

## Entry point

### `update_guard.py`
Makes an update survive being cut short, and undoes one that won't start. Standard library only and outside the package, so `main.py` can run it before importing anything else. The journal (`.update.json`) goes `swapping` → `trial` → gone. `finish_swap()` is safe to run again: Windows moves each `lib-<build>` folder in with one rename, then swaps the exe with two (the one instant nothing can start), then the other files; Linux replaces each file in one step (so `start.sh`, `main.py` and this module are never missing) and moves each folder aside to `.previous/` before moving the new one in. `recover()` on every start: finishes a cut-short swap (relaunching the new exe if the old one was running), marks a trial as started, and rolls back a trial that already started but never reached `confirm()` (`confirm_on_terminate()` makes a SIGTERM or SIGHUP, i.e. a logout, confirm first, so only a start that dies with no signal counts as failed), after first giving that start up to `TRIAL_GRACE_S` (30 s) to take the single-instance lock, so a double-click during the new version's first start doesn't roll it back. `roll_back()` puts the old exe or `.previous/` entries back and writes the build to `.update-failed`, which `updates.is_newer()` then skips. It leaves everything alone while another copy holds the single-instance port.

### `main.py`
First `update_guard.recover()`, before anything else is imported; then the dependency check (it only looks for opencv, numpy, pyvirtualcam, ifaddr and zeroconf, since importing them is slow on a Windows first start) and argument handling. On bundled Windows, a copy opened from inside a zip (`windows.running_from_archive()`) shows a message box to extract it first and quits. After Qt app setup, the new instance takes the single-instance lock before `pyav_vaapi.activate()` can promote a staged build. The window and built-in plugins import only after activation, so they use the selected PyAV. Then `apply_theme()`, `win.load_plugins(builtin_plugins())`, config restore and the event loop. Command-only and duplicate launches never activate or replace PyAV.
Before Qt starts it gives OpenCV 2 threads (`cv2.setNumThreads`; with one per CPU thread they mostly spun waiting on per-frame jobs this small) and, on Linux, calls `limit_malloc_arenas()`.
The built-in plugins and their registration order are in `builtin_plugins()` (`telescope/plugins/__init__.py`, see below).
On Linux (not from a source checkout) it calls `autostart.update_menu_entry()` to keep the app menu entry pointing at this copy.
`--after-update` (passed by the updater when it relaunches) and `--restarted` (the Plugins tab's **Restart now**) wait up to 15 s for the old copy to exit. 3 s after the window is up, or when the app quits normally, it calls `update_guard.confirm()` and `updates.clean_up_after_update()`. `--minimized` (the sign-in entry) starts in the tray via `win.start_hidden()`. `--action ID name=value…` and `--list-actions` start no window: they hand the request to the running copy (`app.send_action`), print its answer and exit. Arguments it doesn't know go to Qt.
Calls `win.apply_saved_config()` **after** all plugins are registered so every plugin's `set_config()` is available.

## `telescope/` package

### `app.py`
**TelescopeWindow** - thin coordinator shell.
- Owns the header bar (plugin header widgets on the left, or just left of the settings button for a plugin whose `header_side` is `"right"`; the settings button and Start button on the right), the column body, the footer (stream status, FPS, throughput), and the tray icon.
- Owns `EventBus` and `StreamWorker` lifecycle.
- `register_plugin(p, added=False)` - calls setup, routes panel to the named region, appends header widget. For an added plugin (`added=True`) that raises part way, `_take_out` undoes what was done before passing the exception on.
- `load_plugins(builtins)` - registers the built-in plugins except those switched off in Plugins (a `required` one always), then the added ones switched on (`plugin_loader.load_enabled`). An added plugin that fails to load or start is left out, with a `plugins` banner; its error is in `_plugin_problems`. `_remind_plugins_off()` shows a `plugins_off` banner naming the built-in ones that are off, once per change (`plugin_loader.notice_off`). `plugins_off()` lists them; the Plugins tab is named **Plugins (N off)** while some are. `open_settings("plugins")` brings the Settings window up on it, and `restart_app()` starts a new copy (`single_instance.relaunch(restart_argv())`) and quits (under `dev_desktop.py` it quits with an exit code that has the script start it again, see `dev_profile.py`). Copy diagnostics adds `Plugins off` and `Added plugins` lines.
- `_refresh_layout(force=False)` - redistributes panels across columns by width (a panel its plugin has hidden stays hidden): `three` (≥1300px) left/center/right, `two` (≥900px) left+right/center, `one` center-first. Both rails are `_RAIL_WIDTH` wide so the preview sits centred. Triggered on resize (no-op if layout mode unchanged) and on registration.
- `open_settings(tab="")` - the settings button's action (`HostShell`). Builds `widgets/settings_window.py` the first time from every plugin's `create_settings_sections()` plus the Plugins tab (`widgets/plugins_panel.py`), then keeps it: later calls show it again, on `tab` if that's a tab that exists. A plugin that raises while listing its sections is logged and left out. It isn't modal, since that would block every other Telescope window. `register_plugin` logs a deprecation warning for a plugin that still overrides `create_menu_actions()`, whose actions the default `create_settings_sections()` puts behind an Open settings button in General.
- Re-exports `STATUS_COLORS` from `theme.py`.
- Collects every plugin's `create_actions()` at registration (`shortcut_actions()`), and implements `toggle_window()` and `stop_all_streams()` for the Shortcuts plugin's own actions.
- `telescope --action` (`single_instance.py`): `listen_for_raise(srv, raise_cb, action_cb, control_key)` also takes `action:<json>`, checked against the key `write_control_key()` puts in `.control-key` next to the config (a new one each start, mode 600), since the single-instance socket is one any local account can reach. `run_remote_action()` runs the request on the GUI thread through the Shortcuts plugin and waits up to 5 s for its answer. `send_action(request)` is the client side, used by `main.py`.
- `acquire_single_instance()` (`single_instance.py`) holds the lock at `update_guard.instance_address()`: on Linux a Unix socket per user (abstract name `telescope-<uid>`, `-dev` for a dev profile, no file to go stale), so two accounts on one machine each run their own; on Windows `127.0.0.1:47823` (`+1` for dev). A second launch sends `raise:<user token>` (`user_token()`: a hash of the user name and Windows session); the running copy answers `ok` after raising its window, or `other` when the token is another user's, which shows "already running for another user". No answer means something else holds the lock, and a message box says so instead of quitting silently.
- `_set_plugin_config()` loads a plugin's saved settings; if that fails it keeps the fields that load on their own and defaults only the bad ones.
- `apply_saved_config()` - call after all plugins are registered; restores config round-trip for each plugin.
- **Several streams.** Each streaming source holds its own `StreamSession`; the window keeps them in `_sessions` (`session.Sessions`, driven by `stream_flow.StreamFlow`, see below): `streams` lists them in start order (at most `vcam.MAX_SLOTS`). `focus` is the one the panels show, and `_session` is its session. `main` is the first, which plugins with `follows_focus = False` (the mic) stay with, until `make_main(id)` moves them to another stream (saving their settings as the one they leave, loading the new one's); `main_stream()` says which. `_tell(source, hook)` calls a stream hook on the plugins that hear about that source (`Sessions.hearing`). `add_stream(id)` (the header's + button, shown while streaming) moves the panels to the new source and starts it; `StreamFlow.free_slot` gives it the virtual camera it had last (`output_slots` in the config) or the lowest free one, and `_set_up_slots` asks to add the extra cameras first when they aren't there. `StreamFlow.move_focus` (a tile click via `focus_stream`, or `pick_source` from the picker) freezes the old stream's frame steps, saves the following plugins' settings as its device's, loads the new one's, emits `device_changed`, shows its status and asks its phone for its state again (`refresh_state`). Stopping the shown stream moves the panels to the first one left, and stopping the first moves the mic on (`StreamFlow.sync_main`), unless it's only restarting (`reconnect_stream`), when the mic waits for it. `stream_started` and `stream_stopped` only mark the first start and the last stop; `streams_changed` gives the count. The header's Stop (`StreamFlow.stop_all`) stops them all; `stop_stream()` stops the one shown, `stop_stream(id)` a given one. Worker signals find their stream through `sender()`; one the panels don't show only updates its tile, and still recovers or stops by itself. With more than one stream, the camera can't go off, the canvas can't be resized, and once a second one has streamed Automatic streaming stops nothing until all have stopped. `StreamFlow.announce_idle_outputs` emits `bus.idle_outputs` on each change (the main camera, 0, included while only extra ones stream), and just before a stream opens an extra camera so the wait screen lets go of it. A source whose `prepare()` declines while `waiting()` (Browser camera with no browser yet) becomes `_sessions.pending` when added next to others: a **Waiting** tile with the panels on it, until it's no longer waiting; its tile's x (`stop_stream(id)`) and Stop call its `cancel_wait()`. `start_again(id, before)` is the callback banners use for Start and Try again: that source by itself or next to the others, `before` running with the panels on it (Switch to Heavy). Banners about one stream that stopped use the key `stopped:<id>`, and another stream connecting leaves them. `remove_extra_cameras` (**Extra cameras** on Virtual camera & phone in Settings) deletes them on Linux (`v4l2_remove_devices`) or re-registers UnityCapture with one camera (`register_unitycapture(1, reset=True)`). Plugins can offer and take back sources while running (`add_stream_source`, `remove_stream_source`) and start one (`stream_source`: picked and started when nothing streams, else `add_stream`); at Start, a picked source's `redirect()` can name another to stream instead. `_drop_unchanged` keeps a `remember_changes_only` source's settings only where they differ from the plugin defaults. `widgets/tiles.py` draws the row of tiles.
- **Stream sources.** Every stream comes from a `Source` (`sources.py`), which keeps that stream's own state: `_phone` (a `PhoneSource`) is the phone Connection has picked, and `add_stream_source(source)` wraps a plugin's `StreamSource` in a `PluginSource` and emits `bus.stream_sources_changed`. `_selected_source()` is the plugin source whose id is Connection's `selected_device`, else the phone; `_active_source()` is the session's source, or the selected one while idle. The session keeps its source, and the window asks it rather than checking which kind it is: a plugin source sends no remote stop, has no state to fetch, and its reader waits for it to come back after a drop instead of probing routes.
- **Two-phase start.** `StreamFlow.start()` calls `source.prepare()` (a phone: `conn.get_stream_info()`, which validates ADB/v4l2 and builds the URL; a plugin source: `conn.ensure_virtual_camera()` and its own `prepare()`). A source that doesn't wake goes straight to `StreamFlow.begin_stream(source)`. A phone does: `PhoneSource.wake()` snapshots `conn.session_target()` on the GUI thread and brings the camera up on a background thread (`_spawn_wake()`), then the `StreamFlow.wake_done(source, ok, reason)` either runs `StreamFlow.begin_stream()` (worker, ctrl, pipeline) or re-enables Start and shows the error. The phone's `_wake_id` counter drops stale results after user Stop/device switch/quit. Split for testability (tests call synchronously).
- `StreamFlow.stop(remote_stop=True)` - tears down worker and ctrl; `on_stream_stop()` on each plugin (ConnectionPlugin releases its USB forward there); `source.stopped()` invalidates any in-flight wake and takes the phone's camera down with it (`PhoneSource._stop_phone_async()`). `remote_stop=False` is for the internal stop/start pairs that are really a desktop-side reconnect (`reconnect_stream()`, `restart_vcam_canvas()`) - bouncing the phone there would cost seconds and a lens re-open for nothing.
- `_drain_phone_stops(timeout=2.0)` - the remote stop runs off the UI thread but is tracked rather than fire-and-forget, so the quit paths (`closeEvent`, `_tray_quit`) can give it a bounded moment to actually leave the machine (each source's `drain_stops()`). Both quit paths then call every plugin's `shutdown()`.
- Implements the public **`HostServices`** contract (see `plugin.py`): `schedule_save()`, `save_now()`, `switch_device()`, `forget_device_settings()`, `reconnect_stream(source_id=None)` (a stream the panels don't show gets them first; during another start it waits for it), `hand_over_stream(route, source_id=None)` (move a running phone stream onto another route without a gap; `PhoneSource.hand_over` prepares the route with Connection, the worker's `moved` or `move_failed` says how it went), `send_notification()`, `is_streaming()`, `is_starting()` (a Start is waking the phone, before the worker exists), `is_restarting()` (the `stream_stopped` being handled is a reconnect or resize, and a stream starts again right after), `stop_stream()`, `update_stream_output()`, `restart_vcam_canvas()`, `quit_app()` (really quits, tray or not), `start_stream(interactive=True)` (False: no password prompt, problems go to a banner), `set_keep_in_tray(keep)` (close hides to the tray even when idle), `show_issue(key, Issue)` / `clear_issue(key=None)` (problem banners above the body; every banner clears when a stream connects), `diagnostics_report()` (the Copy diagnostics text), `open_settings(tab="")` (the Settings window, on a tab by its id), `plugin_config(name)` / `apply_preset(name, cfg)` (another plugin's config, and handing it one to apply; used by Presets), `is_camera_on()` / `is_camera_off_auto()` / `can_turn_camera_off()` / `set_camera_on(on, auto)` (see **Camera off** below), `start_again(source_id, before)`, `focused_source_id()`, `background_streams()` and `device_config(source_id, plugin)` (see **Several streams**). Plugins only call these; private internals (`_worker`, `StreamFlow.stop()`) are hidden.
- `send_notification(title, body, urgent=True)` - uses `notify-send` on Linux (critical urgency only when `urgent`), tray balloon on Windows.
- `save_now()` - writes global plugin configs (connection, setup) and per-device configs (camera_control, stream_output, transforms, monitoring, presets, microphone) under `devices[selected]`. `schedule_save()` is the debounced variant plugins call after a settings change.
- `switch_device(prev, new)` - saves `prev` phone's per-device configs, restores `new` phone's; called by `ConnectionPlugin._activate_profile()`. Keys are phone ids.
- `forget_device_settings(id)` - deletes a removed phone's stored settings. `move_device_settings(old, new)` stores a phone's settings (presets included) and remembered virtual camera under a new id, for a phone that paired again after a reinstall.
- `restart_vcam_canvas()` stops the stream for the resize and starts it again when done (`_sessions.canvas_restart`); any real stop meanwhile cancels that restart.
- `is_streaming()` / `stop_stream()` / `update_stream_output(width, height, fps)` - public stream controls; `stop_stream()` is a guarded no-op when idle, and `update_stream_output()` forwards only the values a caller passes (`None` width/height means pass-through).
- `_plugin(name)` - central typed lookup of a registered plugin by name (replaces scattered inline `next(p for p ...)` scans).
- Footer "Throughput" (Mbps) readout, coloured amber when frames sustainedly arrive under 85% of the target rate (`_frames_arrived`: every frame the readers took in, `last_frame_count` of them per read, since an H.264 burst shows only its newest), and `bus.stream_behind(source id, bool)` when that changes (`_note_throughput()`: not while recovering a dropped stream, nor for the first report after it's back, which still counts the gap; a stop, a stream loss or an `"ok"` status resets it to False). Before going amber, `_on_slow_arrival()` has the source check its camera's rate (`PhoneSource.check_camera_rate()` asks the phone for its `camera_fps`, the answer kept for `_CAMERA_FPS_KEEP_S`): frames arriving at 90% of what the camera makes mean the camera is slow (dim light), not the link, so the readout stays normal and the FPS readout's tooltip says so; a phone that doesn't report it counts as the link; live FPS/resolution readout reflects the frame's actual current shape rather than the frozen stream-start size.
- Pending-resolution tracking: `_on_resolution_pending()` marks changes in flight on the source (8s timeout); readout amber until fps readout confirms new size or timeout fires error. The behind, settling and slow-arrival state live on the source too.
- **Getting a dropped stream back.** The worker's `"reconnecting"` status starts `StreamFlow.begin_recovery()`: `bus.stream_lost`, then `source.lost()`. A phone (`PhoneSource`) then, every `_RECOVER_RETRY_MS` (3 s), does a quiet state fetch (`_spawn_state_fetch()`: the phone may have dropped the stream on purpose, e.g. H.264 it can't do, and its state says why, sometimes only seconds after the drop; plugins get it only when it has a `codec_error`) and a background `conn.recovery_probe()` job that resolves the route again. A phone that answers while streaming gets the stream moved there once per route (`conn.adopt_stream_route()` for the URL and a fresh USB forward, a new `PhoneControlClient`, `worker.retarget(url)`); one that answers but isn't streaming ends the stream with a "The phone stopped streaming" banner. `_recovery_gen` drops probes from before the stream came back or stopped. So a pulled cable falls back to Wi-Fi, and a replugged one gets a working forward again. For any source, `start_lost_clock()` runs two timers: after `_PARK_AFTER_MS` (10 s) `StreamFlow.park()` has the worker let go of its virtual camera (`StreamWorker.set_parked`) and `StreamFlow.announce_idle_outputs` counts it as idle, so the wait screen shows instead of the last frame; after `_UNREACHABLE_AFTER_MS` (30 s) a `stopped:<id>` banner says it can't be reached, with the source's `lost_hint`. Retrying carries on. On `reconnected` the wait screen lets go (`StreamFlow.free_vcam_for`) and the worker takes the camera back; `end_recovery()` stops both timers and drops the banner.
- **Camera off.** `set_camera_on(on, auto=False)` keeps the stream (and so the mic) going without video: it sends the `camera_on` control, ends the worker (`_end_worker()`), sets `session.worker` to `None` and calls `on_camera_off()` on every plugin (the wait screen takes the virtual camera back); on again it starts a new worker through `StreamFlow.start_worker()` (after `on_stream_starting()`) and calls `on_camera_on()`. Before a start it only picks what the next start does: `PhoneSource.wake()` adds `camera: "off"` to the opening and Start reads **Start mic only**. The choice is kept on the source (`camera_off`, `camera_off_auto`), so picking another source can change it: `_on_source_selected()` then updates Start and emits `camera_on_changed`. Only a source with `mic_alone` (a phone) can turn its camera off. Going off needs the microphone card on (`can_turn_camera_off()`), and switching the mic off turns the camera back on. `is_streaming()` is the session, not the worker, so a mic-only stream counts. `StreamFlow.stop()` puts the camera back on unless it's a restart. With no video to notice a dropped phone, the phone's `_alive_timer` asks for its state every 5 s and two misses in a row start `StreamFlow.begin_recovery()`; a route move with no worker swaps the client and reruns `on_stream_start`. The first state fetch matches the phone to the desktop (`PhoneSource.on_phone_state()`): a phone without `camera_toggle` gets the camera back with a banner. `_CAMERA_ON_CHECK_MS` after turning it on, a phone reporting `camera_error` puts it back off with a banner. `auto` (from Startup) is remembered as `is_camera_off_auto()`, so an app opening the camera can undo it but not a choice made by hand. `bus.camera_on_changed` reports every change.
- The tray icon (`create_tray_icon(camera, mic)`) and its tooltip follow the stream, `camera_on_changed` and `bus.mic_changed`: a red dot while the camera streams, a mic while the mic does, crossed out when muted.
- `_start_reconnecting_animation()` / `_tick_reconnecting_animation()` - animates the "Stream dropped - reconnecting" footer status (yellow, cycling "." → ".." → "..." once a second) instead of a static line.
- `_apply_config(cfg)` - routes global plugin slices to `p.set_config()`, per-device slices for the selected device, then calls `conn.sync_active_profile()` so the restored selection doesn't spuriously re-trigger a profile switch.
- The single-instance lock and `--action` (`acquire_single_instance()`, `listen_for_raise()`, `send_action()`, `write_control_key()`) live in `single_instance.py`, which `main.py` imports directly; nothing in it needs the window. `restart_argv()` and `relaunch(argv)` start a new copy with `--restarted` (the Updates plugin's relaunch uses them too).

### Settings window
One window with tabs down the left (`plugin.SETTINGS_TABS`: General, Streaming, Video, Audio, Virtual camera & phone, Keyboard shortcuts, Plugins, Updates & About). The window owns the tabs and plugins fill them with `SettingsSection`s, so two plugins can share a tab (Streaming holds Startup's Automatic streaming and the Wait screen) without knowing about each other. A tab nobody fills isn't shown, which is how a switched-off plugin's tab goes away, and a section with an unknown tab id gets a tab of its own just before Plugins. Settings apply as they change, with no OK button; a control that needs a step of its own keeps its button (Apply and reload for the canvas, Restart now for plugins). A setting that belongs to a panel's feature lives in that panel, not here, and a notification's on/off sits next to whatever triggers it (Monitoring's thresholds, the Automatic streaming stops). Sections are sorted by `order`, then by registration order. A search box sits above the tabs (**Ctrl+F** or just typing when it opens; arrow keys and Enter pick a result, Escape clears it) and a result takes you to its tab, scrolled to the setting and outlined for a moment. What it searches is read off the widgets: every `setting_row`, `control_row` label, card title, switch with text and tab, plus the small print, tooltips, button texts and drop-down entries in a row. Extra words come from `keywords=` on `setting_row` and `control_row`, `settings_search.keywords(widget, text)` for a card or anything else, and `SettingsSection.keywords` for a whole section, so a plugin's controls can be found without it doing anything.

### `theme.py`
The app's entire visual definition: palette constants (`BG`, `SURFACE`, `ACCENT`, `FILL`, the `OK`/`WARN`/`ERR`/`DIM` status set, `STATUS_COLORS`), a dark `QPalette`, and the stylesheet built from those tokens.
- `PLUGIN_HUES` - each card's own colour, by name. `hue(name)` gives it, or `ACCENT` for an unknown name or once `set_plugin_hues(False)` turned them off (Advanced, **Card colours**).
- `apply_theme(app)` - sets Fusion as the base style, installs the palette, applies the QSS. A no-op once installed, since re-applying repolishes every live widget.
- Tooltips: show after `TIP_WAKE_MS` (250 ms, Qt's is 700), wrap at about `TIP_LINE_CHARS` (64) characters, and stay up while the mouse is still on their control. `_PopupStyle` does it with a style hint and one event filter on Qt's single tooltip window (`_TipFilter`), not an app-wide filter.
- Focus: `keyboard_focus(widget)` is true only when focus came from the keyboard (Qt clears it on the next click), and `focus_ring()` is the ring every control draws then, white on filled ones. `_PopupStyle` swaps Fusion's square box on buttons for it and gives every dialog `_TabOrderFilter`, which tabs in reading order.
- No image files and no third-party theme: icons are inline SVG rendered by `create_vector_icon()`, and controls that need a custom look (segmented toggles, card actions, the preview stage) are targeted by object name or property selector.
- The layout rules every panel and dialog follows (type scale, control column, button roles) are written at the top of `widgets/common.py`.

### `plugin.py`
**TelescopePlugin** base class + **HostServices** contract + **EventBus**.
- Everything here a plugin can use (plus the banner classes and shortcut helpers) is frozen in `tests/plugin_api.txt`. `tests/test_plugin_api.py` fails on any change and says whether it breaks plugins. ARCHITECTURE.md has the rules for changing it.
- `HostServices` (typing.Protocol): the public surface a plugin may call on its `host` handle, made of eight narrower protocols a plugin can name when it needs only part of it: `HostSettings` (`schedule_save`, `save_now`, `plugin_config`, `apply_preset`, `preset_plugins`, `device_config`, `has_device_settings`, `switch_device`, `forget_device_settings`, `move_device_settings`), `HostStreams` (`is_streaming`, `is_starting`, `is_restarting`, `is_streaming_from`, `stream_count`, `start_stream(interactive)`, `start_again`, `stop_stream`, `stop_all_streams`, `reconnect_stream`, `focused_source_id`, `background_streams`, `pick_source`, `main_stream`, `make_main`, `update_stream_output`, `canvas_size`, `restart_vcam_canvas`, `stream_output`, `remove_extra_cameras`), `HostCamera` (`is_camera_on`, `is_camera_off_auto`, `can_turn_camera_off`, `set_camera_on`), `HostSources` (`add_stream_source`, `remove_stream_source`, `stream_source`), `HostView` (`view`, `set_view`, `take_view`, `steer_view`, `release_view`: the shown stream's zoom, pan, flip and rotation), `HostVision` (`vision_state`, `person_mask`, `want_people`: MediaPipe through `vision.py`), `HostPreview` (`add_preview_layer`, `remove_preview_layer`, `refresh_preview`, `pick_on_preview`, `finish_pick`, `cancel_pick`, `preview_overlays`: drawing on the preview and picking points there through `overlays.py`) and `HostShell` (`show_issue`, `clear_issue`, `send_notification`, `set_keep_in_tray`, `toggle_window`, `quit_app`, `restart_app`, `diagnostics_report`, `open_settings`, `shortcut_actions`). Structural typing only (`TelescopeWindow` implements it without inheriting). Keeps plugins off private window internals.
- `StreamsBehind`: for a plugin following the panels, what it keeps about a stream they moved away from while it streams on (`keep()` from `on_focus_lost`, `take()` from `on_focus_gained`, `drop()` from `on_stream_stop`). Camera control keeps its last phone state and focus point, the window's view what the phone crops and Transforms which lens it was on, so coming back to a tile shows the stream as it is without resending anything.
- `StreamSource` (Protocol): `id` (also its per-device settings key), `name`, `url`, `prepare(interactive)`, `open_reader()`, `control_client()` (stands in for `PhoneControlClient`: `base`, `auth`, `send`, `get_state`, `close`), `fps()`; optionally `redirect()`, `waiting()` and `cancel_wait()`. `HostServices.add_stream_source()` offers one.
- `UNCHANGED`: sentinel for `update_stream_output` so `None` can be passed as a real value (pass-through resolution) distinct from "leave as-is".
- What a plugin says about itself, for the Plugins tab: `title`, `about` (a sentence on what it does), `when_off` (what goes away when it's switched off, shown before it is) and `required` (can't be switched off: Connection, Setup and Updates). `device_local = True` keeps its settings per phone (under `devices[id]` in the config) instead of once for all phones; Presets saves and loads these.
- `TelescopePlugin.follows_focus` (default `True`): with several streams, the plugin hears about the one the panels show; `False` keeps it on the main one (the mic): the first, or the one `make_main` picked. The Microphone card shows the main stream's mic only while the panels show that stream; on another stream's tile it reads off, with a note saying where it's on, and turning it on there calls `make_main`. When the main stream stops with the mic on, the next one gets it on too.
- `TelescopePlugin`: override `setup`, `create_panel`, `on_stream_starting` (just before the worker opens the virtual camera), `on_stream_start`, `on_stream_stop` (the stream really started or ended, or came back after a drop), `on_focus_gained` / `on_focus_lost` (the plugin moved onto or off a stream that keeps running: a tile click, the shown stream stopping with others left, or the mic moving; by default they call `on_stream_start` / `on_stream_stop`), `on_camera_off` / `on_camera_on` (the stream carries on without video, or gets it back), `on_phone_state`, `process_frame`, `frame_step` (a copy of `process_frame` frozen at the current settings, for a stream the panels aren't showing; `None` by default), `get_config`, `set_config`, `apply_preset`, `diagnostics` (lines for Copy diagnostics), `on_plugins_ready` (every plugin is set up and the saved settings are in: a plugin emits again any state others follow, since one set up after it missed what it said during `setup`; Connection repeats `phones_changed` and `source_selected`, Microphone `mic_changed`), `shutdown`. The host calls the stream and phone-state hooks one plugin at a time and logs a hook that raises, so one broken plugin can't stop the others hearing about it; a `get_config` that raises keeps that plugin's saved settings.
  - `apply_preset(cfg)` loads a saved config; the default is `set_config`. Camera control and Stream output also send it to the phone while streaming.
  - `panel_region` (class attr): `"left"` / `"right"` / `"center"` - which region the host puts the panel in. A preference, not a guarantee: narrow windows merge regions.
  - `create_header_widget()` → a compact widget for the window header, or `None`. `header_side` (`"left"` / `"right"`) picks where it goes.
  - `create_settings_sections()` → `SettingsSection(tab, widget, order=0, on_show=None, tab_title="")`s for the Settings window, asked for once when it first opens, or `[]`. Lets a plugin without a panel have settings. `on_show` runs each time its tab comes on screen, to bring the controls in line with the plugin's state.
  - `create_tray_actions()` → `QAction`s for the tray menu, or `[]`. Asked once, at registration (after `create_panel()`); the host puts them between Show and Quit and the plugin keeps them up to date.

- `EventBus(QObject)`: signals - `stream_started`, `stream_stopped`, `stream_start_failed` (a Start ended without a stream: the stream info wasn't available or the phone didn't wake), `stream_connected(source id)`, `stream_lost(source id)` (frames stopped; Transforms greys out Zoom and Pan) and `view_status(ViewStatus)` (how the zoom is shared with the phone, for Transforms' lens dot), `people_seen(source id, [Person])` (where the people are, while something `want_people`) and `vision_state_changed(state)`, `vcam_opened(w, h)` (the stream opened the virtual camera at this size), `camera_watched(bool)` (Wait screen: an app started or stopped reading the camera), `stream_sources_changed([(id, name)])` (every offered StreamSource; ### `i18n.py`
The desktop's translations. `tr(text, ctx="", **fields)` and `trn(singular, plural, n, ...)` look a text up in the loaded language and fill in its `{fields}`; a missing, fuzzy or broken translation shows the English. `N_()` marks texts built at import time, which are translated with `tr()` where they show. `and_list()` joins words the language's way. `english(text)` turns a shown text back into its English, for keys that are saved (`widgets/collapse.py` keys folds by it). `load(lang=None, qt=True)` (from `main.py`, after the `QApplication` and before any window; `qt=False` from `splash.py`, before Qt loads) picks the system language, or `TELESCOPE_LANG`, from the `locale/<lang>.po` files, reads it with `read_po()` and its `Plural-Forms` rule, and loads Qt's own `qtbase` translation for standard dialogs. `find_all()` is the extractor `scripts/i18n.py` uses: every literal `tr()`/`trn()`/`N_()` call, with a `# Translators:` comment above it, and a problem for an f-string or fields the call doesn't pass. `add_plugin_catalog()` (called by `plugin_loader.load()`) gives an added plugin its own `locale/<lang>.po`: a `tr()` or `trn()` call made from a `telescope_ext.<plugin>` module looks there first, then in Telescope's catalog. A plugin file that can't be read is logged and skipped. `TELESCOPE_LANG=pseudo` loads a made-up language built from the template with `pseudo()` (every text longer and accented) for trying layouts; it isn't in `available()`. See [docs/translating.md](../docs/translating.md).

### `splash.py`
The Windows build's start-up splash, which PyInstaller's launcher shows before Python starts (`Splash` in `telescope.spec`, picture from `scripts/write_splash.py`). `show_text(chosen_language)` runs at the top of `main.py`, before Qt loads: it picks the language from Settings, `TELESCOPE_LANG` or Windows' display languages (asked through ctypes), loads it with `i18n.load(lang, qt=False)` and puts "Starting Telescope…" and why it can take a minute on the splash. `close()` takes it down once the window shows (or before an `--action` or the "extract first" message). Outside the packaged build both do nothing.

### `shortcuts.py`
What a keyboard shortcut can do, independent of how the key arrives. `ShortcutAction(id, label, group, run, params, release, repeats, describe, widgets, current)`: `run(params)` returns what to say ("Mute: muted") or `None` when the control can't be used now; `release` is for keys held down; `widgets` get "Add keyboard shortcut…" on a right-click. `Param` describes one setting (a choice, static or from a callable, or a number with bounds that can move, and `shown_if` another setting's value); `clean()` takes the strings `--action` sends. Most actions wrap a control so a key does exactly what using it does: `button_action` (click, or toggle/on/off/hold for a checkable one), `slider_action` (up/down by an amount in the units the card shows, set, reset to the slider's default), `log_slider_action` (ISO and shutter, in stops), `choice_action` (a combo or a row of exclusive buttons: next, previous, a named option; skips greyed-out items, and emits `activated` since some combos only listen for that). All check `control_ready()` (enabled and not hidden in its card) first. A `slider_action` can use `ready_widget` for a visible replacement controlling a hidden slider, as the pan pad does. Choice buttons can keep a stable `shortcutValue`, and combo items a `SHORTCUT_VALUE_ROLE`, while their displayed text changes; both names are accepted when loading a binding. Resolution choices keep the older `1280 x 720` value while displaying `1280 × 720`. Bindings are `{id, keys, action, params, global}`, keys in Qt's portable text; `clean_bindings()` keeps well-formed ones and gives a missing or repeated id a new one; `clashes()` names bindings whose keys an earlier one already uses.

### `plugin_loader.py`
Plugins people add, from `plugins_dir()` (a `plugins` folder next to the config, made with mode 700). Each is a folder holding `plugin.json` (`name` = the folder's name, `title`, `version`, `author`, `description`, `api`, `class`) and `__init__.py`. `find_installed(reserved)` lists every folder as an `Installed` with `problem` set when it can't load: no or bad manifest, a name that isn't lowercase letters, digits and `_`, a built-in name, `api` outside `OLDEST_PLUGIN_API`..`PLUGIN_API`, a link or compiled code (`.pyc`, `.pyo`, `.so`, `.pyd`) anywhere in it, or (POSIX) any folder or file in it another user owns or could write (group write is fine when the group is the user's own, with nobody else in it or using it as their primary group). Added plugins are off until `set_enabled(item, True)`, which stores the sha256 `digest()` of its files (`__pycache__` left out); `load_enabled()` loads only those whose files still match, so a changed plugin stays off until switched on again. `load()` deletes its `__pycache__` folders first (so only the checked source runs), then imports it as `telescope_ext.<name>` with `importlib` from its own folder, never through `sys.path`, so it can't shadow other modules, and checks the class is a `TelescopePlugin` with the same `name`. `install_zip(path)` unpacks a `.zip` holding one folder into a temporary folder in the plugins folder, refusing paths outside it, links, more than 500 files or 20 MB, and a name already there, sets its files to 644 and folders to 755, then moves it in, switched off. An added plugin that raises (or calls `sys.exit()`) while loading or starting is left out. `remove(item)` deletes a folder inside the plugins folder only. Folders from `dev_profile.plugin_folders()` come back as `Installed(dev=True)`: always on, digest without hidden files (`.git`), `__pycache__` left alone, and standing in for an installed plugin of the same name; the Plugins tab shows them without a switch or **Remove**. Built-in switches: `builtin_off()`, `set_builtin_off(name, off)`, `all_builtin_on()` (leaves the optional ones alone), `unnoticed_off()`, `notice_off()`, and for the `optional` ones, which are stored the other way round so a new one starts off for everyone, `optional_on()` and `set_optional_on(name, on)`. All of it is kept under `plugins` in the config file. `examples/plugins/black_and_white` is the example plugin [docs/writing-plugins.md](../docs/writing-plugins.md) starts from; `tests/test_plugin_loader.py` loads it.

### `session.py`
- `StreamSession` (frozen dataclass): one stream's `id` (guards against stale async results), `url`, `client`, `worker` and `source`.
- `Sessions`: the bookkeeping behind the window's stream lifecycle, with no Qt in it: `streams`, `focus`, `main`, `pending`, the start under way (`waking`, `wake_source`, `preparing`), `restarting`, `stopping_all`, and what waits for a start to be through (`restart_later`, `held_states`, `start_later`, `canvas_restart`). Queries: `shown`, `find(id)`, `background()`, `by_worker(worker)`, `is_starting()`, `is_waking(id)`, `is_streaming_from(id)`, `active(selected)` (the shown stream, else the one waking, else `selected()`), and who hears about a stream: `hearing(plugins, source)`, `followers(plugins)`, `stays(plugins)`. `add`/`forget` keep `streams` and each source's `session` in step; `drop_queued()` is for a Stop. `StreamFlow` (below) does the starting and stopping and calls the plugins; `tests/test_session.py` tests this part without a window.

### `stream_flow.py`
**StreamFlow(host)** - starting, stopping and moving the panels between streams, on top of `Sessions` (`flow.sessions`, which the window reads as `_sessions`). `start()` / `wake_done()` / `begin_stream()` start a source (waking a phone first), `stop()`, `stop_all()`, `stop_stream(id)` and `drop_pending()` stop one or all, `move_focus()` / `show_focus()` / `focus_stream(id)` / `pick_source(id)` / `add_stream(id)` move the panels and add streams, `set_main()` / `sync_main()` / `make_main(id)` keep the plugins that stay put (the mic) on one stream, `reconnect_stream()`, `stop_for_restart()` and `after_start()` restart one and run what waited for a start, `begin_recovery()`, `stream_reconnected()` and `park()` handle a dropped stream, and `free_slot()`, `start_worker()`, `pipeline()` (the window's view first, then plugin steps in registration order, those with `sees_final_frame` last) and `announce_idle_outputs()` pick the virtual camera, make the worker and tell the wait screen what's free. `slot_memory` and `start_id` live here too. It reaches the window only through `FlowHost` (a `Protocol` in the module: plugins and their hooks, sources by id, banners, the Start button, the footer, tiles, per-device settings, `new_worker()` / `end_worker()`); `app._FlowHost` forwards each to the window, and `tests/test_stream_flow.py` drives it with a stand-in and no window.

### `view.py`
The view's maths, with no Qt and no window: `View` (frozen: `zoom`, `pan_x`, `pan_y`, `flip_h`, `flip_v`, `rotation`), `ViewStatus` (what `view_status` carries), `ROTATIONS`, and these, all pure:
- `split_zoom(zoom, pan_x, pan_y, caps)` - the framing asked for as the phone's share (`PhoneZoom(ratio, crop, x, y)`, sent as the `zoom` control) plus the desktop's remainder `(zoom, pan_x, pan_y)`; together they always frame the same. The phone's ratio only steps between lenses (`lensZooms`, the ratios where a multi-lens camera's longer lenses take over): the longest lens whose centred view still holds the window, with a 5% margin to move onto a lens (capped at the zoom itself, so a centred window always gets its lens) and none to stay on it (`current_ratio`). Phones animate ratio changes, so a ratio that followed the pan made the picture breathe. A freeform crop then cuts the window itself out of that lens's view; with a centre-only crop the phone stops at the lens and this computer does the rest, so the phone's share never changes with the pan. `PhoneZoomCaps.from_camera(cam)` reads `zoomRatioMax`, `cropZoomMax`, `freeformCrop`, `lensZooms` from the current `/v1/state` camera; `None` (a lens that can't zoom, an older phone app, not streaming) leaves it all to the desktop. `lens_step(lens)` is a lens as a Zoom slider value, rounded up so the mark always gets the lens (`_lens_ratio` allows float slack, as 1/(1/z) can land a hair under z).
- `apply_zoom`, `zoom_origin` and `transform_frame` - the crop, then flip and rotation, on a frame. The crop is fractional (an affine warp): one cut at whole pixels made a slowly moving framing shake.
- `to_full(view, u, v)` / `to_shown(view, x, y)` - `shown_to_view` / `view_to_shown` with a `View`'s own fields, for points kept in the whole picture (preview picks).
- `shown_to_view` / `view_to_shown` - continuous and unclamped: a point in the frame as shown to and from the full view of the main lens, by the zoom/pan asked for (not the desktop share). `pan_for(centre, zoom)` inverts `window_centre`. `zoom_detent` stops a scroll on the first lens mark it crosses. `lens_boxes(caps, ...)` - each longer lens's centred 1/ratio of the view, as shown.
- `inverse_map(u, v, w, h, zoom, pan_x, pan_y, flip_h, flip_v, rotation)` - a point in the transformed frame back to the phone's frame (undoes rotate, flip, then zoom).
- `phone_window(phone)` - the `(zoom, pan_x, pan_y)` a phone share sends. `rest_within(zoom, pan_x, pan_y, phone, clamp)` - what this computer crops when the phone stays on that share, or None when the framing doesn't fit inside it (clamp: the nearest that does). `share_shift(old, new)` - how a point moves between frames cropped to two shares.

### `overlays.py`
What plugins draw on the preview and the points they ask for there, never part of what apps get. The window makes one `PreviewOverlays` (`window._overlays`) and the `HostPreview` methods forward to it; the Preview plugin draws it (`attach()` once it has a stage, so picks can start).
- `PreviewLayer`: `tint(frame)` on the UI thread with the preview's scaled copy (in `PreviewPlugin._on_frame`, so it adds nothing to the output's lag), `analyse(frame)` on the `preview-analyse` thread at most `analyse_fps` a second with a copy from before any tint (newest frame only, started the first time a layer wants one), `paint(painter, rect)` on the UI thread, clipped to the frame. Layers run by `order`; one that fails is logged once and leaves the frame or the painting alone. `refresh()` (any thread) emits `changed` on the UI thread, which repaints the preview.
- `set_warp(owner, matrix)` (`HostPreview.set_preview_warp`, any thread): a plugin moving the whole picture after the view. `unwarp()` and `warp_point()` map between the preview and the frame as shown; picks, the Preview plugin's clicks, scrolls and drags go through them, and `Pick.in_picture` has the points on the warped picture. `end_warps()` on `stream_stopped`.
- Picks: `start_pick(owner, kind, on_done, start, hint)` for "point", "rect" or "quad" cancels any other and keeps the points in the whole picture (`view.to_full`), so they stay on the same spot while zoom, pan, flip or rotation change mid-pick. `press`/`move`/`release`/`key`/`cursor` take the mouse from `FrameLabel` in shown coordinates: a point ends on release, a rect once it's dragged past `_MIN_RECT`, a quad's corners are dragged (inside it drags all four; outside is left to the preview to pan) and Enter or `finish_pick` ends it. Esc, a right click, `cancel_pick`, the last stream stopping or the panels moving to another phone (the window connects `stream_stopped` and `device_changed`) hands `on_done` None. Dragging a whole quad stops where a corner reaches the picture's edge. The result is a frozen `Pick(kind, shown, full, picture)`; a rect's corners are sorted in each space and `picture` is a copy of the last frame the preview showed (kept only while a pick runs), for reading a colour where someone clicked. `pick_changed` becomes `bus.preview_pick_changed`. `_paint_pick` darkens what's outside the area, draws the corners and a hint chip at the top.
- `tests/test_overlays.py` checks the mapping through every view transform, the pick flows and the layer threading.

### `pictures.py`
`read_picture(path)` and `cover(image, w, h)`, shared by Background and Chroma key for the picture behind you.

### `scopes.py`
Histogram, waveform, RGB parade and vectorscope maths for the preview, numpy and OpenCV only. `shrink()` scales to `SCOPE_WIDTH` (256) columns first, so a scope costs one to four milliseconds at any stream size. `histogram`, `waveform` (a `bincount` of level x column, level 255 in row 0), `parade` and `vectorscope` (Cb right, Cr up) return counts; the `*_image` functions turn them into BGRA pictures (`glow()` is a log scale, the vectorscope's graticule with the 75% bar targets and skin line is drawn once per size). `scope_image(name, frame)` is what Cinema tools calls. `tests/test_scopes.py`.

### `view_controller.py`
**ViewController** - the window's view of the shown stream (`window._view`, the `HostView` methods forward to it). It's a `TelescopePlugin` subclass so it hears the stream hooks like a plugin that follows the panels, through `FlowHost.plugins()`, but it isn't in the plugin list: it has no card, no settings and can't be switched off. `tests/test_view_controller.py` tests it.
- `set_view(**changes)` is the manual view (Transforms). `take_view(owner)` / `steer_view(owner, zoom, pan_x, pan_y)` / `release_view(owner)` let one thing at a time move zoom and pan (Auto framing); manual zoom and pan wait meanwhile and come back on release, flip and rotation stay manual.
- It tracks the current camera from `on_phone_state` and `bus.camera_switched`, re-splits on any view or caps change and sends the phone only changes (and again on each stream start), then emits `view_status`. Nothing is ever sent until something set a view, so with Transforms switched off the phone is left alone. A stream the panels leave keeps what the phone crops through `StreamsBehind`.
- `process_frame(frame)` - the desktop's share of the crop, then flip and rotation; runs on the worker thread and reads plain attributes the Qt thread writes (the GIL makes them atomic). `frame_step()` freezes them for a stream behind the panels.
- While something steers, `_held()` keeps the phone on the share it was sent, with `_HOLD_SLACK` room around the framing, so small moves are cropped here and the phone doesn't hop lenses or lag behind. It sends a new share at once when the framing leaves the old one, or after the share it would pick has been clearly different (`_HOLD_DRIFT`) for `_HOLD_S`. A fresh `take_view` picks one on the first steer. A new share on the same lens starts a `_Handover`. Frames keep the old share's crop (clamped) until `moved_like` sees a frame shifted the way the new share would shift it, compared at 128x72 against the last frame, or `_HANDOVER_S` passes. Without it the picture jumped for the few frames the phone takes to catch up. No new share is picked while one is on its way.
- `feed_raw` gets `_upright(view)`: the small copy is flipped and rotated the way it's shown (pose finds people upright), and each point goes back through the phone share it was sent with onto the picture as shown at zoom 1. `aspect()` is that picture's width over height (`HostView.view_aspect`).
- Maps `bus.focus_point_picked` back through the desktop's share only, with the last frame's size, and emits `bus.focus_point`; the phone maps it on through its own crop. It also emits `lens_boxes` and `view_pannable` for the preview.

### `pose.py`
What a pose says, for the plugins that look at people (Auto framing, the preview's skeleton), with no Qt: `SEEN` / `ARM_SEEN` visibility bars, `body(person, aspect)` (shoulder centre and width), `arm(person, side, aspect)`, `hands_out(people, aspect)` and the skeleton's `BONES`.
`upright(person, aspect)` levels the shoulders in picture heights, uses the head or hips to choose which way is up, and returns the pose plus a mapping back. Framing and hand detection use it so rotation and flips keep the same body region in view.

### `vision.py`
MediaPipe for the plugins that ask, with no Qt: the window makes one `Vision` (`window._vision`) and the `HostVision` methods forward to it.
- Nothing loads until a plugin asks (`person_mask` or `want_people`); then `load()` imports MediaPipe on a thread. `find_backend()` looks for the pack in `pack_dir()` (`vision_dir()/<pack id>`, in the user's data folder or the dev profile, so app versions with the same pack share it): `site/` holds MediaPipe unpacked (absent when it's pip-installed from `requirements-vision.txt`) and `models/` the selfie segmenter and the lite pose model, read into memory since a model path with non-ASCII characters fails on Windows. MediaPipe's drawing helpers import matplotlib, which isn't there, so an empty one stands in. `state()` is off, loading, ready, missing (no pack) or failed (it tries again after missing, not after failed). Before anything has asked, it already says missing when there's no pack (`pack_there()`, which imports nothing), so the preview knows whether to offer its skeleton.
- `current_frame` (a `ContextVar`) is `(worker, frame number)`, set by `StreamWorker._publish` around the plugin steps, so `person_mask(frame)` knows the stream without a new `process_frame` argument. Each stream gets its own tasks (VIDEO mode tracks between frames and wants each task's timestamps to go up) and a mask is worked out once per frame however many plugins ask. The segmenter gets `model_input(frame)`, a copy just big enough to cover its 256 × 144 input with an area shrink: MediaPipe's own shrink picks single pixels, which lets camera noise through as flicker at the mask's edges. The mask is blended with the last one at that size (`_MASK_CARRY`, more while nothing moves), then scaled up once to the frame's size. `_Motion` compares a 64 × 36 grey copy with the frame last used: while nothing moves the mask is worked out every `_MASK_STILL_EVERY_S` (15 times a second) and reused in between, and anything moving brings it back to every frame. `set_power_saving(True)` (Power-saving effects in Video settings) keeps the mask at that rate while things move too, and people at `_SAVING_PEOPLE_EVERY_S` and `_SAVING_PEOPLE_STILL_EVERY_S`; `diagnostics()` says when it's on. A `vision-tidy` thread (started with the first stream) runs `tidy()` every `_TIDY_EVERY_S`: a stream's segmenter that no plugin asked for in `_IDLE_CLOSE_S` (10 s) is closed under its `lock` (which `person_mask` holds per frame), and a people thread not fed for that long gets its `people_quit` event and closes the pose model on its way out; both then hand freed memory back (`malloc_trim` on Linux). The next ask makes them again, so flipping a switch back within 10 s finds them still loaded.
- `feed_raw(frame, prepare, to_shown)` is called by the window's view before it crops, while something wants people: a small copy every `_PEOPLE_EVERY_S` while something moves, or every `_PEOPLE_STILL_EVERY_S` while nothing does (its own `_Motion`), goes to that stream's people thread (newest only), which turns it upright with `prepare`, runs the pose model and reports `Person`s (named landmarks, put through `to_shown` onto the picture as shown at zoom 1) through `on_people`. The window hands them to the Qt thread and emits `people_seen` with the source id.
- `drop_stream(worker)` when a worker ends, `shutdown()` on quit, and `diagnostics()` for Copy diagnostics (state and median ms; only the error's type, since its message can hold a path with the user's name).
- `shutdown()` waits for any active state or people callback and blocks later callbacks before the window releases its Qt signal receivers. A loader or detector finishing afterwards cannot notify the deleted window.

### `vision_pack.py`
The vision pack (MediaPipe unpacked plus the two models) that the optional plugins download, with no Qt and no OpenCV, since the release's `vision` job runs `scripts/build_vision_pack.py` on a bare Python (`tests/test_vision_pack.py` checks). It has the model names and `default_dir()`, where packs are unpacked (`vision.vision_dir` is the same function). `vision_pack.json` next to it, written by `scripts/build_vision_pack.py --write`, names each platform's pack by `tree_hash()` of its files (a sha256 over each file's path and sha256, since zips of the same files differ between zlib builds), so an app update only downloads it again when a pin in `requirements-vision.txt` changed. `platform_key()` is `linux` or `windows` (64-bit Intel/AMD only; elsewhere there's no pack and the plugins can't be switched on). `download(vision_dir)` fetches `Telescope-vision-<platform>-<id>.zip` from this build's release (`version.release_asset_url`), stops when it gets much bigger than expected, unpacks into a staging folder (refusing paths that escape it), checks the tree hash, writes `.verified` and renames it to `vision_dir/<id>`, then deletes older packs; any problem is a `PackError` worded for the person who clicked. `installed()` checks the `.verified` marker, `remove()` deletes them all. `tests/test_vision_pack.py`.

### `sources.py`
What the window streams from. `Source` holds one stream's state (its `session` while it streams, the virtual camera `slot` it feeds, camera off and whether that was automatic, `camera_toggle`, recovering, behind, settling reports, slow arrival, pending resolution, and the status, readouts and last phone state the footer and panels get back when they return to it) and no-op hooks the window calls at each step: `prepare`, `wake`, `started`, `stopped`, `lost`, `end_recovery`, `check_camera_rate`, `on_phone_state`, `watch_alive`, `camera_turned_on`, `drain_stops`. Sources reach the window only through `SourceHost` (a `Protocol` in `sources.py`: the Connection and Stream output plugins, banners, whether it's waking or shown, and a few callbacks such as `wake_done`, `stop_source`, `mic_reconnected` and `lost_contact`); the window hands them `app._SourceHost`, which forwards each to its own methods, and `tests/test_sources.py` drives sources with a stand-in.
- `PluginSource` - a plugin's `StreamSource` (see `plugin.py`), ready once the virtual camera and the source are; nothing to wake, no state, and its reader waits for it after a drop. On Linux an Auto canvas becomes 1920x1080 (`auto_canvas`).
- `PhoneSource(host, phone_id)` - one paired phone; the window makes one per id as needed (`_phone_source`), and passes the id to Connection's per-phone calls (`get_stream_info`, `session_target`, `recovery_probe`, `adopt_stream_route`, `show_problem`, `release_stream`). Owns the wake (`_wake_id`, the target to stop if a wake lands after Stop), the remote stop and its tracked threads, the state fetch, route recovery (`_recovery_gen`, `_recovery_route`, the retry timer), the camera-rate check, the alive poll while the camera is off, and the check after turning the camera back on. It calls back through its `SourceHost` for the session, banners, the footer and stopping.

### `stream.py`
**StreamWorker(QThread)** - video capture and virtual camera output.
- Reads the authenticated stream with `MjpegReader` (`mjpeg_reader.py`) or, for a URL ending `.h264`, `H264Reader` (`h264_reader.py`), or for one ending `.udp`, `UdpH264Reader` (`udp_reader.py`); all send the bearer token and report `last_frame_bytes` for the throughput readout. Writes to the virtual camera opened by `vcam.open_camera()` (at the canvas or phone size, or `vcam.locked_size()` while an app holds the camera at another) and emits `vcam_opened(w, h)` once it's open.
- Three kinds of thread: a reader pulls packets off the wire (`read_packet()`) and hands only the newest to the decoders (`_Newest`), so a slow decode drops frames instead of building up lag; decoders (`MJPEG_DECODERS`, 2 on most machines, for MJPEG; one for H.264, which `H264Reader` decodes in order while reading) run `decode()` and then `_publish()`; the vcam loop sends each new frame as soon as it's ready and resends the last one once a period otherwise.
- `open_reader` (a StreamSource's) replaces the phone's reader; its `waiting_text`, if it has one, is the status while it can't open.
- `frame_pipeline: list[Callable]` - each callable receives a BGR numpy array and returns one; applied in order after resize, one frame at a time under a lock (plugins aren't thread-safe), and a frame older than the one already out is dropped. The host wraps each plugin step in `guarded_step()`: a step that raises or returns something other than an HxWx3 uint8 frame passes the frame through unchanged, and after `STEP_FAILS_BEFORE_SKIP` failures in a row it's skipped for the rest of the stream. On Linux the virtual camera opens in I420 when the size is even (`_vcam_format()`) and each new frame is converted once with OpenCV, about 8x cheaper than pyvirtualcam's own conversion from BGR; resends reuse it. Elsewhere it opens in BGR.
- `update_output(width, height, fps)` - hot-swap output resolution/FPS without stopping the worker. An FPS change reopens only the virtual camera (`_run_vcam()`); the phone connection and reader thread stay up.
- Emits `status(kind, msg)` for the footer: `"ok"`, `"warn"`, `"fps"`, `"net"`, `"net_warn"`, `"reconnecting"`, `"idle"`. `"fps"` is frames that arrived from the phone, not what went to the virtual camera (that loop resends the last frame when none comes, which padded a phone at 30 up to 42 at 60 fps). `"net_warn"` needs two 2 s windows in a row under 85% of the target; a window with no frames at all doesn't count, since that's a drop the reader is about to reconnect.
- `settle()` - the phone is restarting its camera, so windows don't count toward `"net_warn"` until frames have kept coming for `SETTLE_AFTER_FRAMES_S` (2.5 s; a gap over `SETTLE_GAP_S` starts that over), or `SETTLE_MAX_S` (10 s) has passed. The worker starts settled this way and settles itself on a reconnect or FPS change; the host calls it on `camera_switched` and `resolution_change_requested`.
- `run()` never dies quietly: a crash logs, emits `"error"`, and always ends with `"idle"`, which the host treats as "stopped unexpectedly" (banner with Start) when it didn't ask for the stop. A reader thread that crashes wakes the vcam loop so the stream reconnects instead of freezing on the last frame.
- Auto-reconnects: `DROP_RETRY_DELAY` (1 s) between tries after a stream drops mid-way, `RECONNECT_DELAY` (3 s) after an open fails. `set_parked(True)` closes the virtual camera (waiting up to 1 s for it) while the reader keeps reconnecting; `set_parked(False)` opens it again. `retarget(url)` switches the URL it reconnects to and skips the rest of the wait; the host calls it when the phone is reachable another way.

### `vcam.py`
The virtual camera outside a stream. Streams can go to up to `MAX_SLOTS` cameras at once: slot 0 is the usual one, and `slot_label(n)` names the others ("Phone Camera 2" on Linux, found by label through sysfs in `slot_device(n)`; "Telescope #2" on Windows, as UnityCapture numbers the extra devices it registers). `slot_ready(n)` says whether one is set up. `open_camera(w, h, fps, fmt, slot=0)` opens `/dev/video11` (Linux) or the UnityCapture device named `UC_NAME`, falling back to any free one (Windows); `stream.py` uses it too. `locked_size()` (Linux) reads the size from sysfs while an app still reads the camera: v4l2loopback keeps its format then and silently ignores a writer asking for another, so the stream and the wait screen both open at that size instead (the stream letterboxes into it).
- `WaitScreen` holds the camera while nothing streams and shows `load_frames(path, w, h)` on it (flipped left to right with `show(..., mirror=True)`): the chosen image or GIF fitted to the camera size, or the default screen. Frames are prepared once (I420 on Linux, so a send is a plain write), sent once a second while nobody reads the camera (on Windows, until an app's filter creates the shared image, `_uc_filter_probe()` looks for it every `FILTER_POLL` (50 ms) and the frame goes out the moment it appears, so UnityCapture's own screen shows for a frame or two at most), and at `STILL_PERIOD` or the GIF's own timing while someone does. A GIF keeps every nth frame past `FRAME_BUDGET` (64 MB).
- `CameraWatch(on_change)` reports whether an app is reading the camera: the v4l2loopback client-usage event (0.13+), a `/proc` scan every 5 s on older drivers (`camera_holders()`), or on Windows the `UnityCapture_Want` event an app's filter sets for each frame it wants (`_uc_object_name()` mirrors pyvirtualcam's numbering). The filter creates that event when an app first opens the camera, so while it doesn't exist the watch reports no reader.
- `device_released()`: both let go of the device for the block (module reloads fail while anything holds it) and take it back after.

### `jpeg_guard.py`
`decode_jpeg(data)` is `MjpegReader.decode`: it reads the declared size from the first start-of-frame header (`jpeg_size`, every SOF variant, segments skipped by length) and returns None, dropping the frame, when it is over 8192 px a side or 64 MP, or has no readable header, before `cv2.imdecode` can allocate it.

### `h264_reader.py`

Hardware fallback retains the latest SPS/PPS and retries the input in software, so later TCP keyframes can decode without reconnecting. `decoding_backends()` reports live decoder instances, independently of the setting for the next connection.

Each `Decoder` converts frames to BGR with its own `ToBgr` (one `VideoReformatter` with 4 threads; `BrowserReader` uses one too). `frame.to_ndarray()` would build a new swscale context and its slice threads for every frame.

**H264Reader** - the `/v1/video.h264` counterpart of `MjpegReader`: `open()` checks the `video/h264` response, `read()` returns the newest frame completed by the next data that finishes one (older frames in the same data are dropped). `new_decoder()` / `decode_newest(codec, data)` / `decode_counted(codec, data)` (also how many frames the data finished) are the pure decode steps (PyAV, low-delay, 2 threads). PyAV is optional: `available()` is False without it, and the desktop then offers only MJPEG. It checks without importing, and PyAV itself is imported by the first decoder, so a start that never streams H.264 doesn't load it (on a Windows first start that's tens of seconds of files being checked). The same goes for `cryptography` in `udp_reader.py` and `sounddevice` in the Microphone plugin. `new_decoder()` returns a `Decoder`: on the graphics card when `set_hardware(True)` (Hardware acceleration in Video settings) and `hardware_device()` found one (`d3d11va` or `cuda` on Windows, `vaapi` (with a VA-API PyAV, see `pyav_vaapi.py`) or `cuda` on Linux, probed once by opening it), else in software; a hardware one that raises is swapped for software on the spot and not tried again that run (`hardware_in_use()`). A packet it rejects only counts as the card's fault before it has decoded a frame; after that it's skipped as the stream's.

### `udp_reader.py`

Reassembly repairs partial keyframes at startup, during playback and after a gap. A keyframe gets more time while new fragments arrive, but duplicates do not extend its timeout. A newer keyframe can replace a full backlog.

**UdpH264Reader** - the experimental `/v1/video.udp` (docs/protocol.md) with `H264Reader`'s interface: `open()` gets the key and the phone's port over HTTPS, `read()` decodes the next whole frame. It falls back to an `H264Reader` on `.h264` (`fell_back`) when the phone refuses, or when nothing decodes within `FIRST_FRAME_S`, and then skips UDP for that phone (`_UDP_FAILED`) for the rest of the run. `Seal` is one direction's AES-GCM with its replay window; `Reassembler` (pure, driven by the caller's clock) puts pieces back into frames in order, says which to NACK and when to give up on one and wait for a keyframe. Without `cryptography` it goes straight to TCP.

### `browser_server.py`
The Browser camera, Qt-free: a device's browser opens `https://<this computer>:8767/#<token>` (`BROWSER_PORT`, any free port if taken) and the page (`telescope/web/`: `index.html`, `app.js`) sends its camera and mic over WebRTC (`browser_rtc.py`). A WebSocket on `/ws?token=&id=` (`id`: one the page keeps in the browser's storage, so a reload is the same browser) carries the rest as JSON: the page's `hello` (device, why there's no mic), `offer` and `stats` (what it really sends, and `limit`), and the server's `config` (size, fps, whether to send audio, `max_kbps`, the virtual camera it streams to) whenever it changes, `answer` or `rtc_error`. docs/protocol.md has the details. The page's script is run in Node by `tests/test_browser_page.py` (`tests/js/page_harness.js` stands in for the browser, WebRTC included, and holds its promises; skipped without `node`).
- `ensure_certificate(folder, hosts)`: a self-signed EC certificate (`cryptography`) next to the config, 0600, valid 397 days (browsers refuse longer) and kept until 30 days before it ends, so a browser told to trust it keeps doing so. `certificate_available()` is False without `cryptography`.
- `BrowserHub(can_join)`: a `BrowserFeed` per browser id. `join(id)` gives the browser its feed, or a new one when `can_join(id)` says there's a camera left for it; `drop(id)` forgets one that left; `set_capture` goes to every feed. Given one feed instead, every browser shares it.
- `BrowserServer(hub, cert, key, on_change, rtc_session=)`: `start()` / `stop()`, `url_for(host)`, `new_token()` (the old link stops working and its browsers are dropped with 4002, `CLOSE_NEW_LINK`, so their pages stop instead of retrying). TLS is done on each connection's own thread; at most 16 connections, 6 per address. A wrong token gets 403. A newer connection from the same browser id replaces the older one, which gets close code 4000 (`CLOSE_REPLACED`); a new browser with no room gets 4001 (`CLOSE_FULL`); `stop()` closes with 1001. The server pings every 3 s (`_PING_S`, which browsers answer by themselves) and closes a connection it hears nothing from for 10 s. Each offer gets a new `rtc_session(on_video, on_audio)` (a `browser_rtc.RtcSession`; tests pass a stand-in), closing the one before; it's closed when the connection ends. Each connection's thread does all its own sending and closing (an SSL socket mustn't be touched while another thread reads it, and on Windows a shutdown from another thread doesn't wake the read), checking every 0.5 s for a changed config or for `new_token()` / `stop()` having ended it. Answering an offer blocks that thread for as long as aiortc takes (under a second without STUN).
- `ServerStats` (`server.stats`, new on each `start()`): the port, whether 8767 was taken (`fell_back`), and counts of how far browsers got: `connections`, `tls_failed` (hung up in the handshake, which is what a browser that hasn't accepted the certificate does), `pages`, `refused` (old or wrong token), `browsers`. Counts only, no addresses or tokens; each step is logged the first time it happens, and the port when it starts.
- WebSocket framing by hand (`ws_accept_key`, `ws_frame`, `unmask`, `_WsConnection`): masked frames in, fragments assembled, pings answered, messages over 64 KB end the connection, binary ones are ignored.
- `BrowserFeed`: what the server hands over, per connection generation, so an old browser's frames never come out after a new one connected. It keeps the newest decoded frame only (`put_video`, with `frame_bytes` for the throughput readout), and `codec`, `rtc_error` and `sent` (the page's stats) for the card. `max_kbps()` is what the page may send at its size and rate. `BrowserReader` is StreamWorker's reader on it (same interface as `MjpegReader`): `read_packet()` hands over the newest `av.VideoFrame` and `decode()` turns it into BGR with `h264_reader.ToBgr`, on one decode thread. `open_audio()` is AudioWorker's opener: a `BrowserAudioStream` that lasts through the browser reconnecting, or an `HTTPError` carrying the browser's reason when it has no mic. `BrowserControl` stands in for `PhoneControlClient` (`base`, `auth` = `BrowserAuth`), so the Microphone plugin works unchanged.

### `browser_rtc.py`
The Browser camera's WebRTC side, Qt-free, on aiortc (imported only when used; `available()` is False without it and the card says so). One asyncio loop on a daemon thread (`browser-rtc`) serves every browser. `RtcSession(on_video, on_audio)`: `answer(offer, max_kbps)` blocks up to 10 s and returns the answer or raises `RtcError`, `close()` returns at once, `codec` is what the answer settled on. Video comes out as `av.VideoFrame` with the bytes per frame worked out from the transport's stats once a second; audio is resampled to 48 kHz mono s16le, the same PCM a phone's `/v1/audio` sends.
- No ICE servers: aiortc falls back to a public STUN server when given none, which also cost about 5 s per answer.
- `_widen_jitter_buffers`: each video receiver's jitter buffer is swapped for one of 1024 packets (`JITTER_PACKETS`). aiortc's own 128 packets (~150 KB) can never hold a sharp 1080p keyframe, so it asks for another keyframe forever and no frame ever comes out. It reaches into aiortc's private attribute and logs a warning once if that's gone.
- `tune_answer(sdp, max_kbps)` adds `x-google-start-bitrate` (two thirds of the max) and `x-google-max-bitrate` to the video codecs; `answer_codec(sdp)`; `max_kbps_for(w, h, fps)` (0.15 bits per pixel per frame, 1500 to 12000 kbps).
- aiortc 1.15 asks for PyAV below 18 but runs on 18 (its main branch already allows it), so it's installed with `--no-deps` from `requirements-nodeps.txt` and its own dependencies are in `requirements.txt`. `pip check` complains about that and nothing else does.

### `audio.py`

The jitter buffer marks refill silence so Auto level does not learn it as room noise. Quiet catch-up skips only positive excess audio. Audio handover preserves buffered samples, interrupts a stalled old HTTPS read and resets jitter measurement to the new route's USB or Wi-Fi target.

The phone's mic into the virtual mic. `JitterBuffer` (pure): silence until its target has built up (`USB_TARGET_MS` 20 or `WIFI_TARGET_MS` 40, growing up to `MAX_TARGET_MS` 120 when audio arrives unevenly) and silence-padding on a gap. It follows clock drift by playing up to `MAX_SKEW` (0.2%) faster or slower (`FAST_SKEW`, 0.5%, when far over and never quiet), skips a quiet moment with a crossfade once `QUIET_SKIP_MS` over the target, and jumps back to the target past `MAX_MS`. `AudioWorker`: a reader thread (`/v1/audio` with the bearer token; on a refusal it reports the phone's `error` and retries every 3 s, so allowing the mic on the phone just starts it) and a writer thread that drains 10 ms at a time into a sink at the sink's pace. Sinks: `FifoSink` (Linux: writes the virtual mic's FIFO, paced to real time itself since the pipe source reads whatever arrives, with the pipe shrunk to one page so a stalled reader can't build up delay; it refuses anything that isn't a FIFO owned by this user, and won't follow a symlink) and `SoundDeviceSink` (Windows). `on_status(kind, text)` comes from the worker threads. The writer's `_shape()` applies `gain`, then the limiter when `limit` is on (peaks held under -1 dBFS: down within 1 ms, back up at 25 dB/s; a few microseconds a chunk, and quiet audio skips it), then clips to 16 bits; mute comes after. `take_level()` gives the loudest (peak, rms, limited) since the last call, with gain and limiter counted and mute not. It's measured in the reader as audio arrives, since PipeWire stops reading an idle virtual mic and that stalls the writer. `muted` writes silence instead; gain and mute changes both fade over one chunk so they don't click; the sink keeps running, so apps never lose the mic.

### `platform/virtual_mic.py`
Linux: `linux_setup()` loads `module-pipe-source` (`telescope_mic`, "Telescope Microphone", s16le 48 kHz mono) on `fifo_path()` with `pactl`. `fifo_path()` is in `XDG_RUNTIME_DIR`, else a `telescope-<uid>` folder in the temp dir that must be a real 0700 folder owned by this user. It's an input only, so nothing shows up as a speaker. `remove_stale_source()` unloads a source a crashed run left (`main.py` calls it at start, once it holds the single-instance port, so a kill -9 doesn't leave the mic listed). `linux_setup()` does the same first (including the null sink + remap the first builds used), and retries without the description if a server rejects it. `linux_teardown(ids)`. Windows: `find_vb_cable(devices)` finds CABLE Input in `sounddevice.query_devices()`. `download_vb_cable()` fetches VB-Audio's `VBCABLE_Driver_Pack45.zip`, refuses it unless its SHA-256 matches the pinned one, and unpacks only top-level names into a temp folder; `run_vb_cable_setup()` hashes `VBCABLE_Setup_x64.exe` again and opens it with ShellExecute's `runas` (UAC). It's VB-Audio's own setup with its own windows: their readme doesn't allow folding VB-Cable into another setup. Runners, `urlopen` and the launcher are injectable for tests.

### `dev_profile.py`
`TELESCOPE_DEV_PROFILE` (set by `scripts/dev_desktop.py`) names a folder; when set, `active()` is true and the config, log, single-instance lock (`instance_address(dev=True)`), virtual mic source and USB pairing package (`com.telescope.dev`) all move off the real app's, and the menu entry, dock grouping and sign-in toggle are left alone. Read at import, as at startup.

For writing plugins, `dev_desktop.py --plugin FOLDER` sets `TELESCOPE_DEV_PLUGINS` (read by `plugin_folders()`, only in a dev profile) and `TELESCOPE_DEV_SUPERVISED` (`supervised()`). `plugin_loader` then loads those folders as they are and always on. `main.py` looks at `files_stamp()` of them every 0.7 s and calls `restart_app()` when it changes. Under `supervised()`, `restart_app()` doesn't relaunch: it quits with `RESTART_EXIT` (or `RESTART_STREAMING` while streaming) and `dev_desktop.py` starts it again in the same terminal and profile, with `TELESCOPE_DEV_RESUME` set for the second so `main.py` starts streaming once it's up (`resume_stream()`). `dev_desktop.py` stops the app when it's stopped itself. `scripts/check_plugin.py FOLDER` runs a plugin next to the built-in ones in a throwaway profile, offscreen, and reports each problem with the plugin's own traceback (`tests/test_check_plugin.py`).

### `config.py`
Load/save of `telescope_config.json` with versioned schema (current: v3) and per-section validation. It holds the pairing tokens, so on Unix the folder is kept 0700 and the file, its temp file and any `.invalid-*` backup 0600. A file that can't be read is backed up once per launch and `take_reset_notice()` tells the window, which shows a banner.

**v3 schema:**
```
{
  "version": 3,
  "selected_device": "3f9c…",                  ← phone id
  "plugin_configs": {
    "connection": {                             ← global
      "computer_id": "8d1e…", "computer_name": "desk", "route": "auto", "udp": false,
      "phones": [{"id", "name", "token", "ips", "active_ip"}], "selected_phone": "3f9c…"
    },
    "setup": {...}
  },
  "devices": {
    "3f9c…": {
      "plugin_configs": {                       ← per phone
        "camera_control": {...},
        "stream_output":  {...},
        "transforms":     {...},
        "monitoring":     {...},
        "presets":        {"presets": [{"name": ..., "camera": {...}, "stream": {...}, "transforms": {...}}]},
        "microphone":     {"enabled": false, "gain_db": 0}
      }
    }
  }
}
```

A plugin's `device_local` attribute marks whether its settings are per phone. The `plugins` key holds what `plugin_loader` keeps: `off` (built-in plugins switched off), `noticed` (ones the banner already named) and `added` (added plugins switched on, each with the digest of its files). `_upgrade_from_v2()` turns a v2 file into v3 by dropping the connection section, `devices` and `selected_device` (phones were keyed by name then) and keeping everything else. Anything older, or unparseable/malformed at the top level, is backed up (`.invalid-<timestamp>`) and replaced with defaults. A current config has each top-level section (`plugin_configs`, `devices`, `selected_device`) validated independently, so one malformed section resets to its default without discarding the rest.

### `models.py`
`PhoneState.from_dict(raw)` checks the shape of a `/v1/state` reply, with a `CameraCapabilities` per lens, and raises `PhoneStateError` on a wrong type or a missing field (a bool never passes for a number). The window checks every reply with it before applying any of it, so a malformed one leaves the panels as they were.

### `phone_client.py`
**PhoneControlClient** - authenticated HTTPS client for phone's `/v1/state` and `/v1/control` endpoints, through the phone's `PhoneAuth` (pinned certificate, bearer token on each request).
- `send(action=..., **params)` - queues commands, coalesces repeated actions to latest value (sent at the place of the latest send), sends in order via background thread. Camera switches always go individually; slider bursts stay ordered (no stale response overtakes newer ones). A request that doesn't get through is retried with backoff for up to `_RETRY_FOR_S` (15 s), unless a newer value for that action is waiting, the phone refused it (HTTP error) or the client closed.
- `resend_settings()` - sends the last value of each camera/output setting again, for a background stream that reconnected. `retarget(url)` points it at the stream's new route, queue and settings included.
- `get_state()` - fetch current camera state dict (lenses, ISO, shutter, WB, focus, AE comp, NR/edge mode, battery, etc.). Each state it reads is checked against the settings last sent (`drifted_settings()`), and one the phone doesn't show is sent again, once per value, so a value the phone fitted to the lens doesn't start a loop.

### `ip_utils.py`
Qt-free address helpers for pairing and routing.
- `PairingAddress(ip, interface, kind)` - one address the phone can try, `kind` being `"lan"` / `"tailscale"` / `"other"`.
- `get_pairing_addresses()` - enumerates real adapters through `ifaddr` (never a route probe, which follows a VPN's default route), drops loopback/link-local/IPv6 and container/VM-only adapters, and returns candidates ordered LAN → Tailscale → other.
- `classify_ip(ip)` / `is_virtual_interface(name)` / `looks_like_vpn_interface(name)` - the pieces the above is built from.
- `MAX_PAIRING_CANDIDATES = 8` - cap on what goes into the QR code.
- `rank_ip()` / `valid_ipv4()` - used on the *phone's* reported addresses when choosing which to probe.

### `pyav_vaapi.py`
A second PyAV with VA-API for AMD and Intel graphics cards on Linux, since PyAV's wheel leaves VA-API out. `activate()` runs in `main.py` before anything imports av: if Video settings picked one (`choice.json` under `~/.local/share/Telescope/pyav-vaapi/`), `probe()` checks it in a separate process (loads from its folder, PyAV 14 or newer, VA-API opens) and only then puts it first on `sys.path`; otherwise `problem` says why and the venv's own PyAV loads. `find_system()` / `link_system()` give the distro's av in a folder of its own, `build()` builds the venv's PyAV version from source against the system FFmpeg (no pip cache, so never against an FFmpeg since replaced; rebuilding the one this run imports from waits in `staged()` until the next instance owns the startup lock; promotion keeps the previous directory until the replacement is in place, restores it on failure and recovers a backup left by an interrupted promotion), `missing_tools()` and `install_command()` say what a build needs.

### `pinned_https.py`
HTTPS to a paired phone, trusting only the certificate fingerprint it gave at pairing. Qt-free.
- `PhoneAuth(token, pin)` - `headers()` for the bearer header, `open(req, timeout)` like `urlopen`. An `https://` URL needs a pin, and the certificate is checked right after the handshake, before any request byte goes out. No redirects, no proxies. Plain `http://` only works with no pin at all (tests' local servers), so a paired phone's token never goes out unencrypted.
- HTTPS responses offer `abort()`: shut down TCP to interrupt a blocked read before closing the buffered response, without changing OpenSSL state on the reader's thread. The microphone uses it for handover and stop.
- `fingerprint(der)`, `is_fingerprint(value)`, `pin_rejected(exc)` (the failure was the pin check: something answered, but not the paired phone).

### `session_client.py`
**PhoneSessionClient(base_url, auth)** - HTTPS client for the phone's session port (8766), where `SessionServer` answers whether or not a stream is running. Qt-free.
- `hello(timeout)` → `Hello(status, phone_id, phone_name, protocol, app_version, build)` - no token sent; which phone is on the other end and which app version. `status` is `HELLO_OK`, `HELLO_MISSING` (an app too old: one without `/v1/hello`, or one from before TLS, found by a plain `/v1/hello` with no token when the handshake fails) or `HELLO_NONE` (nothing there, or a certificate that isn't the pinned one).
- `read_capped(response)` - every reply is read through this, capped at `MAX_REPLY_BYTES` (256 KB), since whatever answers may not be the phone.
- `clean_name(raw)` - a phone's name as plain display text: no control characters, no `<` or `>` (Qt would render it as HTML), at most 64 characters. Every name from pairing, the phone or the config goes through it.
- `ping()` → `PingResult(status, streaming, busy, local_only, phone_id, phone_name)` - `status` is `paired` / `not_paired` (401) / `unreachable` (anything else, including a body that isn't Telescope's JSON).
- `start()` / `stop()` → `SessionResult(ok, error)`.
- `unpair()` - asks the phone to forget this computer (best effort).
- Owns `SESSION_PROTOCOL` (must equal the phone's `SessionServer.PROTOCOL_VERSION`; the release workflow checks), `PING_PORT = 8766`, `REQUEST_TIMEOUT`, `START_TIMEOUT`, `START_POLL_INTERVAL` (and `START_FAST_POLL_INTERVAL`, 0.1 s for the first `START_FAST_POLL_FOR` 2 s, since most phones are up within a second).

### `phones.py`
Qt-free model of paired phones and how to reach them; adb, the session client and discovery are injected, so it's tested without any of them.
- `Phone(id, name, token, ips, active_ip, cert_sha256)` with `to_dict()` / `from_dict()`; `phone.auth` is its `PhoneAuth`. A phone paired before TLS has no `cert_sha256` and resolves straight to `NOT_PAIRED` with `before_tls`, without contacting it.
- `Route(kind, host, serial)`, `Resolution(status, route, usb_note, streaming, busy, phone_version, before_tls)`; statuses `READY`, `UNREACHABLE`, `NOT_PAIRED`, `LOCAL_ONLY`, `USB_NEEDS_ATTENTION`, `PHONE_OUTDATED` / `DESKTOP_OUTDATED` (the phone speaks an older/newer session protocol, or has no `/v1/hello` at all; the route is kept so the phone can be updated over it); USB reasons `USB_NO_ADB`, `USB_NO_CABLE`, `USB_UNAUTHORIZED`, `USB_OTHER_PHONE`, `USB_APP_CLOSED` (`usb_note_text()` words them for the UI).
- `RouteResolver.resolve(phone, preference)` - USB first (each usable adb device, verified by `/v1/hello` id, then `/v1/ping`), then Wi-Fi probed in parallel over mDNS-discovered, last-good and stored addresses. Blocking.
- `UsbTunnels` - refcounted `adb forward tcp:0` per (serial, remote port).
- `STREAM_PORT = 8080`, `ROUTE_AUTO` / `ROUTE_USB` / `ROUTE_WIFI`.

### `version.py`
`VERSION`, `BUILD`, `CHANNEL` (`stable` / `nightly` / `dev`) and `COMMIT` of this build. Release builds read `telescope/_build.py`, which CI writes with `scripts/write_build_info.py`; a source checkout reads the repo's `VERSION` file and is `dev`. `display_version()` is what the UI shows; `release_asset_url(name)` links a file from this build's release (nightly for dev builds).

### `diagnostics.py`
The log and Copy diagnostics. `install(app_dir)` (from `main.py`) opens `events`, an `EventLog` handler, on `log_dir()/telescope.log` (`/tmp/telescope-<user>` or `%TEMP%\Telescope`), links `telescope.log` in the app folder to it where symlinks work, adds it to the root logger and hooks sys and thread exceptions. It takes Telescope's info and up, other libraries' warnings and up, crashes and `note()`s (the host notes each status line and banner). A repeat of the latest line becomes a "repeated N more times" line; notes drop a trailing seconds counter ("(12s)") and treat "…" as "..." first, so a ticking status counts as repeats. The file rotates at `MAX_BYTES` into `telescope.log.1`; without a file it keeps `REPORT_LINES` in memory. `sanitize()` strips URLs, IPs, tokens and the home path before a line is stored. `report(state, qt_platform)` builds the text: version, OS, desktop session, then each plugin's `diagnostics()` lines, then the last `REPORT_LINES` log lines (across a restart). The host's `diagnostics_report()` is what the Advanced dialog's button copies.

### `web.py`
`urlopen(url, timeout)` for Telescope's own downloads (updates, Get adb, Install VB-Cable, the camera driver's fallback download): the certificate is checked by the system's store through `truststore`, so a fresh Windows fetches a root it doesn't have yet instead of failing with "unable to get local issuer certificate". Without `truststore` it falls back to Python's default check. `certificate_failed(exc)` tells a certificate failure from being offline, so the messages don't blame the internet. Phone connections use `pinned_https.py` instead.

### `updates.py`
Qt-free update logic, everything injectable for tests. `fetch_manifest(channel)` reads the channel's `manifest.json` (stable: the latest release, nightly: the `nightly` tag); `None` when the channel has no release. `is_newer(manifest, build)` compares build numbers (never true for a dev build, or for the build in `.update-failed`); `was_rolled_back()` is that last case, so the dialog can say so, and `forget_rolled_back()` clears it for a retry. `platform_asset()` picks the zip or tarball. `self_update_blocker()` says why this copy can only link to the release (source checkout, dev build, folder not writable). `download(asset, dest, progress, cancelled)` streams to a `.part` file and checks size and SHA-256. `install(archive, build=)` extracts to a staging folder next to the app (refusing paths that escape it), writes the journal and has `update_guard` do the swap (a failure puts the old version back and raises `UpdateError`); the old version is kept until the new one confirms it started:
- Windows: the app is a PyInstaller folder build whose libraries sit in `lib-<build>` (`LIB_PREFIX`), a new folder per build. Moves the new build's lib folder in with one rename, then renames the running `TelescopeDesktop.exe` to `TelescopeDesktop.old.exe` and moves the new one in, then replaces other files whose hash changed; a locked file (UnityCapture held by OBS) is skipped and reported.
- Linux: replaces each top-level entry, keeping the old one in `.previous/`.
- Windows, unzipped (`is_unzipped_copy()`: the packaged app with no `unins*.exe` beside it): `install_with_setup()` runs the downloaded `TelescopeSetup.exe` silently (per-user, so no UAC; downloaded by the app, so no SmartScreen), finds the install through the setup's uninstall entry (`installed_location()`, keyed by `SETUP_APP_ID`), and relaunches that copy with `--after-update --moved-from <old folder>`. Before that it clears the installed folder's own update journal (else its first start would roll the fresh install back to that folder's older files), marks the build in the old folder's `.update-failed` (so if the installed copy doesn't start, reopening the old one doesn't offer the same build straight back), and, when a desktop shortcut starts the old exe (`shortcuts_to()`, a search of `.lnk` files for its path), passes `/MERGETASKS=desktopicon` so the setup makes a working one. That copy runs `remove_unzipped_copy()` once it has started fine: only entries that are unmistakably Telescope's (`_ours()`: its own file names, the updater's dot-folders, `lib-<digits>` holding `PyQt6`, and `platform-tools`/`unitycapture` only when they hold nothing but Telescope's files, since a zip unpacked into Downloads sits beside the user's own things), the exe last, then the folder if that left it empty and the dead desktop shortcuts. An old zip's bundled adb is first copied to where Get adb keeps it (`_keep_adb()`) unless one is there already. Retries while the old copy exits; it refuses the running copy's folder, an installed copy and a folder without `TelescopeDesktop.exe`. A copy unzipped into the setup's own folder (`default_install_dir()`) isn't treated as unzipped, since the setup would close it mid-update.
- Windows, installed: an update swaps `lib-<build>` like the zip and never runs the setup, so `note_installed_version()` writes this version into the setup's uninstall entry (`DisplayVersion`, `MajorVersion`, `MinorVersion`) at start, for Settings > Apps.
Returns `InstallResult(relaunch, skipped)`. `clean_up_after_update()` runs on every start once the app is up (never while the journal says an update is unconfirmed) and deletes the leftovers: the old or failed exe, the staging folder, `.previous/`, and every `lib-*` folder but the running one (only when it knows which that is).

### `discovery.py`
**LanDiscovery** - browses `_telescope._tcp` with `zeroconf` and maps the TXT `id` to current IPv4 addresses. `lookup(phone_id)` never blocks; without zeroconf or multicast it returns nothing and stored addresses are used.

### `pairing.py`
**PairingServer** - the Qt-free one-shot pairing handshake: bind a port, mint a nonce and bearer token, wait for the phone's `POST /pair/{nonce}` echoing the token back.
- `PairingServer(on_paired, computer_id, computer_name)`; `start()` → `PairingOffer(payload, port, nonce, token, candidates, usb_payload)`. `candidates` may be empty (no network); `usb_payload` advertises only `127.0.0.1`, reached through `adb reverse`.
- `payload` is the version-3 JSON (`version`, `port`, `candidates[]`, `nonce`, `token`, `computer_id`, `computer_name`); `PAIRING_PROTOCOL_VERSION` moves in lockstep with the app's.
- `PairingResult(name, ips, token, source_ip, phone_id)` - a POST without `phone_id` is rejected. `source_ip` is where the POST came from, i.e. a phone address proven reachable from here, and becomes the phone's first `active_ip`.
- One phone per offer: after a phone pairs, a different `phone_id` gets `409`. Threaded, with a 10 s read timeout, so a stalled connection can't hold up the phone that's pairing. At most 32 connections at once and 4 per address, each cut off 15 s after it opens, so a peer trickling bytes can't pile up threads.
- `PAIRING_PORT = 8765`, falling back to a random free port if it's taken. A port still in TIME_WAIT from the last pairing is reused.

### `widgets/common.py`
Reusable Qt widgets and helpers used across multiple panels:

These are also what `widgets/collapse.py` looks for to make cards and sections foldable, so build cards with them (and with the `card_title`, `section_head` and `section_title` object names they set).
- `action_button()`, `button_row()`, `dialog_layout()`, `dialog_header()`, `dialog_buttons()`, `wrapped_note()` / `WrapLabel` - dialog kit. `WrapLabel` measures its text on every resize and text change and pins its minimum height to that, so wrapped text is never clipped and never keeps stale space.
- `icon_button(icon, name, tooltip)` - a small square button with only a line icon; `name` is what a screen reader says.
- `host_window(host)` - the main window to parent a plugin's own window on, so it stays above it (None for a test's stand-in host).
- `reading_order(root)` / `tab_in_reading_order(root, forward)` - Tab follows the layouts (top to bottom, left to right), not the order widgets were made, and stops on every option of a pick-one group. The main window's `focusNextPrevChild` calls it; dialogs get it from `theme`.

- `elided()`, which every widget that draws its own text cuts it with, so `scripts/text_fit.py` can list what got cut (`tests/test_text_fit.py`). Text drawn past its box without it shows up there too, since the script watches every `drawText()`.

- `run_off_ui_thread(fn, *args)` - run a blocking call (adb) on a worker thread while the window keeps repainting; used by every GUI-thread adb call.
- `stretch_slider(slider, minimum)` - give a slider a minimum width and an Expanding policy so it fills its column instead of being pinned to a fixed track width.
- `NoScrollComboBox`, `NoScrollSlider`, `NoScrollSpinBox`, `NoScrollDoubleSpinBox` - scroll-wheel suppressed variants. The combo also keeps its popup on screen: `fit_on_screen(rect, avail, margin)` slides it back in and only shrinks it when it's taller than the screen.

Dragging the handle (only `SliderMove` actions, through `actionTriggered`, so listeners only ever see the snapped value) sticks to a snap within `SNAP_PX` (5 design px), or a third of the gap to its nearest neighbour if that's less; keys and groove clicks never snap. `set_default(value)` makes a double-click reset to it and adds "Double-click to reset" to the tooltip (`setToolTip` keeps the caller's text first). `PanSliderRow` snaps and resets to 0.

### `widgets/collapse.py`
Cards and sections that fold when their title is clicked. Nothing in it names a card: it finds them by what `common.py`'s helpers build (`QFrame#card` with a `QLabel#card_title` header row, and `QWidget#section_head` rows), so a plugin or a later change that builds a card the usual way is foldable without touching this file.
- `Collapsing(on_change)` - the folded keys and the folding. The window owns one (`TelescopeWindow._collapse`), `install(panel, scope)` runs on each panel right after `create_panel()` (scope is the plugin's name), `load(keys)` takes the saved list and `keys()` gives it back for saving. Keys are `scope/Card title` and `scope/Card title/Section title` (`#2` after the first one of a repeated title).
- `install()` takes every row under a card's header out of the card's layout and puts it in a `card_body` container, with a nested one under each section heading. A fold hides that container, never the rows, so a plugin's own `setVisible()` calls and a card hidden on purpose (`dim_until_paired(phone_only=True)`, onboarding) are left alone. Stretch factors and alignment move with the rows. A card without the standard header is skipped, and so is one that was done already.
- A click on a card's icon or title (anywhere on a section's row, the rule too) folds it. `_Toggle` is the event filter doing that and setting the title's `hot` property while the pointer is on it, which `theme.py` styles (a card title goes half as bright, a section title takes the main title colour). It sits on the labels themselves, so it still works while `dim_until_paired` has the card disabled.
- `_FoldButton` wraps each title label in a native checkable button. Tab reaches it, Space and Enter toggle it, and checked means expanded. Its name and state reach the accessibility tree before its rows. Folding a container with a focused control moves focus to its title.
- The set of folded keys is saved by `save_now()` as the top-level `collapsed` list in the settings file (checked by `config._validate_sections`) and read back in `_apply_config()`. Keys of cards that aren't there are kept, so switching a plugin off and on again keeps its folds. Rows added to a card's layout after `install()` ran land outside the fold.

### `widgets/settings_window.py` and `widgets/plugins_panel.py`
**SettingsWindow(sections, parent)** - the tabs as a `QListWidget` (`settings_nav` in the theme) beside a stack with one scrolling page per tab. `ordered_tabs()` decides which tabs show and in what order. A page tells its sections' `on_show` when it comes on screen (a raising one is logged and the rest carry on). `show_tab(id)`, `current_tab()`, `tabs()` and `tab_names()` are what the window and tests use. It sizes itself to 940×680, kept inside the screen.

**`fuzzy.py`** (no Qt) - the one matcher both searches use. `Doc(**fields)` holds named fields of text and `Doc.score(query, weights)` says how well a query fits: every word has to match something (filler like "how do i", "not working" or "setting" doesn't count and a one or two letter word is let off), by whole word, word start, a word inside a long one (5 letters or more, so "crop" isn't found in "microphone"), a typo in a word of 4 letters or more (not in its first letter), initials ("ha") or letters in order for a name ("hwaccel"). Fields count by weight (name over keywords over card, tab, the small print and tooltips), and an exact or leading name match adds to it. `partial=True` lets unmatched words only pull the score down.

**`widgets/settings_search.py`** - `collect(tabs)` turns what the tabs show into `Entry`s (hidden rows left out, a card or tab ranking just under the setting in it) and `search_ex(entries, query)` ranks them, falling back to entries that match some of the words (the window says so). The shortcut editor's control list uses `fuzzy` too (`BindingEditor._matches`), keeping its grouped order; group titles in it are items marked `accessibleDescription == "heading"`, which `ComboItemDelegate` paints as a tinted band.

**PluginsPanel(builtins, running, problems, restart, is_streaming, download)** - the **Plugins** tab: cards **Built in** (a switch each, **Turn all back on** in its header), **Optional** (the `optional` built-in ones, off until switched on; one that `needs_vision` asks before downloading the vision pack, shows the download's progress and why it failed, and **Remove download** in the header deletes the pack while none of them is on), **Added** (a switch and a remove icon each, with the author, version and any problem under it; **Install** in its header takes a `.zip` from a file picker, or one dropped on the tab) and **Always on** (the `required` ones, no switch). Switching one off asks first with its `when_off`; switching an added one on warns that it can do anything Telescope can. A row waiting on a restart gets a **Restart now** button next to its note (it warns while streaming). The strip above the list with the same button only shows when the switches differ from what's running and no row has one, like an added plugin that didn't start. **How plugins work** (docs/plugins.md on GitHub) and **Open plugins folder** sit under the cards. It rebuilds its list each time the tab comes on screen and keeps the scroll position. Confirmations go through the module's `_ask`, which tests replace.

### `widgets/vision_download.py`
**VisionDownload** - the vision pack's download, one for the app (`shared()`), so the Plugins tab and the cards that need the pack share it and a download carries on when the window closes. `start(switch_on)` downloads on a thread (`progress`, `finished(error)`) and then switches on the optional plugin that waited for it; `failed_for` and `error` remember why it didn't work for that plugin's row. `remove()` deletes the pack.

### `widgets/level_meter.py`
**LevelMeter** - DAW-style meter fed `set_level(peak, rms)` about 30 times a second: a solid RMS bar over a fainter peak bar, coloured by zone (green, yellow from -18 dB, red from -6 dB), on a scale from -60 dB that gives the top 20 dB half the width. ## `telescope/platform/`

### `platform/__init__.py`
Cross-platform constants and helpers: `IS_LINUX`, `IS_WINDOWS`, `adb_available()`, `adb_device_states()` (serial + state, including `unauthorized`), `adb_devices()`, `adb_forward(port)`, `adb_forward_auto(remote_port, serial)` (adb picks the local port), `adb_unforward(port)`, `adb_reverse(port)`, `adb_unreverse(port)`, `adb_broadcast_pair(payload)`, `adb_install(serial, apk, timeout)` → `(ok, detail)` with plain-language failures (different signing key, downgrade), `adb_exe()` (the app folder's `platform-tools`, which copies from before adb was downloaded still have, then the downloaded one on Windows, then PATH), `bundled_apk_path()`, `_run(cmd)`. `_run()` returns an error tuple instead of raising when adb isn't installed, and on Windows runs with `NO_WINDOW` (`CREATE_NO_WINDOW`) so the packaged app doesn't flash a console for every adb call. ### `platform/adb_download.py`
Windows: adb isn't bundled (the Android SDK License doesn't allow passing it on), so `download_adb(urlopen, dest, progress)` fetches it when asked. It reads Google's SDK index (`INDEX_URL`, what Android Studio's SDK manager reads), takes the Windows platform-tools archive with `find_archive()` (only a `.zip` next to the index on dl.google.com), downloads it with a cap at the listed size, checks the size and SHA-1, and keeps only `NEEDED` (adb.exe, AdbWinApi.dll, AdbWinUsbApi.dll, libwinpthread-1.dll, Google's NOTICE.txt and source.properties). It unpacks into a `.adb-*` folder beside `downloaded_dir()` (`%LOCALAPPDATA%\Telescope\platform-tools`) and swaps the whole folder in, so `adb_exe()` never sees half of one; a failure keeps what was there. Returns `(True, revision)` or `(False, why)`. The installer's uninstall removes the folder.

### `platform/autostart.py`
`launch_command()` (the exe, else `start.sh`, else `python main.py`, plus `--minimized`), `enable(command)`, `disable()`, `is_enabled()`. Linux writes `$XDG_CONFIG_HOME/autostart/telescope.desktop` (Exec quoted per the desktop entry spec); Windows sets `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\Telescope`. Paths and `winreg` are injectable for tests.
`update_menu_entry(save_icon)` keeps `$XDG_DATA_HOME/applications/telescope.desktop` and its 256px icon (drawn by `create_app_icon`) pointing at this copy; `main.py` calls it on every Linux start except from a source checkout (`is_dev_checkout()`, channel `dev`; a release unpacked inside a git-tracked folder still counts as a release), and it only writes when the entry changed. `APP_ID` is also the Qt desktop file name, so docks match the window to the entry.
`ensure_portal_entry(app_id)` writes a hidden (`NoDisplay`) menu entry when there's none under that id, since the desktop portal only lets an app register under an id that has one; the global shortcuts portal calls it before its first bind, so a dev profile (`telescope-dev`) or a source checkout can use global shortcuts too.

### `platform/hotkeys.py`, `hotkeys_windows.py`, `hotkeys_portal.py`
Global shortcuts. `HotkeyBackend` takes `Hotkey(id, keys, description)`s in `apply()`, emits `pressed(id)` / `released(id)` / `changed` on the GUI thread, and reports `status(id)` as `HotkeyStatus(working, text)`. `create_backend(app_id)` picks one, or `None`.
- Windows: `RegisterHotKey` with no window and `MOD_NOREPEAT`; a native event filter catches `WM_HOTKEY` in Qt's own loop. Windows never reports the key coming up, so a 30 ms timer watches it with `GetAsyncKeyState` while held. `to_windows(keys, VkKeyScanW)` maps Qt keys to virtual-key codes, asking the layout for punctuation. A key another app holds fails to register and its `status()` reports that, with `reaches_app` False (Windows hands that key to the other app even while Telescope is in front). A press of a key with Alt and no Win taps Ctrl (up then down when Ctrl is held), or the app in front would see a lone Alt and show its menu key tips.
- Linux: the GlobalShortcuts portal over jeepney, on two threads (commands, and signals). Nothing touches D-Bus until the first global binding. Then `Register(app_id)` first of all (the portal needs it for an app outside Flatpak), the interface version, `CreateSession`, `BindShortcuts` with each key as a `preferred_trigger` (`to_trigger()`, the shortcuts spec's keysym names). Requests answer through a `Response` signal on a predictable path, matched before the call goes out. The desktop confirms and may pick other keys; their `trigger_description` is the status text, and `ShortcutsChanged` updates it. A session binds only once, so new bindings close it and make another. `configure()` calls `ConfigureShortcuts` (version 2). Plasma's kglobalaccel keeps every shortcut a session ever bound and lists the ones no session has any more, greyed out, in System Settings; after a confirmed bind, after the last one is removed, and once at start when nothing is global (straight to kglobalaccel, no portal), `cleanUp()` on the app's component (`getComponent(app_id)`) drops those. Elsewhere that call just fails quietly.

### `platform/linux.py`
v4l2loopback helpers. Root work goes through `_privileged(steps)`: one `pkexec sh -c`, else `sudo -n`, else a `PrivResult(False, NO_PROMPT, command)` whose `command` is the same steps as pasteable `sudo` lines. `PrivResult` is an `(ok, message)` tuple with `.command`; `result_parts()` gives `(ok, message, command or "")` for a status line and its command box. `v4l2_setup(persist)` loads the module and, with persist, writes the boot config in the same prompt (skipped when another file already configures v4l2loopback). `v4l2_module_installed()`, `v4l2_load()`, `v4l2_unload()`, `v4l2_module_loaded()`, `v4l2_devices_ready()`, and the load-at-boot trio `v4l2_persist_status/enable/disable()`. Device constants: `V4L2_PHONE_DEV = /dev/video11`, `V4L2_OBS_DEV = /dev/video10`.

`limit_malloc_arenas()` (called in `main.py` before Qt starts) caps glibc's per-thread memory pools at 4, and `release_freed_memory()` (`malloc_trim`, when a stream stops) hands freed frame memory back. Both do nothing on a libc that isn't glibc.

`v4l2_add_devices(labels)` adds cameras to the running module with `v4l2loopback-ctl add` (one prompt), for streaming several at once; they last until the module reloads.

### `platform/windows.py`
`register_unitycapture(devices)` with more than one also registers the extra cameras (`/i:UnityCaptureDevices=N`). UnityCapture helpers: `uc_registered_name()` (the name apps list it under, read from the filter's CLSID key; `None` if not registered), `uc_in_app_folder()` (registered by an older version from the writable app folder), `uc_is_registered()`, `unitycapture_dir()`, `protected_unitycapture_dir()` (`Program Files\Telescope\UnityCapture`, from the known-folder API rather than `%ProgramFiles%`), `download_unitycapture()`, `register_unitycapture()` (one elevated PowerShell finds Program Files itself, refuses a `Telescope` folder there that has a link anywhere in it or that anyone but admins could change (it never repairs one), copies both DLLs in, checks the finished tree again and their SHA-256, and registers those copies with System32's `regsvr32` as `UC_NAME` = "Telescope" via `/i:UnityCaptureName=`). `running_from_archive(app_dir, temp_dir)` spots a zip tool's temp folder (Explorer's `Temp1_*.zip`, 7-Zip's `7zO*`, WinRAR's `Rar$EX*`); `warn_running_from_archive()` is the message box. `use_installed_app_id(app_dir)` gives the installed copy (one with an `unins*.exe`) the AppUserModelID its Start menu entry carries (`APP_USER_MODEL_ID`), so notifications show as Telescope; other copies keep the exe's own, since Windows can drop toasts from an id no shortcut has. `vcam.open_camera()` opens the camera by that name and falls back to any free UnityCapture device for older registrations.

## `telescope/plugins/`

### `plugins/__init__.py`
`builtin_plugins()` makes one of each built-in plugin, in registration order (the order their cards and settings sections come in, after each section's `order`). ### `plugins/connection.py`
**ConnectionPlugin** - paired phones, how they're reached, and pairing.
- Card rows, in one block: the status ("Streaming over USB") with the route under it, **Connect via** (Auto / USB / Wi-Fi segments driving a hidden Automatic / USB only / Wi-Fi only combo), **UDP on Wi-Fi**, a note with the fix when something's wrong or why a plugged-in cable isn't used, and **Switch to USB** when the phone is plugged in mid-stream over Wi-Fi but moving the stream over without a gap (`host.hand_over_stream`, which opens USB next to Wi-Fi in `StreamWorker.hand_over` and moves once it has kept frames coming for 2 s) didn't work. USB that just failed a stream sits out 10 s so it can't flap. Mic-only streams move their control and audio connections without needing a video reader. `bus.stream_transport_changed` asks Connection to re-evaluate UDP after a bitrate or preset change; changing the UDP switch does the same. The card header's action is **Add phone**. While streaming, the status reads Connecting… until `bus.stream_connected`, and Reconnecting… from `bus.stream_lost` until it's back.
- `recovery_probe()` → a blocking job returning the current `Resolution`; `adopt_stream_route(route)` → moves the stream's route (and its USB forward, always opened fresh since adb drops forwards with the cable) and returns the new video URL.
- `create_header_widget()` returns the phone picker and the Your phones button.
- Stream sources (`bus.stream_sources_changed`) are listed in the picker after the phones, below a separator. Picking one makes its id `selected_device` (its settings are saved under it), hides the route rows, and emits `bus.source_selected`; `set_config` restores it. `ensure_virtual_camera(interactive)` is the virtual camera check from `get_stream_info()`, which the host also runs before a source starts.
- `status_line()`, `problem_text()`, `route_text()` - module-level text for each state, shared by the card and Start failures.
- `_check_status()` every 3 s while idle, and only while the window is on screen (`bus.window_shown`), an app reads the camera (`bus.camera_watched`) or Automatic streaming waits for the phone (`bus.phone_wanted`; once it has started for this arrival, only every `_HELD_POLL_S` (60 s), since only the phone leaving matters then), resolves the selected phone in a background thread (`_spawn_resolve`); results carry a check id and are dropped when stale. A Wi-Fi address that answers is remembered as the phone's `active_ip`.
- `get_stream_info()` → `(url, token, ok)` - makes sure the virtual camera is loaded (Linux: one consent prompt with **Also switch it on at every startup**, then `v4l2_setup`), resolves the route, and for USB holds a `UsbTunnels` forward to 8080 until that phone's stream ends (`release_stream(pid)`, or `on_stream_stop()` once the host no longer streams from it). Routes are held per phone (`_holds`), so several phones can stream at once; the per-phone calls take a `pid`, defaulting to the selected phone. Picking a phone first asks `host.pick_source(pid)`, which handles a phone that already streams (its tile gets the panels) or, with several streaming, replaces the one shown; `show_selected(pid)` is how the host shows a pick it made itself, without a profile switch. Each failure becomes a `"start"` banner with its fix (`_fix_actions`).
- `session_target()` → `SessionTarget(token, route)` - read on the GUI thread and handed to worker threads.
- `session_channel(target)` - context manager yielding a `PhoneSessionClient` on the target's route (USB through a refcounted forward), or `None`.
- `ensure_phone_streaming(on_progress=None, target=None)` → `(ok, reason)` - starts the phone's camera if needed and polls `/v1/ping` until it streams (12 s budget). **Blocking - background thread only.**
- `stop_phone_streaming(target=None)` - best-effort `POST /v1/session {"action":"stop"}`. **Blocking.**
- `AddPhoneDialog` - QR for Wi-Fi when there's a network; polls `adb devices` every 2 s and re-sends the USB offer (`adb reverse` + broadcast) every 4 s to each usable device; says so when a device is waiting on the USB debugging prompt.
- `PhonesDialog` - a Phones card with Add phone in its header and a strip per phone or saved browser (rename and remove buttons, browsers only remove), plus a This computer card with the name phones see. Remove calls `forget_phone()`: unpairs on the phone when reachable (`/v1/unpair`) and deletes the phone's stored settings.
- `PHONE_OUTDATED` with the phone on a cable, a bundled APK and adb: **Update over USB** (`adb_install` in a thread). `DESKTOP_OUTDATED`: **Update this app**, which emits `bus.update_requested`.
- Re-pairing the phone that's streaming reconnects the stream with the new token.
- A phone pairing with a new id but the name of a listed phone that no longer answers as itself (`_earlier_install`: its last check, or a fresh one, says not paired, unreachable or USB needs attention) asks "Is this <name> again?"; yes moves the old entry's settings and slot to the new id (`host.move_device_settings`) and puts the new phone in its place (`_take_over`).
- Picking another phone or source in the picker by hand mid-stream stops the stream and starts the picked one (`_select(switch=True)`); `select()` from code only stops it.
- Changing **Connect via** mid-stream first resolves the phone with the new choice (`_spawn_route_probe`, `_pending_route`); only if it's ready does the choice stick and the stream reconnect. Otherwise the stream and the old choice stay, with a `"route"` banner and Try again.
- Emits `bus.phones_changed` on every list change and opens Add phone on `bus.add_phone_requested`. The icon-only **?** in the header, before Add phone, emits `bus.setup_guide_requested`.
- Config keys: `computer_id`, `computer_name`, `route`, `udp` (UDP on Wi-Fi, off unless saved as `true`), `phones`, `selected_phone`.

### `plugins/browser_camera.py`
**BrowserCameraPlugin** - the Browser camera card (`panel_region = "right"`, shown while Browser camera or a browser is picked) and its `StreamSource`s. The picker entry (`SOURCE_ID = "browser"`) never streams itself: its `redirect()` gives a connected browser that doesn't stream, and without one `prepare()` waits for one (`waiting()`): a "Waiting for a browser" banner when nothing else streams, a Waiting tile next to other streams, either cancelled with `cancel_waiting()`. Each connected browser is a `_BrowserSource` (`browser:<id>`, named by its device once it says hello) offered with `add_stream_source` and taken back with `remove_stream_source` once it has left and doesn't stream. A browser that connects starts streaming by itself (`stream_source`), once per connection, one at a time; `_room` (cameras left) decides whether a new browser gets a feed. Picking Browser camera or a browser starts the `BrowserServer`; it stops once neither is picked, nothing waits for a browser and no browser streams. Card: the shown browser's status (its device and `sending_text(codec, sent)`, "H.264, 1280×720 at 30 fps"; a warning with a tooltip when the page reports the device's processor holding it back, the tooltip alone for `bandwidth`; the error when its offer couldn't be answered) and its mic problem, each connected browser and the camera it goes to, the QR code and link for the picked address (a combo when there are several), Copy, Resolution (480p, 720p, 1080p) and Frame rate (15, 24, 30), sent to every page; a frame rate change also goes to every browser's stream (`update_stream_output(source_id=)`). **New link** in the header: the old code stops, and every browser on it is cut off with its stream ended (no reconnect wait, no other browser started in its place). Two connected browsers with the same device name are told apart as "Chrome on Linux" and "Chrome on Linux (2)" (remembered by the plain name). Browser sources set `remember_changes_only`, so the host only keeps their settings where they differ from the defaults. `known` (id: name, last seen) lists them; `remembered()` is the ones with settings, sent as `bus.remembered_sources` for the phones list, whose Remove comes back as `bus.forget_source_requested`; ones not seen for `REMEMBER_DAYS` (60) or without settings are dropped at start. Without `cryptography` or aiortc (`browser_rtc.available()`) the card says so and Start shows a banner. `waiting_hint(stats, connected, now)` (pure) is a warn note on the card while no browser is connected: nothing has reached the computer after `HINT_AFTER_S` (30 s) points at the network and firewall, a failed handshake with no page load at the certificate. `diagnostics()` adds the port and the stats counts. While it's picked, `bus.stream_behind` shows its own "Can't keep up" banner (key `behind`) pointing at Resolution and Frame rate. Config keys (global): `size`, `fps`, `address`, `known`.

### `plugins/camera_control.py`
**CameraControlPlugin** - lens selection, exposure, white balance, focus, OIS, and image tuning. `panel_region = "right"`.
- UI: `LensPanel` ("Full manual control" in the header when the lens has it, the details on hover), then sections: Light (exposure auto/manual, ISO, shutter, brightness, white balance auto/manual, Kelvin, tint), Focus (Auto / Tap a point / Manual, distance), Image (stabilization, low light, black-level lock and torch as switch tiles; noise reduction and sharpening as dropdown tiles). Brightness snaps and resets to 0; Tint resets to 0 and Temperature to 5500 K on a double-click, without snap points.
- `derive_camera_control_view(state)` - pure function mapping a raw phone-state dict to a `CameraControlView` dataclass, independently testable without a `QApplication`.
- `on_stream_start`: stores ctrl, sets "Loading lenses..." placeholder, re-pushes desktop-restored state to phone (phone keeps boot defaults until user touches a control).

- Point focus: `bus.focus_point(x, y)` sends `focus_point` when the lens reports `supportsFocusPoint`; the Point button picks the centre of the preview. Point isn't saved: the next stream starts on Auto.
- Config keys: `exp_manual`, `iso`, `shutter_ns`, `ois`, `focus_manual`, `focus_diopters`, `wb_manual`, `wb_kelvin`, `wb_tint`, `ae_comp`, `nr_mode`, `edge_mode`, `bll`, `lens` (the lens id; only a preset switches to it).
- `apply_preset(cfg)`: `set_config`, then while streaming switches to the saved lens (if this phone has it and it isn't live) and resends everything through `_push_settings_to_phone()`.

### `plugins/cinema.py`
**CinemaPlugin** - focus peaking, zebras, false colour and a scope, all on the preview through a `CinemaLayer` (`host.add_preview_layer`, only while a tool is on). `optional`, `panel_region = "right"` after Camera, not in presets.
- UI: three switches and a Scope dropdown on the card; peaking colour and sensitivity, Zebras from (70 to 100%) and scope size in a Video settings section. All of it is one frozen `Look`, swapped whole.

### `plugins/desk.py`
**DeskPlugin** - Desk and document mode: four corners of a sheet picked on the preview (`host.pick_on_preview(..., "quad")`), straightened with a perspective warp that reaches the output. `optional`, `in_presets`, `device_local` (the corners belong to where that phone is), `panel_region = "left"` after Auto framing.
- UI: an on switch in the header (on without corners starts the marking), **Mark the sheet** (Done and Cancel while marking, which `finish_pick`/`cancel_pick`), a Writing row (Off, Contrast, Black and white) and a status line; **Keep the sheet's shape** in a Video settings section.
- The corners are kept in the whole picture (`Pick.full`) and mapped through the current view (`view_changed`) each time it changes, so zoom, flip and rotation don't undo them; the status line warns when a corner ends up off the frame as shown (`_off_picture()`). `Warp.on_preview` is the warp in 0..1 coordinates, which `process_frame` hands to `host.set_preview_warp` whenever it changes (None while off or marking), so clicks on the preview land where they mean. `process_frame` passes the frame through while its own pick runs, so the corners go onto the real picture.
- `Warp.get()` caches the matrix and target rectangle per corners, view, size and shape; `order_corners()` sorts them from the top left in the frame as shown and the sheet is cut `_INSET` inside them, so a corner a pixel off brings no desk along; `target_rect()` fits the sheet's size (the average of opposite edges) into the frame. `straighten()` warps only the sheet's rectangle and pads it with `copyMakeBorder`; `whiten()` divides out the paper's light worked out at an eighth of the size, `black_and_white()` is an adaptive mean threshold. About 4 to 5 ms a 1080p frame. `frame_step()` freezes settings and a warp for a stream behind the panels.
- Config keys: `on`, `corners`, `cleanup`, `keep_shape`. `tests/test_desk.py`.

### `plugins/chroma_key.py`
**ChromaKeyPlugin** - a green or blue screen (or a colour picked on the preview with `host.pick_on_preview(..., "point")`) swapped for a colour or a picture, with spill removal. `optional`, `in_presets`, `panel_region = "right"` after Background. No vision download.
- UI: an on switch in the header, Screen (Green, Blue, Picked with a swatch), Tolerance, Edges and Spill sliders, Behind you (Colour with a `QColorDialog`, or Picture like Background's) and a status line.
- `key_tables()` turns the key colour and the sliders into three 65536-entry tables indexed by `Cr << 8 | Cb`: alpha (by the distance from the key's chroma, with a ramp for the edge) and the colour with the spill taken off (the part along the key's chroma direction, only for hues within about 60 degrees of it). They're rebuilt when a setting changes, never per frame. `matte()` looks colour up at half size (the phone sends chroma at half resolution anyway), scales alpha and colour back up and keeps full-size luma; `compose()` is the same two multiplies and an add as Background's. About 6 ms a 1080p frame.
- Keying waits while its own pick runs, so the screen shows on the preview. The pick samples the median of a small square of `Pick.picture` at `Pick.in_picture` (what the preview showed, after Desk mode's warp too; the last frame before keying without one) and refuses a colour with hardly any colour in it (`keyable()`). `frame_step()` freezes the settings for a stream behind the panels.
- Config keys: `on`, `screen`, `picked`, `tolerance`, `softness`, `spill`, `background`, `colour`, `picture`. `tests/test_chroma_key.py`.

### `plugins/qr_reader.py`
**QrReaderPlugin** - QR codes held up to the camera go to the clipboard: a Wi-Fi code's password (`parse_wifi()`, with its backslash escapes) or the network's name without one, else the text as it is. `optional`, `panel_region = "left"`, not in presets.
- UI: an on switch in the header, a status line with **Copy** once a code was read, and **Notify me when a code is read**.
- `process_frame` only hands a copy (at most 1280 wide) to a `qr-reader` thread every `_EVERY_S` while none is running; `read_code()` tries `QRCodeDetectorAruco` and `QRCodeDetector` on it and on a half-size copy, since each misses codes the other reads and big ones close up read better small. The result comes back to the UI thread; the same text isn't copied again within `_AGAIN_S` of last seeing it.
- `_check()` reads the clipboard back `_CHECK_MS` after a copy: Wayland ignores one from a window in the background, and then the card says to click **Copy** (a click gives the window focus, so that one goes through). A `CodeLayer` outlines the code on the preview for `_OUTLINE_S`.
- Config keys: `on`, `notify`. `tests/test_qr_reader.py`.

### `plugins/background.py`
**BackgroundPlugin** - blurs the background or puts a picture behind the person. `optional` and `needs_vision`, so it's off until switched on in Plugins, which downloads the vision pack first. `panel_region = "right"`, after the Camera card; one setting for the whole app (`device_local` is False, so Presets leave it alone).
- UI: Off / Blur / Picture segments, a Blur strength slider (Blur only), **Choose…** and the picture's name (Picture only), an Edges slider, and a `VisionStatus` line (a missing picture comes first).
- `process_frame` asks `host.person_mask(frame)` and leaves the frame alone until there is one. `blurred(frame, strength, mask)` blurs at an eighth of the size with the person left out (a masked blur divided by the blurred mask), so they don't smear into a halo; `soften(mask, edges)` feathers the edge at a quarter size; `compose(frame, mask, background)` is two uint8 multiplies and an add (float blending was the slow part on Windows). `cover()` (from `pictures.py`) scales the picture to fill the frame once per size; `read_picture()` reads it as bytes, since `cv2.imread` fails on non-ASCII paths on Windows. Settings are swapped as one `_Settings` object, which `frame_step()` freezes for a stream behind the panels (Off returns None).
- `scripts/smoke_check.py` times a 1080p blur without the model. Config keys: `mode`, `blur`, `edges`, `picture`.

### `plugins/stream_output.py`
**StreamOutputPlugin** - capture resolution, frame rate, and encoding settings.
- UI: aspect-ratio and resolution combos from the current lens's `supportedSizes` (dynamic, not fixed) - sends a live `resolution` control instead of a post-decode resize. FPS dropdown (15, 24, 25, 30, 48, 60) drives both phone capture and virtual-camera playback; choices above the current camera's `maxFps` are grayed out and the fastest one below runs, while `get_config()` keeps the one picked (an older saved rate snaps to the nearest choice). Format (MJPEG / H.264; H.264 enabled once the phone lists `h264` in `codecs` and PyAV is installed), then JPEG quality (1-100%; the High/Balanced/Low wording is in its tooltip) or, in H.264, Bitrate (Auto, 1-100 Mbps, or all the way right Dynamic; sent as `bitrate` in bits/s, `-1` for Dynamic). A double-click resets quality to 85 and bitrate to Auto. A phone whose state lacks `dynamic_bitrate` runs Dynamic as Auto, and the slider's tooltip says so.
- `bus.stream_behind(id, True)` for the shown stream shows a "Can't keep up" warn banner (key `behind`): **Switch to Light** on Heavy when Light is offered, **Switch to Dynamic** on Light unless the phone can't do it, and on Dynamic just a lower resolution or FPS; `False` clears it. Silent while another source is picked (`bus.source_selected`), which says what helps itself.
- Switching format calls `host.reconnect_stream()`: the route decides the phone's codec, and Connection's `_video_path()` reads `format` through `host.plugin_config()`. A `codec_error` in phone state while on H.264 switches back to MJPEG with a warn banner, except with `codec_unsupported` (H.264 can't do this size here): then it stops the stream (deferred, so every plugin sees the state first) and shows a banner (key `encoder`) to lower the resolution or FPS, with **Switch to Heavy** (sets MJPEG and starts again).
- Keeps the last resolution the device used, so saves made while idle or during a device switch don't drop it. After a stop the lens's sizes stay up (cleared only on a device switch): a size picked then, or by a preset, is saved and becomes the pending one. `opening()` gives the host `{width, height, fps}` for the start request (`app._start()` reads it on the GUI thread and passes it through `conn.ensure_phone_streaming(opening=...)` to `PhoneSessionClient.start()`), so the phone opens at that size rather than one that just failed.
- `_apply_camera()` rebuilds resolution combo on lens change, carries current selection forward (reuses existing capture size) instead of resetting to largest; reflects live stream size on reconnect if it differs.
- `get_stream_params()` → `(width, height, fps)` - width/height are always `None` (resolution is phone-controlled, not desktop-resized); called by `app.py._start()` to construct `StreamWorker`.
- `on_stream_start`: stores ctrl, schedules `_push_initial_settings` (1500ms delay) to sync quality/fps after connect.
- `_on_resolution()` sends `resolution` control and emits `bus.resolution_change_requested` (used by `app.py` for footer readout). `_on_fps_picked()` / `_apply_fps()` send `fps_target` and call `host.update_stream_output()` for virtual-camera hot-swap (no stream restart).
- Config keys: `resolution`, `fps`, `jpeg_quality`, `format`, `bitrate_mbps` (`-1` is Dynamic, which an older desktop reads as Auto).
- `apply_preset(cfg)`: `set_config`, then while streaming sends fps and quality and, if the current lens has the saved size, the resolution.

### `plugins/preview.py`
**PreviewPlugin** - the centre video stage and its pop-out. `panel_region = "center"`.
- UI: letterboxed frame and a toolbar with Hide/Show toggle, an icon-only camera toggle (`host.set_camera_on()`; a crossed-out camera with an accent border while off, greyed out with the reason as its tooltip while it can't go off), an icon-only lens outline toggle (fixed width, so the stage stays narrow; keeps the lens boxes on; enabled only while the camera has longer lenses) and Pop out.
- Active by default - it's the centre of the window, not an opt-in card. The toggle remains as an escape hatch for anyone who'd rather not spend the decode.
- `process_frame(frame)` - runs on a stream decoder thread; scales the frame to fit the view it's going to (the card's or pop-out's size as of the last frame shown, or `_CARD_MAX_W` wide before that), emits cross-thread Qt signal, returns frame unmodified (preview-only). `sees_final_frame` puts it after every other plugin's step, added plugins included, so it shows what apps get. The UI thread only wraps it in a pixmap (`Format_BGR888`) and puts it up; it scales only for the one frame after a resize.
- Pop-out window auto-hides the in-card preview when opened. While the main window is hidden (tray) the card stops decoding without changing its Hide/Show setting.
- `FrameLabel` (card and pop-out): knows where the letterboxed frame sits (`frame_rect`), so a click becomes a point in it (bars ignored). With `bus.focus_point_available` it shows a crosshair, draws a square for a second where you clicked, and emits `bus.focus_point_picked` on release. When pannable (open-hand cursor) a press that moves more than a few px is a drag instead: `dragged(du, dv)` in fractions of the frame. The wheel emits `scrolled(1.1^notches, u, v)`. `paintEvent` draws the lens boxes over the frame, edges on whole pixels, white over a dark halo, labelled in the corner that's in view (skipped for a box around the whole frame, label skipped on a sliver).
- Skeleton: the button is there while the vision download is (`vision_state()` isn't missing or failed). On, it asks `want_people`, keeps the shown stream's `people_seen` and draws `skeleton(people, map_point, aspect)` over the frame: `pose.BONES` mapped through the current view, faint where the model is unsure, orange for an arm `pose.hands_out` counts. Repainted on `view_changed`, cleared on `stream_stopped`. Config key `skeleton`.
- Lens boxes: every `lens_boxes(..., moved=True)` shows them at full opacity, holds `_BOXES_HOLD_MS`, then fades over `_BOXES_FADE_MS`; the lens outline toggle keeps them at full.
- Hides the whole stage while `bus.setup_needed` is true, giving the column to the first-run checklist.
- With the camera off the stage shows a camera-off icon (`FrameLabel.set_placeholder_icon()`) over text in the accent colour (`uiRole="camera_off"`), saying the mic still streams and, when Startup turned it off, that an app opening the camera brings it back. A frame that arrives after `on_camera_off` is dropped.
- Plugins' preview layers and picks (`host.preview_overlays()`): `_on_frame` sends the scaled copy through `tint()` on the UI thread (`_fit_within` never scales above the stream's size; the pixmap is scaled up instead), `FrameLabel.paintEvent` draws `paint()` over the frame, and while a pick runs the label hands left presses, moves, releases and keys to it first (a press it doesn't take, like outside a quad, still pans; no focus click is sent). A pick starting while the preview is hidden shows it again. While a plugin warps the picture (`overlays.warping()`) clicks, wheel turns and drags are mapped back through `unwarp()` and the lens boxes and skeleton aren't painted.
- Config keys: `lens_boxes` (the Lenses button). Preview visibility isn't persisted across restarts.

### `plugins/onboarding.py`
**OnboardingPlugin** - the first-run checklist. `panel_region = "center"`.
- Four steps: virtual camera (`v4l2_module_installed()` on Linux, with the package names if it's missing; one-click UnityCapture install on Windows), phone app (QR to `APK_URL`, or install over USB when a bundled APK and adb are present), Add phone (emits `bus.add_phone_requested`), and Start streaming, which points at the header's Start button and ticks on the first `bus.stream_connected`. While a stream source is picked (`bus.source_selected`) the phone steps read as not needed and count as done.
- Shown while not streaming until a phone is paired, the virtual camera can work and a stream has delivered frames once (`streamed`, persisted).
- `bus.setup_guide_requested` opens it again until its close button (shown only then), the next `setup_guide_requested` or a stream starting, with the phone steps showing even while a stream source is picked.
- Announces whether it's showing with `bus.setup_needed`.
- Config key: `streamed`.

### `plugins/framing.py`
**FramingPlugin** - Auto framing: zooms and pans to keep the people on the shown stream framed. `optional` and `needs_vision` like Background, `panel_region = "left"` after Transforms, one setting for the whole app.
- UI: an on/off switch in the header, a Framing slider (0 to 3 through `FRAMINGS`: Head, Chest, Waist, Body, in tenths, the nearest name as its readout), a Speed slider (1 to 10, named by `SPEEDS` from Sloth to Zippy), a Room to move slider (`ROOMS`: Off, Fidget, Shift, Lean, Step, Roam; `_Room` holds the framing still while the target stays within it of where it settled, follows after `_LEAVE_S` outside, and holds again once it has caught up for `_SETTLED_S`; a hand held out skips it), **Widen for something in your hand**, and a `VisionStatus` line.
- On: `take_view` and `want_people`; off, switched off or `shutdown`: both let go, and the view goes back to the manual zoom and pan. If something else has the view it says so and stays put.
- `people_seen` for `focused_source_id()` keeps the newest people. A 30 Hz timer works out a `Target` (centre in the picture as shown, zoom): `target_box` from shoulders, eyes and hips in picture heights (several people get one box), `fit` keeps the picture's shape inside the picture up to `_MAX_ZOOM` (or Max zoom). `tuning(speed)` turns Speed into the spring's stiffness, how much the target is `smoothed` (landmarks wobble) and how big the dead zone is. `follow` is a soft dead zone (the framing moves only as far as it takes to keep the target inside it, so a slow move is followed without hops) that drifts back to centre over `_SETTLE_S`, and `Spring` a critically damped follow (zoom in log space), and nobody seen for `_LOST_S` heads back to the whole picture. `hands_out` gives the sides with an arm held out above the hip: the wrist `_HAND_OUT` shoulder widths past its shoulder, or the elbow `_ELBOW_OUT` out with the wrist further. Arms count at `_ARM_SEEN` visibility, since the phone sends little more than the framing and the hand is often a guess past the edge. Each side has a `_Latch` (on after 0.3 s, off after 0.8 s), and `target_box` takes in that arm's points that are out to the side, with room for what's in the hand. While one is out the framing moves at least at `_WIDEN_OMEGA`. The centre goes through `shown_to_view` and `pan_for` into `steer_view`, so flip and rotation are taken into account.
- Config keys: `on`, `framing`, `speed`, `hand`. `tests/test_framing.py`.

### `plugins/transforms.py`
**TransformsPlugin** - the manual controls for the window's view (`host.set_view`); the cropping and the phone's share of the zoom are in `view_controller.py`. `panel_region = "left"` (desktop-side processing, next to the output settings).
- UI: flip (Mirror / Upside down segments), rotation (0° / 90° / 180° / 270° segments driving a hidden combo that keeps the saved names None / 90 CW / 180 / 90 CCW), zoom slider (1× up to Setup's Max zoom, 10× by default, through `bus.max_zoom_changed`), a pan pad (`PanPad`, driving the two hidden pan sliders the shortcuts use; enabled only when zoomed), and a Reset action in the card header that drives the widgets so the handlers do the rest. While `view_taken` names something, Zoom and Pan grey out and say what's moving them, and preview drags and scrolls are ignored.
- The zoom slider's tooltip says where the zoom happens, from `view_status`. `lens_note(zoom, sent_ratio, caps, live, default, tele, settled)` - pure: `(level, text)` for the dot on the zoom value (a child of the value label, outside the layout, so it never moves anything); level `""` hides it. `"on"` (lavender) says "Switched to …" when `/v1/state`'s `active_lens` (the physical lens a multi-lens camera streams from) differs from the one live at ratio 1. `"off"` (red, wins) explains the fallback when the pan put the ratio below the lens a centred window would get, or, once the last ratio sent had `_LENS_SETTLE_S` to take, that the phone stayed on its default lens by itself. The plugin remembers the default and telephoto names from `on_phone_state` (keeping them per stream with `StreamsBehind`) and forgets them when the caps change.
- The zoom slider snaps to each lens at `lens_step(lens)` and resets to 1x on a double-click. Dragging the preview moves the window by the drag mapped through `shown_to_view`, so the picture follows the mouse in any rotation/flip; it sticks at the centre per axis within `_PAN_SNAP` of the frame, from a raw pan (`_raw_pan`) that keeps counting underneath, so dragging on lets go without a jump; any other framing change drops it. Scrolling zooms by the factor, stops on a lens mark it crosses (`zoom_detent`), and re-solves the pan so the point under the mouse stays put (a finer `_wheel_zoom` lets trackpad steps add up). Pan is kept as floats and saved as such, finer than the pan sliders.
- Config keys: `flip_h`, `flip_v`, `rotation`, `zoom`, `pan_x`, `pan_y`. `set_config` pushes all of them to the window's view, so each phone gets its own.

### `plugins/monitoring.py`
**MonitoringPlugin** - battery/temperature display and alerts. `panel_region = "right"` (the phone's own health, beside its camera).
- UI: the card is titled Phone. Battery and temperature as coloured pills, then one Warnings block with the thresholds (battery %, temp °C), each with **Notify me** and **Stop the stream** switches under it.
- Subscribes to `bus.phone_state_updated`; also polls independently every 15 s via a daemon thread + `_Signals` inner class for thread-safe emit. A polled reading carries the control client it was read through and is dropped unless that's still the running stream's.
- Streams the panels don't show (`host.background_streams()`) are polled too, and alert by the thresholds saved for them (`host.device_config`), naming the phone; a Stop streaming stops that one (`stop_stream(id)`). What one has already warned about is kept when the panels move between streams.
- `_check_alerts()`: battery counts as low at or under its threshold while on battery or still falling on a charger; hot at or over its threshold. Calls `host.send_notification()` once per threshold crossing when Notify is on. Stop streaming calls `host.stop_stream()` on every reading past the threshold while streaming (last, since it runs `on_stream_stop()` synchronously), with the notification saying it stopped, and a `stopped:<id>` banner with the level and threshold and **Start anyway**. That start is remembered per source (`_allowed`), so the same reason doesn't stop it again until the reading is back past the hysteresis.
- Config keys (per phone): `battery_alert`, `temp_alert`, `battery_notify`, `temp_notify` (default on), `battery_stop`, `temp_stop` (default off).

### `plugins/updates.py`
**UpdatesPlugin** - a green **Update** button in the header (right side, hidden until there's an update) and the **Telescope** card on the Updates & About tab (`UpdatesSection`). The header button, and `bus.update_requested`, open Settings on that tab through `host.open_settings("about")`.
- Checks 8 s after every launch, then daily (an hourly timer checks whether a day has passed; a background check that failed is retried on the next tick). Background failures stay quiet; **Check now** says what went wrong.
- `UpdatesSection`: this version, channel (Stable / Nightly), Check daily, what's new, and **Update and restart** (disabled while streaming, or **Open download page** when `update_blocker()` says so), and on an unzipped Windows copy **Keep this copy where it is** (config `keep_portable`). `moves_on_update()` sends **Update and restart** through the setup when the copy is unzipped, not kept portable, the release has `TelescopeSetup.exe`, and the camera driver isn't registered from this folder (deleting it would take the camera away); a move needs no writable folder, so it has no blocker.
- Download and install run in a thread; on success it relaunches (`--after-update`) and calls `host.quit_app()`.
- A newer build that was rolled back for not starting isn't offered; the dialog says so and **Try again** clears the marker and checks again.
- Config keys: `channel`, `auto_check`, `last_check`.

### `plugins/presets.py`
**PresetsPlugin** - a **Presets** button in the header (left, after the phone picker) with a menu: the saved presets (click applies), **Save current as…**, **Rename**, **Delete**. Per phone (`device_local`), since lens ids and sizes differ between phones.
- A preset is `{name, <section>...}`, one section per plugin in `host.preset_plugins()` (the ones that are `in_presets`: Camera, Stream output, Transforms, Background, Auto framing, and any added plugin that asks). Camera control, Stream output and Transforms keep the keys they always had (`camera`, `stream`, `transforms`, see `_KEYS`), others use the plugin's name. Snapshotted with `host.plugin_config()` and applied section by section through `host.apply_preset()` in registration order, so the lens switch goes out before Stream output looks up its sizes. A preset from before a plugin was in presets leaves that plugin alone, and a switched-off plugin's section is kept. Saving under an existing name replaces it.
- `clean_presets(raw)` drops malformed entries and duplicate names on load.
- Config key: `presets`.
- `create_actions()`: apply a preset by name, and next or previous (from the one applied last).

### `plugins/microphone.py`
Doesn't follow the panels (`follows_focus = False`): with several streams it stays on the first phone's mic, and moves to the next one if that phone stops.
**MicrophonePlugin** - the Microphone card (left): an On switch in the card header, the level meter on the Phone mic row, a Gain slider (-24 dB up to Setup's Max gain, +12 by default, snaps to 0) with a box to type an exact value (`_GainSpin`, shows +6 dB, applies on Enter), a level meter, a status line (hidden once audio flows, since the meter shows it), a button when something's missing (Install VB-Cable, which asks first, then runs `WindowsMic.install()` on the background thread: `virtual_mic.download_vb_cable()` fetches VB-Audio's pack against a pinned SHA-256 and `run_vb_cable_setup()` checks the setup again and opens it with UAC; a failure turns it into a Get VB-Cable link), and Mute in the header (shown while it's on), mirrored by a checkable **Mute microphone** item in the tray menu (`create_tray_actions()`). Mute sets the worker's `muted` and isn't saved, so the app never starts muted. While the worker runs, a 33 ms timer feeds `take_level()` into the meter and the readout beside it (held peak in dB, or Muted). Per phone (`device_local`). While on, it follows the stream: `on_stream_start` prepares the virtual mic and starts an `AudioWorker` on `{ctrl.base}/audio`; `on_stream_stop` stops it (the camera going off doesn't); `bus.mic_changed` reports the On switch and Mute; switching off also removes the Linux virtual mic, as does `shutdown()`. `LinuxMic` / `WindowsMic` hold the per-OS parts (`problem()`, `prepare()`, `open_sink()`, `teardown()`, `pick_name`); `prepare()`, the worker's `stop()` and `teardown()` wait on pactl or threads, so they run in order on one background thread (`run_job`, injectable like the backend and worker class); a generation counter drops a setup result that arrives after the stream stopped. `shutdown()` waits for them, since the mic has to be gone before the app is. Config keys: `enabled`, `gain_db`.

### `plugins/wait_screen.py`
**WaitScreenPlugin** - runs a `vcam.WaitScreen` from app start to quit, except from `on_stream_starting` to `on_stream_stop` or `on_camera_off`, at the Setup canvas size or else the size the last stream opened the camera at (`last_size`, from `bus.vcam_opened`), or else 1920x1080, so a call that's already reading keeps working when the stream takes over (v4l2loopback readers lose the picture on a size change). Runs `vcam.CameraWatch` and re-emits it as `bus.camera_watched`. The **Wait screen** card on the Streaming tab (`WaitScreenSection`: preview, Choose image…, Use default, and a mirror checkbox for apps that flip the camera, off by default); a chosen image is copied next to the config as `wait_screen-<id>.<ext>` (a new name each pick, so the camera reloads; the previous copy is deleted only once the new one is in place, and a copy that fails leaves the current image and says why in the card; one that won't load is called out in the card too). `vcam.read_image_frames` decodes a photo over Qt's allocation limit at a reduced size. The main camera shows it too while `bus.idle_outputs` has 0 in it (only extra cameras stream). The extra cameras in `bus.idle_outputs` (set up, nothing streaming to them) each get a `WaitScreen(slot=n)` too, at the canvas size or 1920x1080. Config keys: `image`, `mirror`, `last_size` (global).

### `plugins/shortcuts.py`
**ShortcutsPlugin** - keyboard shortcuts. Global config: `bindings`, `notify`. Starts on the first turn of the event loop, once every plugin's controls exist: gathers `host.shortcut_actions()` (its own, Telescope group, first: start/stop streaming, phone camera on/off, show or hide the window), gives their controls a right-click menu (add a shortcut, or edit one it already has; controls that come later, the lens buttons, get it through the key filter's `ContextMenu` handling), installs `_KeyFilter` on the application and asks `create_backend()` for the global keys.
- Keys inside Telescope: `_KeyFilter` sees every key before the focused control does and runs the matching binding, unless a modal dialog or a popup (menu, drop-down) is up, the key editor has focus, or a text box has focus and the key is one that edits text (`edits_text()`: no Ctrl/Alt/Meta, and not an F-key or media key). It acts only at the focused widget, since Qt hands an ignored key on to each parent. Held keys repeat only steps (`ShortcutAction.repeats`). A key's release (matched by key or by scan code, since a shifted key can come up as another), or the app losing focus, releases "while held" bindings. Global bindings are matched here too, since the portal may have bound another key; a press of one binding seen both ways within 150 ms runs once. A binding that couldn't run (its control is off) leaves the key to the focused control.
- `where(binding)`: the dialog's status column (in Telescope, everywhere with the key the system bound, or why not). A global binding the system refused or hasn't confirmed still works inside Telescope, unless its status says the key doesn't reach the app (`HotkeyStatus.reaches_app`).
- `handle_remote(request)`: `telescope --action ID name=value` and `--list-actions`. Settings are checked rather than defaulted (a typo is an error), and `hold` is refused since nothing would let go of it.
- The system only gets the global list again when it changed, since rebinding on Plasma can ask to confirm them all again.
- The **Keyboard shortcuts** tab is `ShortcutsSection` (the **Shortcuts** card with **Add** in its header and a strip per binding with edit and remove icons, where clicking the strip edits it and right-clicking copies its command line; the **Everywhere** card with a note on how global keys work here, **Open** next to **Desktop shortcut settings** on Linux, and the **Notify when one runs** switch). `BindingEditor` is the modal editor: a search (every word has to start a word of the action's card, name, id, `keywords` or its choices), control, its settings (built from the action's `Param`s), the key (`QKeySequenceEdit`, one chord), and "Also works while another app is in front". A key another binding uses blocks Save; a plain key marked global only warns. While it's open, global presses are ignored and the backend `suspend()`s where that's cheap (Windows lets the keys go so the editor can record one; the portal keeps them, since binding again can bring the confirm dialog back). **Open** next to **Desktop shortcut settings** asks the desktop again (`rebind_global()`) when the backend says that would help (`can_rebind()`: the portal is up and some weren't confirmed), else opens Plasma's Shortcuts page. Copying a command line is off for a "while held" binding, since `--action` refuses `hold`.

### `plugins/startup.py`
**StartupPlugin** - two sections: **Open Telescope when I sign in** (`SignInSection`, in a **Startup** card on General; `platform/autostart.py`, read again each time the tab comes on screen) and the **Automatic streaming** card on Streaming (`AutomaticStreamingSection`). Start and Stop are drop-downs, the wait is a number and seconds/minutes, and all of it applies as it changes.
- `start_on`: `off`, `ready` (listens to `bus.phone_ready` and calls `host.start_stream(interactive=False)` once per arrival: a Stop or an attempt holds it until the phone reports not ready or another phone is selected) or `watched` (listens to `bus.camera_watched` and starts the same way once the phone is ready; a Stop holds it until the reader lets go). Neither claims a Start the user already has waking the phone. Any start keeps the window in the tray on close.
- `stop_idle`: `off`, `own` (only a stream it started) or `any`. `_sync_idle_timer()` is the one place the wait starts or stops: it runs while the rule applies, the camera watch has reported at least once, no app reads the camera, and a stream runs (or its own start is still waking the phone). It's called on every watch report, stream start, stop, failed start (`bus.stream_start_failed` clears the claim) and setting change. When the wait (`stop_delay_s`, 10 s to 60 min, default 15 s) runs out, `_stop_idle()` checks again, then `host.stop_stream()` and, with `notify_stop`, a notification. With the microphone card on (`host.can_turn_camera_off()`) it calls `host.set_camera_on(False, auto=True)` instead, without a notification, and the wait doesn't run while the camera is off; an app opening the camera turns it back on (`is_camera_off_auto()`). The card says so under the Stop choice. A restart (`host.is_restarting()`) keeps the stream its own and leaves the wait alone. Changing the wait mid-count restarts it with the new value.
- **Wait before stopping** (a number and seconds/minutes, saved once typed) and **Tell me when it stops a stream** are greyed out while nothing stops by itself. Changing the unit keeps roughly the same wait (90 s becomes 2 min).
- Config keys (global): `start_on`, `stop_idle`, `stop_delay_s`, `notify_stop`. The old `auto_stream` / `watch_stream` booleans load as `ready` + `off` / `watched` + `own` (watching wins when both were on). `diagnostics()` shows all four and whether the running stream is its own.

### `plugins/setup.py`
**SetupPlugin** - the virtual camera, video, audio and About settings, split over tabs; no panel, since nothing in them is adjusted mid-stream. `create_settings_sections()` builds `AdvancedSettings`, which holds the cards, and hands them out: **Virtual camera** and **Phone app** on Virtual camera & phone, **Video** (hardware acceleration, power-saving effects, Max zoom, canvas size), **Microphone** on Audio, **Look** on General and **About** (version, author link, **Open log**, **Copy diagnostics**) on Updates & About. Each time one of its tabs comes on screen the controls are set from the saved values again (a preset or config reload may have changed them) and the system is looked at again (module or driver status, adb, extra cameras).
- `AdvancedSettings` (a `QWidget` that is never shown; its cards are what the tabs hold): v4l2loopback status, load/unload and load at boot (Linux), UnityCapture status and reinstall (or **Rename**, to Telescope, for an older registration) plus adb status (Windows), installing an APK over USB, the virtual camera canvas (presets or custom, applied through `host.restart_vcam_canvas()`; custom sizes step by 2 and odd ones round up to even, also in a hand-edited config, and a resize the host refuses or fails puts the previous canvas back), Max zoom (2-30×, applied straight away through `bus.max_zoom_changed`), Max gain (+12/+24/+36/+48 dB segments, through `bus.max_gain_changed`), the Limiter switch (`bus.limiter_changed`), Hardware acceleration (`h264_reader.set_hardware`) with **Set up VA-API…** (`widgets/vaapi_setup.py`) on Linux, Power-saving effects (`vision.set_power_saving`), Extra cameras (taking them away), and Card colours (`theme.set_plugin_hues`). A privileged step that couldn't ask for the password shows its command under its row in a `CommandBox` instead of the main window's banner.
- `get_canvas_dims()` → `(w, h)` or `(None, None)` for auto; the window reads it at stream start and hands it to other plugins as `host.canvas_size()` (the wait screen), so none of them needs Setup's config format.
- Config keys: `canvas_preset`, `custom_canvas_w`, `custom_canvas_h`, `max_zoom` (default 10; anything else out of range falls back to it), `max_gain` (default 12; anything but the four choices falls back to it), `limiter` (on unless saved as `false`), `hw_decode` and `power_saving` (each off unless saved as `true`), `plugin_hues` (on unless saved as `false`). `set_config` emits `max_zoom_changed`, `max_gain_changed` and `limiter_changed`, and global configs load before per-phone ones, so the sliders' ranges are in place before a saved zoom or gain is set.
