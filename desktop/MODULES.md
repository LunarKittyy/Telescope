# Telescope Desktop - Module Reference

Quick navigation index; see source code for detailed behavior.

---

## Entry point

### `update_guard.py`
Makes an update survive being cut short, and undoes one that won't start. Standard library only and outside the package, so `main.py` can run it before importing anything else. The journal (`.update.json`) goes `swapping` → `trial` → gone. `finish_swap()` is safe to run again: Windows moves each `lib-<build>` folder in with one rename, then swaps the exe with two (the one instant nothing can start), then the other files; Linux replaces each file in one step (so `start.sh`, `main.py` and this module are never missing) and moves each folder aside to `.previous/` before moving the new one in. `recover()` on every start: finishes a cut-short swap (relaunching the new exe if the old one was running), marks a trial as started, and rolls back a trial that already started but never reached `confirm()` (`confirm_on_terminate()` makes a SIGTERM or SIGHUP, i.e. a logout, confirm first, so only a start that dies with no signal counts as failed), after first giving that start up to `TRIAL_GRACE_S` (30 s) to take the single-instance lock, so a double-click during the new version's first start doesn't roll it back. `roll_back()` puts the old exe or `.previous/` entries back and writes the build to `.update-failed`, which `updates.is_newer()` then skips. It leaves everything alone while another copy holds the single-instance port.

### `main.py`
First `update_guard.recover()`, before anything else is imported; then dependency check; on bundled Windows, a copy opened from inside a zip (`windows.running_from_archive()`) shows a message box to extract it first and quits; Qt app setup, `apply_theme()`, single-instance guard, plugin registration, config restore, event loop.
Registration order: `SetupPlugin → ConnectionPlugin → CameraControlPlugin → BrowserCameraPlugin → StreamOutputPlugin → TransformsPlugin → MicrophonePlugin → PresetsPlugin → PreviewPlugin → OnboardingPlugin → MonitoringPlugin → UpdatesPlugin → WaitScreenPlugin → StartupPlugin`. Preview comes before Onboarding so the stage is listening when the checklist first says whether it needs the space, and Wait screen before Startup so the settings menu keeps its dialogs above Startup's divider and toggles (see **Settings menu** below).
On Linux (not from a source checkout) it calls `autostart.update_menu_entry()` to keep the app menu entry pointing at this copy.
`--after-update` (passed by the updater when it relaunches) waits up to 15 s for the old copy to exit. 3 s after the window is up, or when the app quits normally, it calls `update_guard.confirm()` and `updates.clean_up_after_update()`. `--minimized` (the sign-in entry) starts in the tray via `win.start_hidden()`. Arguments it doesn't know go to Qt.
Calls `win.apply_saved_config()` **after** all plugins are registered so every plugin's `set_config()` is available.

## `telescope/` package

### `app.py`
**TelescopeWindow** - thin coordinator shell.
- Owns the header bar (plugin header widgets on the left, or just left of the settings menu for a plugin whose `header_side` is `"right"`; settings menu and Start button on the right), the column body, the footer (stream status, FPS, throughput), and the tray icon.
- Owns `EventBus` and `StreamWorker` lifecycle.
- `register_plugin(p)` - calls setup, routes panel to the named region, appends header widget.
- `_refresh_layout(force=False)` - redistributes panels across columns by width (a panel its plugin has hidden stays hidden): `three` (≥1300px) left/center/right, `two` (≥900px) left+right/center, `one` center-first. Both rails are `_RAIL_WIDTH` wide so the preview sits centred. Triggered on resize (no-op if layout mode unchanged) and on registration.
- `_show_settings_menu()` - builds the header's settings menu fresh on each click from every plugin's `create_menu_actions()` (a `QMenu` entry becomes a submenu owned by that menu), and deletes it once it closes.
- Re-exports `STATUS_COLORS` from `theme.py`.
- `acquire_single_instance()` holds the lock at `update_guard.instance_address()`: on Linux a Unix socket per user (abstract name `telescope-<uid>`, `-dev` for a dev profile, no file to go stale), so two accounts on one machine each run their own; on Windows `127.0.0.1:47823` (`+1` for dev). A second launch sends `raise:<user token>` (`user_token()`: a hash of the user name and Windows session); the running copy answers `ok` after raising its window, or `other` when the token is another user's, which shows "already running for another user". No answer means something else holds the lock, and a message box says so instead of quitting silently.
- `_set_plugin_config()` loads a plugin's saved settings; if that fails it keeps the fields that load on their own and defaults only the bad ones.
- `apply_saved_config()` - call after all plugins are registered; restores config round-trip for each plugin.
- **Several streams.** Each streaming source holds its own `StreamSession`; `_streams` lists them in start order (at most `vcam.MAX_SLOTS`). `_focus` is the one the panels show, and `_session` is its session. `_main` is the first, which plugins with `follows_focus = False` (the mic) stay with, until `make_main(id)` moves them to another stream (saving their settings as the one they leave, loading the new one's); `main_stream()` says which. `_tell(source, hook)` calls a stream hook on the plugins that hear about that source. `add_stream(id)` (the header's + button, shown while streaming) moves the panels to the new source and starts it; `_free_slot` gives it the virtual camera it had last (`output_slots` in the config) or the lowest free one, and `_set_up_slots` asks to add the extra cameras first when they aren't there. `_move_focus` (a tile click via `focus_stream`, or `pick_source` from the picker) freezes the old stream's frame steps, saves the following plugins' settings as its device's, loads the new one's, emits `device_changed`, shows its status and asks its phone for its state again (`refresh_state`). Stopping the shown stream moves the panels to the first one left, and stopping the first moves the mic on (`_sync_main`), unless it's only restarting (`reconnect_stream`), when the mic waits for it. `stream_started` and `stream_stopped` only mark the first start and the last stop; `streams_changed` gives the count. The header's Stop (`_stop_all`) stops them all; `stop_stream()` stops the one shown, `stop_stream(id)` a given one. Worker signals find their stream through `sender()`; one the panels don't show only updates its tile, and still recovers or stops by itself. With more than one stream, the camera can't go off, the canvas can't be resized, and once a second one has streamed Automatic streaming stops nothing until all have stopped. `_announce_idle_outputs` emits `bus.idle_outputs` on each change (the main camera, 0, included while only extra ones stream), and just before a stream opens an extra camera so the wait screen lets go of it. A source whose `prepare()` declines while `waiting()` (Browser camera with no browser yet) becomes `_pending` when added next to others: a **Waiting** tile with the panels on it, until it's no longer waiting; its tile's x (`stop_stream(id)`) and Stop call its `cancel_wait()`. `start_again(id, before)` is the callback banners use for Start and Try again: that source by itself or next to the others, `before` running with the panels on it (Switch to Heavy). Banners about one stream that stopped use the key `stopped:<id>`, and another stream connecting leaves them. `remove_extra_cameras` (Advanced's **Extra cameras**) deletes them on Linux (`v4l2_remove_devices`) or re-registers UnityCapture with one camera (`register_unitycapture(1, reset=True)`). Plugins can offer and take back sources while running (`add_stream_source`, `remove_stream_source`) and start one (`stream_source`: picked and started when nothing streams, else `add_stream`); at Start, a picked source's `redirect()` can name another to stream instead. `_drop_unchanged` keeps a `remember_changes_only` source's settings only where they differ from the plugin defaults. `widgets/tiles.py` draws the row of tiles.
- **Stream sources.** Every stream comes from a `Source` (`sources.py`), which keeps that stream's own state: `_phone` (a `PhoneSource`) is the phone Connection has picked, and `add_stream_source(source)` wraps a plugin's `StreamSource` in a `PluginSource` and emits `bus.stream_sources_changed`. `_selected_source()` is the plugin source whose id is Connection's `selected_device`, else the phone; `_active_source()` is the session's source, or the selected one while idle. The session keeps its source, and the window asks it rather than checking which kind it is: a plugin source sends no remote stop, has no state to fetch, and its reader waits for it to come back after a drop instead of probing routes.
- **Two-phase start.** `_start()` calls `source.prepare()` (a phone: `conn.get_stream_info()`, which validates ADB/v4l2 and builds the URL; a plugin source: `conn.ensure_virtual_camera()` and its own `prepare()`). A source that doesn't wake goes straight to `_begin_stream(source)`. A phone does: `PhoneSource.wake()` snapshots `conn.session_target()` on the GUI thread and brings the camera up on a background thread (`_spawn_wake()`), then the window's `_on_wake_done(source, ok, reason)` either runs `_begin_stream()` (worker, ctrl, pipeline) or re-enables Start and shows the error. The phone's `_wake_id` counter drops stale results after user Stop/device switch/quit. Split for testability (tests call synchronously).
- `_stop(remote_stop=True)` - tears down worker and ctrl; `on_stream_stop()` on each plugin (ConnectionPlugin releases its USB forward there); `source.stopped()` invalidates any in-flight wake and takes the phone's camera down with it (`PhoneSource._stop_phone_async()`). `remote_stop=False` is for the internal stop/start pairs that are really a desktop-side reconnect (`reconnect_stream()`, `restart_vcam_canvas()`) - bouncing the phone there would cost seconds and a lens re-open for nothing.
- `_drain_phone_stops(timeout=2.0)` - the remote stop runs off the UI thread but is tracked rather than fire-and-forget, so the quit paths (`closeEvent`, `_tray_quit`) can give it a bounded moment to actually leave the machine (each source's `drain_stops()`). Both quit paths then call every plugin's `shutdown()`.
- Implements the public **`HostServices`** contract (see `plugin.py`): `schedule_save()`, `save_now()`, `switch_device()`, `forget_device_settings()`, `reconnect_stream(source_id=None)` (a stream the panels don't show gets them first; during another start it waits for it), `send_notification()`, `is_streaming()`, `is_starting()` (a Start is waking the phone, before the worker exists), `is_restarting()` (the `stream_stopped` being handled is a reconnect or resize, and a stream starts again right after), `stop_stream()`, `update_stream_output()`, `restart_vcam_canvas()`, `quit_app()` (really quits, tray or not), `start_stream(interactive=True)` (False: no password prompt, problems go to a banner), `set_keep_in_tray(keep)` (close hides to the tray even when idle), `show_issue(key, Issue)` / `clear_issue(key=None)` (problem banners above the body; every banner clears when a stream connects), `diagnostics_report()` (the Copy diagnostics text), `plugin_config(name)` / `apply_preset(name, cfg)` (another plugin's config, and handing it one to apply; used by Presets), `is_camera_on()` / `is_camera_off_auto()` / `can_turn_camera_off()` / `set_camera_on(on, auto)` (see **Camera off** below), `start_again(source_id, before)`, `focused_source_id()`, `background_streams()` and `device_config(source_id, plugin)` (see **Several streams**). Plugins only call these; private internals (`_worker`, `_stop()`) are hidden.
- `send_notification(title, body, urgent=True)` - uses `notify-send` on Linux (critical urgency only when `urgent`), tray balloon on Windows.
- `save_now()` - writes global plugin configs (connection, setup) and per-device configs (camera_control, stream_output, transforms, monitoring, presets, microphone) under `devices[selected]`. `schedule_save()` is the debounced variant plugins call after a settings change.
- `switch_device(prev, new)` - saves `prev` phone's per-device configs, restores `new` phone's; called by `ConnectionPlugin._activate_profile()`. Keys are phone ids.
- `forget_device_settings(id)` - deletes a removed phone's stored settings. `move_device_settings(old, new)` stores a phone's settings (presets included) and remembered virtual camera under a new id, for a phone that paired again after a reinstall.
- `restart_vcam_canvas()` stops the stream for the resize and starts it again when done (`_canvas_restart`); any real stop meanwhile cancels that restart.
- `is_streaming()` / `stop_stream()` / `update_stream_output(width, height, fps)` - public stream controls; `stop_stream()` is a guarded no-op when idle, and `update_stream_output()` forwards only the values a caller passes (`None` width/height means pass-through).
- `_plugin(name)` - central typed lookup of a registered plugin by name (replaces scattered inline `next(p for p ...)` scans).
- Footer "Throughput" (Mbps) readout, colored amber when frames sustainedly arrive under 85% of the target rate (`_frames_arrived`: every frame the readers took in, `last_frame_count` of them per read, since an H.264 burst shows only its newest), and `bus.stream_behind(bool)` when that changes (`_note_throughput()`: not while recovering a dropped stream, nor for the first report after it's back, which still counts the gap; a stop, a stream loss or an `"ok"` status resets it to False). Before going amber, `_on_slow_arrival()` has the source check its camera's rate (`PhoneSource.check_camera_rate()` asks the phone for its `camera_fps`, the answer kept for `_CAMERA_FPS_KEEP_S`): frames arriving at 90% of what the camera makes mean the camera is slow (dim light), not the link, so the readout stays normal and the FPS readout's tooltip says so; a phone that doesn't report it counts as the link; live FPS/resolution readout reflects the frame's actual current shape rather than the frozen stream-start size.
- Pending-resolution tracking: `_on_resolution_pending()` marks changes in flight on the source (8s timeout); readout amber until fps readout confirms new size or timeout fires error. The behind, settling and slow-arrival state live on the source too.
- **Getting a dropped stream back.** The worker's `"reconnecting"` status starts `_begin_recovery()`: `bus.stream_lost`, then `source.lost()`. A phone (`PhoneSource`) then, every `_RECOVER_RETRY_MS` (3 s), does a quiet state fetch (`_spawn_state_fetch()`: the phone may have dropped the stream on purpose, e.g. H.264 it can't do, and its state says why, sometimes only seconds after the drop; plugins get it only when it has a `codec_error`) and a background `conn.recovery_probe()` job that resolves the route again. A phone that answers while streaming gets the stream moved there once per route (`conn.adopt_stream_route()` for the URL and a fresh USB forward, a new `PhoneControlClient`, `worker.retarget(url)`); one that answers but isn't streaming ends the stream with a "The phone stopped streaming" banner. `_recovery_gen` drops probes from before the stream came back or stopped. So a pulled cable falls back to Wi-Fi, and a replugged one gets a working forward again. For any source, `start_lost_clock()` runs two timers: after `_PARK_AFTER_MS` (10 s) `_park_stream()` has the worker let go of its virtual camera (`StreamWorker.set_parked`) and `_announce_idle_outputs` counts it as idle, so the wait screen shows instead of the last frame; after `_UNREACHABLE_AFTER_MS` (30 s) a `stopped:<id>` banner says it can't be reached, with the source's `lost_hint`. Retrying carries on. On `reconnected` the wait screen lets go (`_free_vcam_for`) and the worker takes the camera back; `end_recovery()` stops both timers and drops the banner.
- **Camera off.** `set_camera_on(on, auto=False)` keeps the stream (and so the mic) going without video: it sends the `camera_on` control, ends the worker (`_end_worker()`), sets `session.worker` to `None` and calls `on_camera_off()` on every plugin (the wait screen takes the virtual camera back); on again it starts a new worker through `_start_worker()` (after `on_stream_starting()`) and calls `on_camera_on()`. Before a start it only picks what the next start does: `PhoneSource.wake()` adds `camera: "off"` to the opening and Start reads **Start mic only**. The choice is kept on the source (`camera_off`, `camera_off_auto`), so picking another source can change it: `_on_source_selected()` then updates Start and emits `camera_on_changed`. Only a source with `mic_alone` (a phone) can turn its camera off. Going off needs the microphone card on (`can_turn_camera_off()`), and switching the mic off turns the camera back on. `is_streaming()` is the session, not the worker, so a mic-only stream counts. `_stop()` puts the camera back on unless it's a restart. With no video to notice a dropped phone, the phone's `_alive_timer` asks for its state every 5 s and two misses in a row start `_begin_recovery()`; a route move with no worker swaps the client and reruns `on_stream_start`. The first state fetch matches the phone to the desktop (`PhoneSource.on_phone_state()`): a phone without `camera_toggle` gets the camera back with a banner. `_CAMERA_ON_CHECK_MS` after turning it on, a phone reporting `camera_error` puts it back off with a banner. `auto` (from Startup) is remembered as `is_camera_off_auto()`, so an app opening the camera can undo it but not a choice made by hand. `bus.camera_on_changed` reports every change.
- The tray icon (`create_tray_icon(camera, mic)`) and its tooltip follow the stream, `camera_on_changed` and `bus.mic_changed`: a red dot while the camera streams, a mic while the mic does, crossed out when muted.
- `_start_reconnecting_animation()` / `_tick_reconnecting_animation()` - animates the "Stream dropped - reconnecting" footer status (yellow, cycling "." → ".." → "..." once a second) instead of a static line.
- `_apply_config(cfg)` - routes global plugin slices to `p.set_config()`, per-device slices for the selected device, then calls `conn.sync_active_profile()` so the restored selection doesn't spuriously re-trigger a profile switch.
- Utility exports: `acquire_single_instance()`, `listen_for_raise()`.

### Settings menu
The header's settings menu stays in one shape as options are added: entries that open a dialog (ending in "…") first, then one divider, then entries that change something straight away. At most one submenu level, with headings rather than nested submenus for groups inside it. A setting that belongs to a panel's feature lives in that panel, not here, and a notification's on/off sits next to whatever triggers it (Monitoring's thresholds, the Automatic streaming stops). Plugin registration order sets the order.

### `theme.py`
The app's entire visual definition: palette constants (`BG`, `SURFACE`, `ACCENT`, `FILL`, the `OK`/`WARN`/`ERR`/`DIM` status set, `STATUS_COLORS`), a dark `QPalette`, and the stylesheet built from those tokens.
- `apply_theme(app)` - sets Fusion as the base style, installs the palette, applies the QSS. A no-op once installed, since re-applying repolishes every live widget.
- Tooltips: show after `TIP_WAKE_MS` (250 ms, Qt's is 700), wrap at about `TIP_LINE_CHARS` (64) characters, and stay up while the mouse is still on their control. `_PopupStyle` does it with a style hint and one event filter on Qt's single tooltip window (`_TipFilter`), not an app-wide filter.
- No image files and no third-party theme: icons are inline SVG rendered by `create_vector_icon()`, and controls that need a custom look (segmented toggles, card actions, the preview stage) are targeted by object name or property selector.
- The layout rules every panel and dialog follows (type scale, control column, button roles) are written at the top of `widgets/common.py`.

### `plugin.py`
**TelescopePlugin** base class + **HostServices** contract + **EventBus**.
- `HostServices` (typing.Protocol): the public surface a plugin may call on its `host` handle - `schedule_save`, `save_now`, `switch_device`, `forget_device_settings`, `move_device_settings`, `reconnect_stream`, `send_notification`, `is_streaming`, `is_starting`, `is_restarting`, `stop_stream`, `update_stream_output`, `restart_vcam_canvas`, `quit_app`, `start_stream(interactive)`, `set_keep_in_tray`, `show_issue`, `clear_issue`, `diagnostics_report`, `plugin_config`, `apply_preset`, `add_stream_source`, `is_camera_on`, `is_camera_off_auto`, `can_turn_camera_off`, `set_camera_on`, `start_again`, `focused_source_id`, `background_streams`, `device_config`. Structural typing only (`TelescopeWindow` implements it without inheriting). Keeps plugins off private window internals.
- `StreamsBehind`: for a plugin following the panels, what it keeps about a stream they moved away from while it streams on (`keep()` from `on_stream_stop`, `take()` from `on_stream_start`). Camera control keeps its last phone state and focus point, Transforms what the phone crops, so coming back to a tile shows the stream as it is without resending anything.
- `StreamSource` (Protocol): `id` (also its per-device settings key), `name`, `url`, `prepare(interactive)`, `open_reader()`, `control_client()` (stands in for `PhoneControlClient`: `base`, `auth`, `send`, `get_state`, `close`), `fps()`; optionally `redirect()`, `waiting()` and `cancel_wait()`. `HostServices.add_stream_source()` offers one.
- `UNCHANGED`: sentinel for `update_stream_output` so `None` can be passed as a real value (pass-through resolution) distinct from "leave as-is".
- `TelescopePlugin.follows_focus` (default `True`): with several streams, the plugin hears about the one the panels show; `False` keeps it on the main one (the mic): the first, or the one `make_main` picked. The Microphone card shows the main stream's mic only while the panels show that stream; on another stream's tile it reads off, with a note saying where it's on, and turning it on there calls `make_main`. When the main stream stops with the mic on, the next one gets it on too.
- `TelescopePlugin`: override `setup`, `create_panel`, `on_stream_starting` (just before the worker opens the virtual camera), `on_stream_start`, `on_stream_stop`, `on_camera_off` / `on_camera_on` (the stream carries on without video, or gets it back), `on_phone_state`, `process_frame`, `frame_step` (a copy of `process_frame` frozen at the current settings, for a stream the panels aren't showing; `None` by default), `get_config`, `set_config`, `apply_preset`, `diagnostics` (lines for Copy diagnostics), `shutdown`. The host calls the stream and phone-state hooks one plugin at a time and logs a hook that raises, so one broken plugin can't stop the others hearing about it; a `get_config` that raises keeps that plugin's saved settings.
  - `apply_preset(cfg)` loads a saved config; the default is `set_config`. Camera control and Stream output also send it to the phone while streaming.
  - `panel_region` (class attr): `"left"` / `"right"` / `"center"` - which region the host puts the panel in. A preference, not a guarantee: narrow windows merge regions.
  - `create_header_widget()` → a compact widget for the window header, or `None`. `header_side` (`"left"` / `"right"`) picks where it goes.
  - `create_menu_actions()` → `QAction`s (or a `QMenu`, shown as a submenu) for the header's settings menu, or `[]`. Lets a dialogs-only plugin skip having a panel.
  - `create_tray_actions()` → `QAction`s for the tray menu, or `[]`. Asked once, at registration (after `create_panel()`); the host puts them between Show and Quit and the plugin keeps them up to date.
- `EventBus(QObject)`: signals - `stream_started`, `stream_stopped`, `stream_start_failed` (a Start ended without a stream: the stream info wasn't available or the phone didn't wake), `stream_connected`, `stream_lost` (frames stopped; the host is looking for a route back), `phone_state_updated`, `device_changed`, `phones_changed(int)`, `add_phone_requested`, `setup_guide_requested` (Connection's **?** → the checklist again, or closed again), `setup_needed(bool)`, `camera_switched`, `resolution_change_requested`, `update_requested` (the phone app is newer; opens the update dialog), `focus_point_picked(u, v)` (preview click, in the frame as shown) → Transforms → `focus_point(x, y)` (in the phone's frame) → Camera control sends `focus_point`, `focus_point_available(bool)` (Camera control → Preview's crosshair), `phone_ready(phone_id, ready)` (from Connection's idle status checks only, never from Start's own resolve), `max_zoom_changed(int)` (Setup's Max zoom → Transforms' slider range), `max_gain_changed(int)` (Setup's Max gain → the Microphone card's Gain range), `limiter_changed(bool)` (Setup's Limiter → the audio worker), `view_dragged(du, dv)` / `view_scrolled(factor, u, v)` (Preview's mouse → Transforms' pan and zoom), `view_pannable(bool)` and `lens_boxes(boxes, moved)` (Transforms → Preview's hand cursor and lens outlines), `vcam_opened(w, h)` (the stream opened the virtual camera at this size), `camera_watched(bool)` (Wait screen: an app started or stopped reading the camera), `stream_sources_changed([(id, name)])` (every offered StreamSource; Connection lists them in the picker), `source_selected(id)` (the picked source, or `""` for a phone; phone-only cards hide, and Onboarding skips the phone steps), `stream_behind(bool)` (the stream fell behind or caught up; only on a change), `camera_on_changed(bool)` (the camera went off or on, or what the next start uses changed), `mic_changed(enabled, muted)` (the Microphone card). `phones_changed`, `add_phone_requested` and `setup_needed` are how the checklist, Connection and Preview cooperate without calling each other.

### `sources.py`
What the window streams from. `Source` holds one stream's state (its `session` while it streams, the virtual camera `slot` it feeds, camera off and whether that was automatic, `camera_toggle`, recovering, behind, settling reports, slow arrival, pending resolution, and the status, readouts and last phone state the footer and panels get back when they return to it) and no-op hooks the window calls at each step: `prepare`, `wake`, `started`, `stopped`, `lost`, `end_recovery`, `check_camera_rate`, `on_phone_state`, `watch_alive`, `camera_turned_on`, `drain_stops`.
- `PluginSource` - a plugin's `StreamSource` (see `plugin.py`), ready once the virtual camera and the source are; nothing to wake, no state, and its reader waits for it after a drop. On Linux an Auto canvas becomes 1920x1080 (`auto_canvas`).
- `PhoneSource(win, phone_id)` - one paired phone; the window makes one per id as needed (`_phone_source`), and passes the id to Connection's per-phone calls (`get_stream_info`, `session_target`, `recovery_probe`, `adopt_stream_route`, `show_problem`, `release_stream`). Owns the wake (`_wake_id`, the target to stop if a wake lands after Stop), the remote stop and its tracked threads, the state fetch, route recovery (`_recovery_gen`, `_recovery_route`, the retry timer), the camera-rate check, the alive poll while the camera is off, and the check after turning the camera back on. It calls back into the window for the session, banners, the footer and stopping.

### `stream.py`
**StreamWorker(QThread)** - video capture and virtual camera output.
- Reads the authenticated stream with `MjpegReader` (`mjpeg_reader.py`) or, for a URL ending `.h264`, `H264Reader` (`h264_reader.py`); both send the bearer token and report `last_frame_bytes` for the throughput readout. Writes to the virtual camera opened by `vcam.open_camera()` (at the canvas or phone size, or `vcam.locked_size()` while an app holds the camera at another) and emits `vcam_opened(w, h)` once it's open.
- Three kinds of thread: a reader pulls packets off the wire (`read_packet()`) and hands only the newest to the decoders (`_Newest`), so a slow decode drops frames instead of building up lag; decoders (`MJPEG_DECODERS`, 2 on most machines, for MJPEG; one for H.264, which `H264Reader` decodes in order while reading) run `decode()` and then `_publish()`; the vcam loop sends each new frame as soon as it's ready and resends the last one once a period otherwise.
- `open_reader` (a StreamSource's) replaces the phone's reader; its `waiting_text`, if it has one, is the status while it can't open.
- `frame_pipeline: list[Callable]` - each callable receives a BGR numpy array and returns one; applied in order after resize, one frame at a time under a lock (plugins aren't thread-safe), and a frame older than the one already out is dropped. The host wraps each plugin step in `guarded_step()`: a step that raises or returns something other than an HxWx3 uint8 frame passes the frame through unchanged, and after `STEP_FAILS_BEFORE_SKIP` failures in a row it's skipped for the rest of the stream. The virtual camera is opened in BGR, so there's no colour conversion on the desktop.
- `update_output(width, height, fps)` - hot-swap output resolution/FPS without stopping the worker. An FPS change reopens only the virtual camera (`_run_vcam()`); the phone connection and reader thread stay up.
- Emits `status(kind, msg)` for the footer: `"ok"`, `"warn"`, `"fps"`, `"net"`, `"net_warn"`, `"reconnecting"`, `"idle"`. `"fps"` is frames that arrived from the phone, not what went to the virtual camera (that loop resends the last frame when none comes, which padded a phone at 30 up to 42 at 60 fps). `"net_warn"` needs two 2 s windows in a row under 85% of the target.
- `settle()` - the phone is restarting its camera, so windows don't count toward `"net_warn"` until frames have kept coming for `SETTLE_AFTER_FRAMES_S` (2.5 s; a gap over `SETTLE_GAP_S` starts that over), or `SETTLE_MAX_S` (10 s) has passed. The worker starts settled this way and settles itself on a reconnect or FPS change; the host calls it on `camera_switched` and `resolution_change_requested`.
- `run()` never dies quietly: a crash logs, emits `"error"`, and always ends with `"idle"`, which the host treats as "stopped unexpectedly" (banner with Start) when it didn't ask for the stop. A reader thread that crashes wakes the vcam loop so the stream reconnects instead of freezing on the last frame.
- Auto-reconnects on stream drop (`RECONNECT_DELAY = 3s`). `set_parked(True)` closes the virtual camera (waiting up to 1 s for it) while the reader keeps reconnecting; `set_parked(False)` opens it again. `retarget(url)` switches the URL it reconnects to and skips the rest of the wait; the host calls it when the phone is reachable another way.

### `vcam.py`
The virtual camera outside a stream. Streams can go to up to `MAX_SLOTS` cameras at once: slot 0 is the usual one, and `slot_label(n)` names the others ("Phone Camera 2" on Linux, found by label through sysfs in `slot_device(n)`; "Telescope #2" on Windows, as UnityCapture numbers the extra devices it registers). `slot_ready(n)` says whether one is set up. `open_camera(w, h, fps, fmt, slot=0)` opens `/dev/video11` (Linux) or the UnityCapture device named `UC_NAME`, falling back to any free one (Windows); `stream.py` uses it too. `locked_size()` (Linux) reads the size from sysfs while an app still reads the camera: v4l2loopback keeps its format then and silently ignores a writer asking for another, so the stream and the wait screen both open at that size instead (the stream letterboxes into it).
- `WaitScreen` holds the camera while nothing streams and shows `load_frames(path, w, h)` on it (flipped left to right with `show(..., mirror=True)`): the chosen image or GIF fitted to the camera size, or the default screen. Frames are prepared once (I420 on Linux, so a send is a plain write), sent once a second while nobody reads the camera (on Windows, until an app's filter creates the shared image, `_uc_filter_probe()` looks for it every `FILTER_POLL` (50 ms) and the frame goes out the moment it appears, so UnityCapture's own screen shows for a frame or two at most), and at `STILL_PERIOD` or the GIF's own timing while someone does. A GIF keeps every nth frame past `FRAME_BUDGET` (64 MB).
- `CameraWatch(on_change)` reports whether an app is reading the camera: the v4l2loopback client-usage event (0.13+), a `/proc` scan every 5 s on older drivers (`camera_holders()`), or on Windows the `UnityCapture_Want` event an app's filter sets for each frame it wants (`_uc_object_name()` mirrors pyvirtualcam's numbering). The filter creates that event when an app first opens the camera, so while it doesn't exist the watch reports no reader.
- `device_released()`: both let go of the device for the block (module reloads fail while anything holds it) and take it back after.

### `jpeg_guard.py`
`decode_jpeg(data)` is `MjpegReader.decode` and `BrowserReader.decode`: it reads the declared size from the first start-of-frame header (`jpeg_size`, every SOF variant, segments skipped by length) and returns None, dropping the frame, when it is over 8192 px a side or 64 MP, or has no readable header, before `cv2.imdecode` can allocate it.

### `h264_reader.py`
**H264Reader** - the `/v1/video.h264` counterpart of `MjpegReader`: `open()` checks the `video/h264` response, `read()` returns the newest frame completed by the next data that finishes one (older frames in the same data are dropped). `new_decoder()` / `decode_newest(codec, data)` / `decode_counted(codec, data)` (also how many frames the data finished) are the pure decode steps (PyAV, low-delay, 2 threads). PyAV is optional: `available()` is False without it, and the desktop then offers only MJPEG.

### `browser_server.py`
The Browser camera, Qt-free: a device's browser opens `https://<this computer>:8767/#<token>` (`BROWSER_PORT`, any free port if taken), and the page (`telescope/web/`: `index.html`, `app.js`, `mic-worklet.js`) sends its camera as H.264 (WebCodecs, hardware encoder only) or JPEG and its mic as 48 kHz mono s16le over one WebSocket on `/ws?token=&id=` (`id`: one the page keeps in the browser's storage, so a reload is the same browser), binary messages with a first byte of `FRAME_JPEG`, `FRAME_H264` (then a keyframe byte) or `FRAME_PCM`, and a JSON `hello` with the device, why there's no mic, and the codec and why it isn't H.264. The server sends JSON `config` (size, fps, whether to send audio, whether H.264 decodes here, and the virtual camera it streams to) whenever it changes, and `keyframe` when the feed asks for one. The page's script is run in Node by `tests/test_browser_page.py` (`tests/js/page_harness.js` stands in for the browser and holds its promises; skipped without `node`).
- `ensure_certificate(folder, hosts)`: a self-signed EC certificate (`cryptography`) next to the config, 0600, valid 397 days (browsers refuse longer) and kept until 30 days before it ends, so a browser told to trust it keeps doing so. `certificate_available()` is False without `cryptography`.
- `BrowserHub(can_join)`: a `BrowserFeed` per browser id. `join(id)` gives the browser its feed, or a new one when `can_join(id)` says there's a camera left for it; `drop(id)` forgets one that left; `set_capture` goes to every feed. Given one feed instead, every browser shares it.
- `BrowserServer(hub, cert, key, on_change)`: `start()` / `stop()`, `url_for(host)`, `new_token()` (the old link stops working and its browser is dropped). TLS is done on each connection's own thread; at most 16 connections, 6 per address. A wrong token gets 403. A newer connection from the same browser id replaces the older one, which gets close code 4000 (`CLOSE_REPLACED`); a new browser with no room gets 4001 (`CLOSE_FULL`). A connection that sends nothing for 10 s is closed. Each connection's thread does all its own sending and closing (an SSL socket mustn't be touched while another thread reads it, and on Windows a shutdown from another thread doesn't wake the read), checking every 0.5 s for a changed config or for `new_token()` / `stop()` having ended it.
- `ServerStats` (`server.stats`, new on each `start()`): the port, whether 8767 was taken (`fell_back`), and counts of how far browsers got: `connections`, `tls_failed` (hung up in the handshake, which is what a browser that hasn't accepted the certificate does), `pages`, `refused` (old or wrong token), `browsers`. Counts only, no addresses or tokens; each step is logged the first time it happens, and the port when it starts.
- WebSocket framing by hand (`ws_accept_key`, `ws_frame`, `unmask`, `_WsConnection`): masked frames in, fragments assembled, pings answered, messages over 16 MB end the connection.
- `BrowserFeed`: what the server hands over, per connection generation, so an old browser's frames never come out after a new one connected. JPEG keeps only the newest frame; H.264 is queued in order (`put_h264`), waits for a keyframe after a connect, and past 8 MB is dropped to the next keyframe, which `keyframe_requests()` asks the page for. `BrowserReader` is StreamWorker's reader on it (same interface as `MjpegReader`): JPEG decodes in parallel in `decode()`, H.264 in order in `read_packet()` with its own PyAV decoder (`decode()` passes the frame on), and `open()` asks for a keyframe. `open_audio()` is AudioWorker's opener: a `BrowserAudioStream` that lasts through the browser reconnecting, or an `HTTPError` carrying the browser's reason when it has no mic. `BrowserControl` stands in for `PhoneControlClient` (`base`, `auth` = `BrowserAuth`), so the Microphone plugin works unchanged.

### `audio.py`
The phone's mic into the virtual mic. `JitterBuffer` (pure): silence until `TARGET_MS` (60) has built up, silence-padding on a gap, and dropping the oldest audio back to the target past `MAX_MS` (150), which absorbs clock drift. `AudioWorker`: a reader thread (`/v1/audio` with the bearer token; on a refusal it reports the phone's `error` and retries every 3 s, so allowing the mic on the phone just starts it) and a writer thread that drains 10 ms at a time into a sink at the sink's pace. Sinks: `FifoSink` (Linux: writes the virtual mic's FIFO, paced to real time itself since the pipe source reads whatever arrives, with the pipe shrunk to one page so a stalled reader can't build up delay; it refuses anything that isn't a FIFO owned by this user, and won't follow a symlink) and `SoundDeviceSink` (Windows). `on_status(kind, text)` comes from the worker threads. The writer's `_shape()` applies `gain`, then the limiter when `limit` is on (peaks held under -1 dBFS: down within 1 ms, back up at 25 dB/s; a few microseconds a chunk, and quiet audio skips it), then clips to 16 bits; mute comes after. `take_level()` gives the loudest (peak, rms, limited) since the last call, with gain and limiter counted and mute not. It's measured in the reader as audio arrives, since PipeWire stops reading an idle virtual mic and that stalls the writer. `muted` writes silence instead; gain and mute changes both fade over one chunk so they don't click; the sink keeps running, so apps never lose the mic.

### `platform/virtual_mic.py`
Linux: `linux_setup()` loads `module-pipe-source` (`telescope_mic`, "Telescope Microphone", s16le 48 kHz mono) on `fifo_path()` with `pactl`. `fifo_path()` is in `XDG_RUNTIME_DIR`, else a `telescope-<uid>` folder in the temp dir that must be a real 0700 folder owned by this user. It's an input only, so nothing shows up as a speaker. `remove_stale_source()` unloads a source a crashed run left (`main.py` calls it at start, once it holds the single-instance port, so a kill -9 doesn't leave the mic listed). `linux_setup()` does the same first (including the null sink + remap the first builds used), and retries without the description if a server rejects it. `linux_teardown(ids)`. Windows: `find_vb_cable(devices)` finds CABLE Input in `sounddevice.query_devices()`. `download_vb_cable()` fetches VB-Audio's `VBCABLE_Driver_Pack45.zip`, refuses it unless its SHA-256 matches the pinned one, and unpacks only top-level names into a temp folder; `run_vb_cable_setup()` hashes `VBCABLE_Setup_x64.exe` again and opens it with ShellExecute's `runas` (UAC). It's VB-Audio's own setup with its own windows: their readme doesn't allow folding VB-Cable into another setup. Runners, `urlopen` and the launcher are injectable for tests.

### `dev_profile.py`
`TELESCOPE_DEV_PROFILE` (set by `scripts/dev_desktop.py`) names a folder; when set, `active()` is true and the config, log, single-instance lock (`instance_address(dev=True)`), virtual mic source and USB pairing package (`com.telescope.dev`) all move off the real app's, and the menu entry, dock grouping and sign-in toggle are left alone. Read at import, as at startup.

### `config.py`
Load/save of `telescope_config.json` with versioned schema (current: v3) and per-section validation. It holds the pairing tokens, so on Unix the folder is kept 0700 and the file, its temp file and any `.invalid-*` backup 0600. A file that can't be read is backed up once per launch and `take_reset_notice()` tells the window, which shows a banner.

**v3 schema:**
```
{
  "version": 3,
  "selected_device": "3f9c…",                  ← phone id
  "plugin_configs": {
    "connection": {                             ← global
      "computer_id": "8d1e…", "computer_name": "desk", "route": "auto",
      "phones": [{"id", "name", "token", "ips", "active_ip"}], "selected_phone": "3f9c…"
    },
    "setup": {...}
  },
  "devices": {
    "3f9c…": {
      "plugin_configs": {                       ← per phone
        "camera_control": {...},
        "stream_output":  {...},
        "transforms":     {...},
        "monitoring":     {...},
        "presets":        {"presets": [{"name": ..., "camera": {...}, "stream": {...}, "transforms": {...}}]},
        "microphone":     {"enabled": false, "gain_db": 0}
      }
    }
  }
}
```

`DEVICE_LOCAL_PLUGINS` frozenset marks which plugin names are per phone. `_upgrade_from_v2()` turns a v2 file into v3 by dropping the connection section, `devices` and `selected_device` (phones were keyed by name then) and keeping everything else. Anything older, or unparseable/malformed at the top level, is backed up (`.invalid-<timestamp>`) and replaced with defaults. A current config has each top-level section (`plugin_configs`, `devices`, `selected_device`) validated independently, so one malformed section resets to its default without discarding the rest.

### `phone_client.py`
**PhoneControlClient** - authenticated HTTPS client for phone's `/v1/state` and `/v1/control` endpoints, through the phone's `PhoneAuth` (pinned certificate, bearer token on each request).
- `send(action=..., **params)` - queues commands, coalesces repeated actions to latest value (sent at the place of the latest send), sends in order via background thread. Camera switches always go individually; slider bursts stay ordered (no stale response overtakes newer ones). A request that doesn't get through is retried with backoff for up to `_RETRY_FOR_S` (15 s), unless a newer value for that action is waiting, the phone refused it (HTTP error) or the client closed.
- `resend_settings()` - sends the last value of each camera/output setting again, for a background stream that reconnected. `retarget(url)` points it at the stream's new route, queue and settings included.
- `get_state()` - fetch current camera state dict (lenses, ISO, shutter, WB, focus, AE comp, NR/edge mode, battery, etc.). Each state it reads is checked against the settings last sent (`drifted_settings()`), and one the phone doesn't show is sent again, once per value, so a value the phone fitted to the lens doesn't start a loop.

### `ip_utils.py`
Qt-free address helpers for pairing and routing.
- `PairingAddress(ip, interface, kind)` - one address the phone can try, `kind` being `"lan"` / `"tailscale"` / `"other"`.
- `get_pairing_addresses()` - enumerates real adapters through `ifaddr` (never a route probe, which follows a VPN's default route), drops loopback/link-local/IPv6 and container/VM-only adapters, and returns candidates ordered LAN → Tailscale → other.
- `classify_ip(ip)` / `is_virtual_interface(name)` / `looks_like_vpn_interface(name)` - the pieces the above is built from.
- `MAX_PAIRING_CANDIDATES = 8` - cap on what goes into the QR code.
- `rank_ip()` / `valid_ipv4()` - used on the *phone's* reported addresses when choosing which to probe.

### `pinned_https.py`
HTTPS to a paired phone, trusting only the certificate fingerprint it gave at pairing. Qt-free.
- `PhoneAuth(token, pin)` - `headers()` for the bearer header, `open(req, timeout)` like `urlopen`. An `https://` URL needs a pin, and the certificate is checked right after the handshake, before any request byte goes out. No redirects, no proxies. Plain `http://` only works with no pin at all (tests' local servers), so a paired phone's token never goes out unencrypted.
- `fingerprint(der)`, `is_fingerprint(value)`, `pin_rejected(exc)` (the failure was the pin check: something answered, but not the paired phone).

### `session_client.py`
**PhoneSessionClient(base_url, auth)** - HTTPS client for the phone's session port (8766), where `SessionServer` answers whether or not a stream is running. Qt-free.
- `hello(timeout)` → `Hello(status, phone_id, phone_name, protocol, app_version, build)` - no token sent; which phone is on the other end and which app version. `status` is `HELLO_OK`, `HELLO_MISSING` (an app too old: one without `/v1/hello`, or one from before TLS, found by a plain `/v1/hello` with no token when the handshake fails) or `HELLO_NONE` (nothing there, or a certificate that isn't the pinned one).
- `read_capped(response)` - every reply is read through this, capped at `MAX_REPLY_BYTES` (256 KB), since whatever answers may not be the phone.
- `clean_name(raw)` - a phone's name as plain display text: no control characters, no `<` or `>` (Qt would render it as HTML), at most 64 characters. Every name from pairing, the phone or the config goes through it.
- `ping()` → `PingResult(status, streaming, busy, local_only, phone_id, phone_name)` - `status` is `paired` / `not_paired` (401) / `unreachable` (anything else, including a body that isn't Telescope's JSON).
- `start()` / `stop()` → `SessionResult(ok, error)`.
- `unpair()` - asks the phone to forget this computer (best effort).
- Owns `SESSION_PROTOCOL` (must equal the phone's `SessionServer.PROTOCOL_VERSION`; the release workflow checks), `PING_PORT = 8766`, `REQUEST_TIMEOUT`, `START_TIMEOUT`, `START_POLL_INTERVAL`.

### `phones.py`
Qt-free model of paired phones and how to reach them; adb, the session client and discovery are injected, so it's tested without any of them.
- `Phone(id, name, token, ips, active_ip, cert_sha256)` with `to_dict()` / `from_dict()`; `phone.auth` is its `PhoneAuth`. A phone paired before TLS has no `cert_sha256` and resolves straight to `NOT_PAIRED` with `before_tls`, without contacting it.
- `Route(kind, host, serial)`, `Resolution(status, route, usb_note, streaming, busy, phone_version, before_tls)`; statuses `READY`, `UNREACHABLE`, `NOT_PAIRED`, `LOCAL_ONLY`, `USB_NEEDS_ATTENTION`, `PHONE_OUTDATED` / `DESKTOP_OUTDATED` (the phone speaks an older/newer session protocol, or has no `/v1/hello` at all; the route is kept so the phone can be updated over it); USB reasons `USB_NO_ADB`, `USB_NO_CABLE`, `USB_UNAUTHORIZED`, `USB_OTHER_PHONE`, `USB_APP_CLOSED` (`usb_note_text()` words them for the UI).
- `RouteResolver.resolve(phone, preference)` - USB first (each usable adb device, verified by `/v1/hello` id, then `/v1/ping`), then Wi-Fi probed in parallel over mDNS-discovered, last-good and stored addresses. Blocking.
- `UsbTunnels` - refcounted `adb forward tcp:0` per (serial, remote port).
- `STREAM_PORT = 8080`, `ROUTE_AUTO` / `ROUTE_USB` / `ROUTE_WIFI`.

### `version.py`
`VERSION`, `BUILD`, `CHANNEL` (`stable` / `nightly` / `dev`) and `COMMIT` of this build. Release builds read `telescope/_build.py`, which CI writes with `scripts/write_build_info.py`; a source checkout reads the repo's `VERSION` file and is `dev`. `display_version()` is what the UI shows; `release_asset_url(name)` links a file from this build's release (nightly for dev builds).

### `diagnostics.py`
The log and Copy diagnostics. `install(app_dir)` (from `main.py`) opens `events`, an `EventLog` handler, on `log_dir()/telescope.log` (`/tmp/telescope-<user>` or `%TEMP%\Telescope`), links `telescope.log` in the app folder to it where symlinks work, adds it to the root logger and hooks sys and thread exceptions. It takes Telescope's info and up, other libraries' warnings and up, crashes and `note()`s (the host notes each status line and banner). A repeat of the latest line becomes a "repeated N more times" line; notes drop a trailing seconds counter ("(12s)") and treat "…" as "..." first, so a ticking status counts as repeats. The file rotates at `MAX_BYTES` into `telescope.log.1`; without a file it keeps `REPORT_LINES` in memory. `sanitize()` strips URLs, IPs, tokens and the home path before a line is stored. `report(state, qt_platform)` builds the text: version, OS, desktop session, then each plugin's `diagnostics()` lines, then the last `REPORT_LINES` log lines (across a restart). The host's `diagnostics_report()` is what the Advanced dialog's button copies.

### `updates.py`
Qt-free update logic, everything injectable for tests. `fetch_manifest(channel)` reads the channel's `manifest.json` (stable: the latest release, nightly: the `nightly` tag); `None` when the channel has no release. `is_newer(manifest, build)` compares build numbers (never true for a dev build, or for the build in `.update-failed`); `was_rolled_back()` is that last case, so the dialog can say so, and `forget_rolled_back()` clears it for a retry. `platform_asset()` picks the zip or tarball. `self_update_blocker()` says why this copy can only link to the release (source checkout, dev build, folder not writable). `download(asset, dest, progress, cancelled)` streams to a `.part` file and checks size and SHA-256. `install(archive, build=)` extracts to a staging folder next to the app (refusing paths that escape it), writes the journal and has `update_guard` do the swap (a failure puts the old version back and raises `UpdateError`); the old version is kept until the new one confirms it started:
- Windows: the app is a PyInstaller folder build whose libraries sit in `lib-<build>` (`LIB_PREFIX`), a new folder per build. Moves the new build's lib folder in with one rename, then renames the running `TelescopeDesktop.exe` to `TelescopeDesktop.old.exe` and moves the new one in, then replaces other files whose hash changed; a locked file (UnityCapture held by OBS) is skipped and reported.
- Linux: replaces each top-level entry, keeping the old one in `.previous/`.
Returns `InstallResult(relaunch, skipped)`. `clean_up_after_update()` runs on every start once the app is up (never while the journal says an update is unconfirmed) and deletes the leftovers: the old or failed exe, the staging folder, `.previous/`, and every `lib-*` folder but the running one (only when it knows which that is).

### `discovery.py`
**LanDiscovery** - browses `_telescope._tcp` with `zeroconf` and maps the TXT `id` to current IPv4 addresses. `lookup(phone_id)` never blocks; without zeroconf or multicast it returns nothing and stored addresses are used.

### `pairing.py`
**PairingServer** - the Qt-free one-shot pairing handshake: bind a port, mint a nonce and bearer token, wait for the phone's `POST /pair/{nonce}` echoing the token back.
- `PairingServer(on_paired, computer_id, computer_name)`; `start()` → `PairingOffer(payload, port, nonce, token, candidates, usb_payload)`. `candidates` may be empty (no network); `usb_payload` advertises only `127.0.0.1`, reached through `adb reverse`.
- `payload` is the version-3 JSON (`version`, `port`, `candidates[]`, `nonce`, `token`, `computer_id`, `computer_name`); `PAIRING_PROTOCOL_VERSION` moves in lockstep with the app's.
- `PairingResult(name, ips, token, source_ip, phone_id)` - a POST without `phone_id` is rejected. `source_ip` is where the POST came from, i.e. a phone address proven reachable from here, and becomes the phone's first `active_ip`.
- One phone per offer: after a phone pairs, a different `phone_id` gets `409`. Threaded, with a 10 s read timeout, so a stalled connection can't hold up the phone that's pairing. At most 32 connections at once and 4 per address, each cut off 15 s after it opens, so a peer trickling bytes can't pile up threads.
- `PAIRING_PORT = 8765`, falling back to a random free port if it's taken. A port still in TIME_WAIT from the last pairing is reused.

- `AddPhoneDialog` - QR for Wi-Fi when there's a network; polls `adb devices` every 2 s and re-sends the USB offer (`adb reverse` + broadcast) every 4 s to each usable device; says so when a device is waiting on the USB debugging prompt.

### `plugins/browser_camera.py`
**BrowserCameraPlugin** - the Browser camera card (`panel_region = "right"`, shown while Browser camera or a browser is picked) and its `StreamSource`s. The picker entry (`SOURCE_ID = "browser"`) never streams itself: its `redirect()` gives a connected browser that doesn't stream, and without one `prepare()` waits for one (`waiting()`): a "Waiting for a browser" banner when nothing else streams, a Waiting tile next to other streams, either cancelled with `cancel_waiting()`. Picking Browser camera or a browser starts the `BrowserServer`; it stops once neither is picked, nothing waits for a browser and no browser streams. Without `cryptography` the card says so and Start shows a banner. `waiting_hint(stats, connected, now)` (pure) is a warn note on the card while no browser is connected: nothing has reached the computer after `HINT_AFTER_S` (30 s) points at the network and firewall, a failed handshake with no page load at the certificate. `diagnostics()` adds the port and the stats counts. While it's picked, `bus.stream_behind` shows its own "Can't keep up" banner (key `behind`) pointing at Resolution and Frame rate; the page itself steps down to 720p, then 480p, when it can't encode frames as fast as asked. ### `plugins/stream_output.py`
**StreamOutputPlugin** - capture resolution, frame rate, and encoding settings.
- UI: aspect-ratio and resolution combos from the current lens's `supportedSizes` (dynamic, not fixed) - sends a live `resolution` control instead of a post-decode resize. FPS dropdown (15, 24, 25, 30, 48, 60) drives both phone capture and virtual-camera playback; choices above the current camera's `maxFps` are grayed out and the fastest one below runs, while `get_config()` keeps the one picked (an older saved rate snaps to the nearest choice). Format (MJPEG / H.264; H.264 enabled once the phone lists `h264` in `codecs` and PyAV is installed), then JPEG quality (1-100%; the High/Balanced/Low wording is in its tooltip) or, in H.264, Bitrate (Auto, 1-100 Mbps, or all the way right Dynamic; sent as `bitrate` in bits/s, `-1` for Dynamic). A double-click resets quality to 85 and bitrate to Auto. A phone whose state lacks `dynamic_bitrate` runs Dynamic as Auto, and the slider's tooltip says so.
- `bus.stream_behind(True)` shows a "Can't keep up" warn banner (key `behind`): **Switch to Light** on Heavy when Light is offered, **Switch to Dynamic** on Light unless the phone can't do it, and on Dynamic just a lower resolution or FPS; `False` clears it. Silent while another source is picked (`bus.source_selected`), which says what helps itself.
- Switching format calls `host.reconnect_stream()`: the route decides the phone's codec, and Connection's `_video_path()` reads `format` through `host.plugin_config()`. A `codec_error` in phone state while on H.264 switches back to MJPEG with a warn banner, except with `codec_unsupported` (H.264 can't do this size here): then it stops the stream (deferred, so every plugin sees the state first) and shows a banner (key `encoder`) to lower the resolution or FPS, with **Switch to Heavy** (sets MJPEG and starts again).

After a stop the lens's sizes stay up (cleared only on a device switch): a size picked then, or by a preset, is saved and becomes the pending one. `opening()` gives the host `{width, height, fps}` for the start request (`app._start()` reads it on the GUI thread and passes it through `conn.ensure_phone_streaming(opening=...)` to `PhoneSessionClient.start()`), so the phone opens at that size rather than one that just failed.
- `_apply_camera()` rebuilds resolution combo on lens change, carries current selection forward (reuses existing capture size) instead of resetting to largest; reflects live stream size on reconnect if it differs.
- `get_stream_params()` → `(width, height, fps)` - width/height are always `None` (resolution is phone-controlled, not desktop-resized); called by `app.py._start()` to construct `StreamWorker`.
- `on_stream_start`: stores ctrl, schedules `_push_initial_settings` (1500ms delay) to sync quality/fps after connect.
- `_on_resolution()` sends `resolution` control and emits `bus.resolution_change_requested` (used by `app.py` for footer readout). `_on_fps_picked()` / `_apply_fps()` send `fps_target` and call `host.update_stream_output()` for virtual-camera hot-swap (no stream restart).
- Config keys: `resolution`, `fps`, `jpeg_quality`, `format`, `bitrate_mbps` (`-1` is Dynamic, which an older desktop reads as Auto).
- `apply_preset(cfg)`: `set_config`, then while streaming sends fps and quality and, if the current lens has the saved size, the resolution.

### `plugins/preview.py`
**PreviewPlugin** - the centre video stage and its pop-out. `panel_region = "center"`.

### `plugins/transforms.py`
**TransformsPlugin** - software frame transforms applied in the stream pipeline. `panel_region = "left"` (desktop-side processing, next to the output settings).
- UI: flip (H/V segmented), rotation (None / 90 CW / 180 / 90 CCW), zoom slider (1× up to Setup's Max zoom, 10× by default, through `bus.max_zoom_changed`), pan left/right and up/down (enabled only when zoomed), and a Reset action in the card header that drives the widgets so the handlers do the rest.
- `split_zoom(zoom, pan_x, pan_y, caps)` - pure: the user's framing as the phone's share (`PhoneZoom(ratio, crop, x, y)`, sent as the `zoom` control) plus the desktop's remainder `(zoom, pan_x, pan_y)`; together they always frame the same. The phone's ratio only steps between lenses (`lensZooms`, the ratios where a multi-lens camera's longer lenses take over): the longest lens whose centred view still holds the window, with a 5% margin to move onto a lens (capped at the zoom itself, so a centred window always gets its lens) and none to stay on it (`current_ratio`). Phones animate ratio changes, so a ratio that followed the pan made the picture breathe. A freeform crop then cuts the window itself out of that lens's view; with a centre-only crop the phone stops at the lens and this computer does the rest, so the phone's share never changes with the pan. `PhoneZoomCaps.from_camera(cam)` reads `zoomRatioMax`, `cropZoomMax`, `freeformCrop`, `lensZooms` from the current `/v1/state` camera; `None` (a lens that can't zoom, an older phone app, not streaming) leaves it all to the desktop, as before.
- The plugin tracks the current camera from `on_phone_state` and `bus.camera_switched`, and re-splits on any zoom/pan/caps change; the phone only hears about changes (and again on each stream start). The zoom slider's tooltip says where the zoom happens. `lens_note(zoom, sent_ratio, caps, live, default, tele, settled)` - pure: `(level, text)` for the dot on the zoom value (a child of the value label, outside the layout, so it never moves anything); level `""` hides it. `"on"` (lavender) says "Switched to …" when `/v1/state`'s `active_lens` (the physical lens a multi-lens camera streams from) differs from the one live at ratio 1. `"off"` (red, wins) explains the fallback when the pan put the ratio below the lens a centred window would get, or, once the last ratio sent had `_LENS_SETTLE_S` to take, that the phone stayed on its default lens by itself. The zoom slider snaps to each lens at `lens_step(lens)` (rounded up, so the mark always gets the lens; `_lens_ratio` allows float slack, as 1/(1/z) can land a hair under z) and resets to 1x on a double-click. A preview drag sticks at the centre per axis within `_PAN_SNAP` of the frame, from a raw pan (`_raw_pan`) that keeps counting underneath, so dragging on lets go without a jump; any other framing change drops it. The plugin remembers the default and telephoto names from `on_phone_state` and forgets them when the caps change.
- `shown_to_view` / `view_to_shown` - pure, continuous and unclamped: a point in the frame as shown to and from the full view of the main lens, by the zoom/pan asked for (not the desktop share). `pan_for(centre, zoom)` inverts `_window_centre`. Dragging the preview moves the window by the drag mapped through them, so the picture follows the mouse in any rotation/flip; scrolling zooms by the factor, stops on a lens mark it crosses (`zoom_detent`), and re-solves the pan so the point under the mouse stays put (a finer `_wheel_zoom` lets trackpad steps add up). Pan is kept as floats and saved as such, finer than the pan sliders. `lens_boxes(caps, ...)` - each longer lens's centred 1/ratio of the view, as shown.
- `inverse_map(u, v, w, h, zoom, pan_x, pan_y, flip_h, flip_v, rotation)` - pure: a point in the transformed frame back to the phone's frame (undoes rotate, flip, then zoom). The plugin maps `bus.focus_point_picked` with it through the desktop's remainder only, using the last frame's size, and emits `bus.focus_point`; the phone maps it on through its own crop.
- `process_frame(frame)` - applies the desktop's share of the zoom crop then flip/rotate; runs on the worker thread. Reads plain Python attrs (`flip_h`, `flip_v`, `rotation`, and `_desktop_crop` as one tuple) written by the Qt thread; GIL makes these reads atomic.
- `frame_step()` - the same crop, flip and rotation frozen at their values now, for a stream that keeps running after the panels moved to another one.
- Config keys: `flip_h`, `flip_v`, `rotation`, `zoom`, `pan_x`, `pan_y`.

### `plugins/monitoring.py`
**MonitoringPlugin** - battery/temperature display and alerts. `panel_region = "right"` (the phone's own health, beside its camera).
- UI: live battery % + temp display, alert threshold spinboxes (battery %, temp °C), each with **Notify** and **Stop streaming** checkboxes under it in the control column.
- Subscribes to `bus.phone_state_updated`; also polls independently every 15 s via a daemon thread + `_Signals` inner class for thread-safe emit. A polled reading carries the control client it was read through and is dropped unless that's still the running stream's.
- Streams the panels don't show (`host.background_streams()`) are polled too, and alert by the thresholds saved for them (`host.device_config`), naming the phone; a Stop streaming stops that one (`stop_stream(id)`). What one has already warned about is kept when the panels move between streams.
- `_check_alerts()`: battery counts as low at or under its threshold while on battery or still falling on a charger; hot at or over its threshold. Calls `host.send_notification()` once per threshold crossing when Notify is on. Stop streaming calls `host.stop_stream()` on every reading past the threshold while streaming (last, since it runs `on_stream_stop()` synchronously), with the notification saying it stopped, and a `stopped:<id>` banner with the level and threshold and **Start anyway**. That start is remembered per source (`_allowed`), so the same reason doesn't stop it again until the reading is back past the hysteresis.
- Config keys (per phone): `battery_alert`, `temp_alert`, `battery_notify`, `temp_notify` (default on), `battery_stop`, `temp_stop` (default off).

### `plugins/updates.py`
**UpdatesPlugin** - a green **Update** button in the header (right side, hidden until there's an update) and the **Updates…** dialog in the settings menu.
- Checks 8 s after every launch, then daily (an hourly timer checks whether a day has passed; a background check that failed is retried on the next tick). Background failures stay quiet; **Check now** says what went wrong.
- `UpdatesDialog`: this version, channel (Stable / Nightly), Check daily, what's new, and **Update and restart** (disabled while streaming, or **Open download page** when `self_update_blocker()` says so).
- Download and install run in a thread; on success it relaunches (`--after-update`) and calls `host.quit_app()`.
- A newer build that was rolled back for not starting isn't offered; the dialog says so and **Try again** clears the marker and checks again.
- Config keys: `channel`, `auto_check`, `last_check`.

### `plugins/presets.py`
**PresetsPlugin** - a **Presets** button in the header (left, after the phone picker) with a menu: the saved presets (click applies), **Save current as…**, **Rename**, **Delete**. Per phone (in `DEVICE_LOCAL_PLUGINS`), since lens ids and sizes differ between phones.
- A preset is `{name, camera, stream, transforms}`, snapshotted with `host.plugin_config()` and applied section by section through `host.apply_preset()`, camera first so the lens switch goes out before Stream output looks up its sizes. Saving under an existing name replaces it.
- `clean_presets(raw)` drops malformed entries and duplicate names on load.
- Config key: `presets`.

### `plugins/microphone.py`
Doesn't follow the panels (`follows_focus = False`): with several streams it stays on the first phone's mic, and moves to the next one if that phone stops.
**MicrophonePlugin** - the Microphone card (left): an On switch, a Gain slider (-24 dB up to Setup's Max gain, +12 by default, snaps to 0) with a box to type an exact value (`_GainSpin`, shows +6 dB, applies on Enter), a level meter, a status line (hidden once audio flows, since the meter shows it), a button when something's missing (Install VB-Cable, which asks first, then runs `WindowsMic.install()` on the background thread: `virtual_mic.download_vb_cable()` fetches VB-Audio's pack against a pinned SHA-256 and `run_vb_cable_setup()` checks the setup again and opens it with UAC; a failure turns it into a Get VB-Cable link), and Mute in the header (shown while it's on), mirrored by a checkable **Mute microphone** item in the tray menu (`create_tray_actions()`). Mute sets the worker's `muted` and isn't saved, so the app never starts muted. While the worker runs, a 33 ms timer feeds `take_level()` into the meter and the readout beside it (held peak in dB, or Muted). Per phone (`DEVICE_LOCAL_PLUGINS`). While on, it follows the stream: `on_stream_start` prepares the virtual mic and starts an `AudioWorker` on `{ctrl.base}/audio`; `on_stream_stop` stops it (the camera going off doesn't); `bus.mic_changed` reports the On switch and Mute; switching off also removes the Linux virtual mic, as does `shutdown()`. `LinuxMic` / `WindowsMic` hold the per-OS parts (`problem()`, `prepare()`, `open_sink()`, `teardown()`, `pick_name`); `prepare()`, the worker's `stop()` and `teardown()` wait on pactl or threads, so they run in order on one background thread (`run_job`, injectable like the backend and worker class); a generation counter drops a setup result that arrives after the stream stopped. `shutdown()` waits for them, since the mic has to be gone before the app is. Config keys: `enabled`, `gain_db`.

### `plugins/wait_screen.py`
**WaitScreenPlugin** - runs a `vcam.WaitScreen` from app start to quit, except from `on_stream_starting` to `on_stream_stop` or `on_camera_off`, at the Setup canvas size or else the size the last stream opened the camera at (`last_size`, from `bus.vcam_opened`), or else 1920x1080, so a call that's already reading keeps working when the stream takes over (v4l2loopback readers lose the picture on a size change). Runs `vcam.CameraWatch` and re-emits it as `bus.camera_watched`. **Wait screen…** in the settings menu opens `WaitScreenDialog` (preview, Choose image…, Use default, and a mirror checkbox for apps that flip the camera, off by default); a chosen image is copied next to the config as `wait_screen-<id>.<ext>` (a new name each pick, so the camera reloads; the previous copy is deleted only once the new one is in place, and a copy that fails leaves the current image and says why in the dialog; one that won't load is called out in the dialog too). `vcam.read_image_frames` decodes a photo over Qt's allocation limit at a reduced size. The main camera shows it too while `bus.idle_outputs` has 0 in it (only extra cameras stream). The extra cameras in `bus.idle_outputs` (set up, nothing streaming to them) each get a `WaitScreen(slot=n)` too, at the canvas size or 1920x1080. Config keys: `image`, `mirror`, `last_size` (global).

### `plugins/startup.py`
**StartupPlugin** - the **Automatic streaming** submenu and **Open Telescope when I sign in** (`platform/autostart.py`). Headings are `QWidgetAction` labels (`menu_section` in the theme), since the menu style draws `addSection()` as a bare gap; actions are made with `QAction(text, menu)` so PyQt hears when the menu deletes them.
- `start_on`: `off`, `ready` (listens to `bus.phone_ready` and calls `host.start_stream(interactive=False)` once per arrival: a Stop or an attempt holds it until the phone reports not ready or another phone is selected) or `watched` (listens to `bus.camera_watched` and starts the same way once the phone is ready; a Stop holds it until the reader lets go). Neither claims a Start the user already has waking the phone. Any start keeps the window in the tray on close.
- `stop_idle`: `off`, `own` (only a stream it started) or `any`. `_sync_idle_timer()` is the one place the wait starts or stops: it runs while the rule applies, the camera watch has reported at least once, no app reads the camera, and a stream runs (or its own start is still waking the phone). It's called on every watch report, stream start, stop, failed start (`bus.stream_start_failed` clears the claim) and setting change. When the wait (`stop_delay_s`, 10 s to 60 min, default 15 s) runs out, `_stop_idle()` checks again, then `host.stop_stream()` and, with `notify_stop`, a notification. With the microphone card on (`host.can_turn_camera_off()`) it calls `host.set_camera_on(False, auto=True)` instead, without a notification, and the wait doesn't run while the camera is off; an app opening the camera turns it back on (`is_camera_off_auto()`). The menu says so under the Stop choices. A restart (`host.is_restarting()`) keeps the stream its own and leaves the wait alone. Changing the wait mid-count restarts it with the new value.
- **Wait before stopping…** opens `StopDelayDialog` (a number and seconds/minutes); it and **Tell me when it stops a stream** are greyed out while nothing stops by itself.
- Config keys (global): `start_on`, `stop_idle`, `stop_delay_s`, `notify_stop`. The old `auto_stream` / `watch_stream` booleans load as `ready` + `off` / `watched` + `own` (watching wins when both were on). `diagnostics()` shows all four and whether the running stream is its own.

### `plugins/setup.py`
**SetupPlugin** - the **Advanced** dialog, reached from the header's settings menu (`create_menu_actions()`); no panel, since nothing in it is adjusted mid-stream.
- `AdvancedDialog`: the cards sit in a scroll area (`_FitScroll`, which asks for its content's full height) between the pinned title and the version row and Close; `_fit_height()` opens it as tall as that, up to the screen minus `SCREEN_MARGIN`. v4l2loopback status, load/unload and load at boot (Linux), UnityCapture status and reinstall (or **Rename**, to Telescope, for an older registration) plus adb status (Windows), installing an APK over USB, the virtual camera canvas (presets or custom, applied through `host.restart_vcam_canvas()`; custom sizes step by 2 and odd ones round up to even, also in a hand-edited config, and a resize the host refuses or fails puts the previous canvas back), Max zoom (2-30×, applied straight away through `bus.max_zoom_changed`), Max gain (+12/+24/+36/+48 dB segments, through `bus.max_gain_changed`), and the Limiter switch (`bus.limiter_changed`).
- `get_canvas_dims()` → `(w, h)` or `(None, None)` for auto; read by `app.py` at stream start.
- Config keys: `canvas_preset`, `custom_canvas_w`, `custom_canvas_h`, `max_zoom` (default 10; anything else out of range falls back to it), `max_gain` (default 12; anything but the four choices falls back to it), `limiter` (on unless saved as `false`). `set_config` emits `max_zoom_changed`, `max_gain_changed` and `limiter_changed`, and global configs load before per-phone ones, so the sliders' ranges are in place before a saved zoom or gain is set.
